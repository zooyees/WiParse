## 配置、依赖和路径补充核对

- 两次默认构建的 `release/deps/wiparse_gui.d` 均记录 `# env-dep:WIPARSE_REVIEWED_MONITOR_VERIFIED`（没有值）；隔离启用实验构建记录 `# env-dep:WIPARSE_REVIEWED_MONITOR_VERIFIED=1`。因此现有构建依赖记录支持两次默认 GUI 没有混入启用配置；这不是直接运行生产程序的行为验收。
- 两次默认构建当前的 Cargo GUI fingerprint JSON 相同，记录的 rustc 指纹、features、profile、rustflags、config 和依赖指纹一致；实验配置 fingerprint 有不同依赖指纹。指纹不是完整输入文件或工具链二进制内容的密码学证明，不能补齐先前构建缺少的构建前清单。
- 两次 GUI 的 `.rsrc` 完全一致；清单范围内的图标和资源在统一冻结构建前后没有变化。`.pdata` 也一致。不能由此证明所有资源或生成输入在更早一次构建期间始终一致。
- 二进制只读字符串检查发现，前一程序含 `target\\release` 路径，独立构建程序含 `default-unified-freeze-r14` 路径；构建目录确实进入程序内容。路径字符串和调试标识可解释部分差异，但不能解释已观察到的全部 `.text`、`.rdata` 和 `.reloc` 变化。
- 对相同偏移的 4 KiB 块比较：GUI `.text` 6,382 块中 3,951 块相同，`.rdata` 2,839 块中 1,600 块相同；剩余字节变化不能仅凭这些统计归因为编译器随机性或具体功能变更。

在不重建或修改冻结源码的约束下，现有记录不足以确认剩余 GUI 差异根因。若后续要验证可复现性，应先固定完整输入、构建工具链、SDK、路径和时间策略，采用新的隔离候选并比对；当前没有进行该重建。当前不依赖外部条件的必要定向检查及已知失败复验见 [闭环核对](closure-audit-r14.md)；需要外部条件的桌面交互、真实设备、千问凭据及可比较的性能基线仍未完成。
