# 工程助手技能

工程助手的技能复选项和串口 AI 菜单中的“技能选择”可显式选择一个或多个内置技能。未选择且未启用自动路由时使用通用助手模式。启用自动路由后，只有唯一候选且当前已知前置条件满足时才自动选择；多项匹配或缺少条件时保留通用入口并显示建议。候选本身不授权读取或控制，也不代替用户指定通道、测试配置或限值。

任务中明确排除某领域时，自动候选、初始计划和对应的自动读取会跳过该领域；例如“不测量，只分析日志”不会阻止日志扫描。该识别是保守的文本规则，复杂或含糊表达仍需在任务中明确说明；它不代替宿主权限检查。

日志分析使用所选日志范围进行本地扫描，长扫描按宿主游标续读。测试报告和 Qi 数据按有界分段读取，分段回执提供 `next_cursor` 或 `next_offset`；宿主按来源和版本核对当前任务的连续覆盖，并保留最多 4096 条精简分段记录。单个步骤可引用最多 40 条证据，覆盖检查可使用同源的其他精简记录；原文淘汰后只能查看覆盖摘要，不能声称原始内容仍在内存。达到记录上限、来源变化或分段缺失时须说明未完成覆盖。波形只有在用户要求游标区间、只有一个可用通道且两个 X 游标有效时，才自动发起区间测量。其他情况需要提供具体通道与范围。

测试执行辅助需要已选插件、已保存配置、实际成功的预检以及匹配的设备会话。设备和测试动作需要相应授权及具体动作确认。开始请求的接受回执不代表执行完成；须等待相同宿主运行 ID 的实际进程结束。`testing.wait` 保持原有失败退出时 `ok=false` 的接口语义，同时提供 `process_completed` 和 `execution_succeeded`；进程退出不是产品通过判定。结果未知时应读取设备或任务状态，不能自动重发。

串口 AI 的“允许控制”只允许提出设备操作；模型的建议、日志内容和监控目标本身不构成具体动作授权。每个受控动作显示目标和参数供确认，来源、任务、技能、授权或会话改变时原确认失效。串口确认最多有效 10 分钟；仪表和测试动作由统一宿主审核一次并核验目标设备会话，缺少可核验会话时不派发。拒绝或撤权会阻止未派发的动作；已派发动作的物理结果可能未知，须先核对设备，不能认为一定已停止。消息队列可能暂停，恢复需由用户主动操作；撤权后重新开启不会给旧请求补授权。串口启动须等待实际连接结果，停止的端口释放是异步的。自动监控的本地告警继续工作，但既有自然语言监控规则不授予自动设备控制；操作失败或结果未知时，云端监控保持暂停，需先核查设备状态。隔离模拟及部分桌面验证见 [R82 核对](verification/router-skill-20261113/verification-r82-delivery-audit.md)，真实设备尚未验收。

设备任务及监控中经确认的串口动作需要先写入工程任务记录；记录目录不可写或无法安全访问时动作不会派发，修复工程存储后可重新提交。当前记录检查不接受 `projects`、项目目录或记录文件本身作为链接或 Windows 重解析点；需要使用其他磁盘时，可直接在工程设置中选择实际数据根目录。设备任务的已派发结果未知时需先读取或核对状态，不能自动重复。

周期性 AI 分析不能自行启动、停止或重设监控和告警规则，以免日志中的内容改变监控状态。用户仍可通过界面直接调整；手动任务提出启动、停止监控或修改规则时，会展示具体调整供确认，不需要开启设备控制权限。启动监控可能持续向已配置的 AI 服务发送新数据。此处的“实时告警”仅指本地规则对已接收数据的处理，并不代表硬件安全联锁。

组合使用测试执行和测试结果技能时，先等待本轮宿主进程结束，再读取运行清单明确列出的报告。宿主进程 ID、Hub 矩阵 ID 与插件自己的运行 ID 属于不同命名空间；旧报告、清单不含报告、或缺少宿主 ID 时，只能作为未关联本轮的历史材料。新清单同时保留现有路径和运行目录相对路径，供工程移动后解析；清单属于本机记录，并非独立认证的防篡改证明。进程退出失败的报告仍可用于故障分析，不能将退出状态当成产品判定。

完整日志扫描会记录来源的 SHA-256 快照。恢复时使用当前已授权来源重新扫描并核验摘要，历史游标不会跨进程复用。缺少完整快照、来源变化或扫描不完整时，相关步骤保持阻塞。历史设备操作恢复时需要重新读取状态。

内置技能与工程版本一起发布，选择记录含 ID 与版本。恢复时技能缺失或版本不一致会拒绝恢复，用户可使用当前配置建立新任务。未选择技能时可使用现有通用助手功能。

示波器辅助采集支持截图和源波形。Windows 上，源波形规范入口不接受模型提供的路径：宿主尝试将其作为新文件保存到当前工程 `ai-evidence` 目录，并等待真实保存回执。新归档实现使用逐级目录句柄和不覆盖创建；重解析点、写入或同步失败时报告错误，可能残留不完整文件。取消或超时不能视为保存成功，已经开始写入的结果仍应按未知处理并自行检查。非 Windows 平台当前不开放该自动归档，仪表页面的手动保存流程不变。R65 已执行编译和部分隔离安全测试，尚未完成真实设备及全部路径竞态验收；范围见 [R65 验证记录](verification/router-skill-20261113/verification-r65.md)。技能契约版本变更后，旧任务需按恢复提示重新建任务或核对数据，不自动沿用过期动作。

成功回执提供工程相对路径，便于工程迁移；绝对路径仍用于当前会话兼容。提交前取消可留下 `.partial`，写入、同步或提交失败时错误会提示候选位置；应用异常退出也可能留下该类文件。确认对应任务已结束后可由用户检查并清理，不应将其当成完整波形。取消与提交可能同时发生，此时必须先检查归档和设备状态再决定是否重试。目录句柄和身份检查不替代工程根目录的可信配置及文件系统 ACL，也不保证断电持久性或抵御已有权限的恶意进程修改文件。

单通道保留仪器返回的源字节；多个 ISF 通道沿用现有合并容器。其他多通道格式沿用软件现有的多列 CSV 组合，属于转换结果而非原始多文件，采样点按现有 CSV 导出规则对齐；某通道解析失败时拒绝自动归档该不完整组合。回执标明 `source_representation` 和 `source_channels`；`derived_csv` 表示转换结果。如需各通道原始文件或严格保留不同时间轴，应使用仪表页面的原始数据采集流程并核对格式。

无线测试插件的外部 live 后端目前无法证明本轮 TX 日志、RX 就绪与 FT4222 访问的执行顺序。该插件 live 入口因此受阻；已有 replay、recorded、dry-run 和通用仪表入口维持各自的现有流程。

报告或附件的新版本经宿主读取确认后，旧版本证据不能作为当前引用；对于签发过的分页游标，来源变化导致读取失败时也会结合宿主观察版本使旧证据失效。版本依赖文件身份、长度和修改时间，不是防篡改内容哈希或持续文件监控；详见 [R81 验证记录](verification/router-skill-20261113/verification-r81-cursor-version.md)。

该文档描述候选能力。已完成部分集中与隔离验证，完整桌面、模型、实机及发布验收尚未完成，实际范围以 [R82 核对](verification/router-skill-20261113/verification-r82-delivery-audit.md) 为准。

## 受审阅自动监控的构建门禁

常规构建默认关闭受审阅自动监控；本地告警仍独立运行。源码提供构建期变量 `WIPARSE_REVIEWED_MONITOR_VERIFIED=1`，仅供该候选通过来源、授权、撤销、并发、请求正文及回执验证后启用；需要针对启用后的实际产物再次验证。变量不会自动证明验证通过，普通用户无需配置。测试构建另有默认关闭的局部开关，用于隔离测试冻结样本的只读续轮。

此入口仅提供受保护的冻结样本搜索和计算；具体串口停止需要逐次确认、持久意图和会话绑定，等待真实工作线程认领。其他未受保护自动设备动作拒绝；宿主会话对象释放不证明操作系统或设备物理安全。异常或回执丢失时不自动重放。默认和启用测试配置的局部验证记录见 [监控配置核对](verification/router-skill-20261113/monitor-configuration-r12.md)；启用生产产物及完整桌面、硬件流程尚未验收，不作为发布能力承诺。

## 启用门禁后的验证证据

默认构建和启用构建是两个不同的构建配置，不能用默认构建的测试记录证明启用产物。集中验证时须冻结同一源码清单、Rust/系统依赖版本和测试数据，先验证默认关闭分支，再在隔离环境设置 `WIPARSE_REVIEWED_MONITOR_VERIFIED=1` 重新构建，针对启用分支执行来源/配置 ABA、撤权、过期、并发、取消、宿主释放、只读多轮及 GUI 确认回归；记录命令、变量、退出状态、测试日志与启用产物 SHA-256。测试局部开关只验证代码路径，不能替代带该构建变量的生产配置验证。验证中任何失败或遗漏维持默认关闭；只有确认相同源码与依赖、适用项通过且产物哈希一致，才能交付启用产物。真实设备反馈及无线 live 仍需独立证据。
