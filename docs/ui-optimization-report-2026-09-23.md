# WiParse 当前 UI 优化评估报告

日期：2026-09-23

评估范围：主框架、串口、仪表、波形、数据分析、集成测试、测试报告、计算器，以及浅色/深色主题体系。

评估目标：简洁、优雅、美观，同时兼顾工程工具所需的信息密度、可读性和操作效率。

## 1. 结论

当前 UI 已经脱离“开发工具默认皮肤”阶段，具备较完整的设计系统和稳定的专业工具气质。配色克制，浅色与深色主题逻辑统一；按钮、圆角、间距、状态色和绘图区颜色都有集中定义；主要页面也普遍采用“侧栏配置 + 主工作区”的清晰结构。

但整体仍有明显优化空间，主要问题不是配色不好，而是**信息架构偏平、字号偏小、页面密度偏高、各模块侧栏与工具栏规则不完全一致**。这些问题会让界面显得“功能很强，但略挤、略硬、需要熟悉后才高效”。

综合评分：**6.9 / 10**。完成第一阶段优化后，预计可提升到约 **8.0 / 10**，且不需要重写业务逻辑。

| 维度 | 评分 | 判断 |
|---|---:|---|
| 简洁性 | 6.4 | 单页结构清楚，但七个一级入口、多个等权按钮和大量常驻参数提高了认知负担 |
| 优雅性 | 7.1 | 设计令牌、深浅主题和绘图区处理较成熟；模块间尺寸规则仍有割裂感 |
| 美观度 | 7.3 | 配色稳健、工业感明确；过小字号、密集边框和局部“表单墙”削弱精致感 |
| 一致性 | 7.0 | 共用主题组件较多，但固定侧栏宽度、按钮组织和标题层级仍由各页面分别实现 |
| 可读性 | 5.9 | 11–13 px 文本大量出现，中文和高 DPI 环境下容易吃力 |
| 响应式适配 | 6.0 | 1440×900 下布局成立，但最小窗口 1280×720，且多处固定宽度，不够灵活 |
| 专业工具感 | 8.1 | 示波器通道色、状态反馈、数据与设备工作区的语义较可信 |

## 2. 当前界面概况

主框架使用 40 px 顶部标签栏、26 px 底部状态栏和中央内容区。七个一级页面全部默认开启：串口、仪表、波形、数据分析、集成测试、测试报告、计算器。设置入口位于顶栏右侧，通过二级菜单管理面板、语言、主题和关于信息。

页面大致分为三类：

1. **采集与设备工作台**：串口、仪表、波形、数据分析。通常采用固定侧栏加大面积主工作区。
2. **流程与结果**：集成测试、测试报告。通常采用资源列表、配置、日志或预览的多栏结构。
3. **辅助工具**：计算器。采用多卡片计算面板。

这个结构适合功能完整的研发工具，但当前一级导航把三类任务平铺成同一层级，缺少对高频主流程的强调。

## 3. 做得好的部分

### 3.1 设计令牌完整，主题基础较好

主题文件已经集中定义 4/8/12/16 间距、6/8/10 圆角、控件高度、字体层级、浅色与深色颜色语义。按钮、状态条、卡片和焦点环也有共享实现。这为后续优化提供了很好的基础，不需要重新建立视觉体系。

浅色模式使用中性灰白背景和低饱和蓝色强调；深色模式使用接近黑色的仪器工作台背景，并提高了次要文字亮度。绘图区单独保持深色，使波形通道色在两种主题下都可识别。这一处理符合示波器和数据分析类软件的使用习惯。

### 3.2 主工作区结构易理解

串口页采用约 215 px 左侧控制区和右侧日志区；仪表页采用 290 px 设备架和右侧设备工作区；波形和数据分析页采用 280 px 侧栏加绘图区；集成测试与报告页也有明确的资源区和内容区。用户进入页面后能够快速判断“左边选与配，右边看与做”。

### 3.3 状态语义明确

成功、警告、停止/错误、运行中等状态都有专用颜色，并且底部状态栏随当前页面显示状态。串口开始/停止、集成测试运行/停止等关键动作已经区分主按钮与停止按钮，符合工业工具的操作预期。

### 3.4 波形与仪表页面具有产品辨识度

波形通道使用示波器常见的黄、青、红、绿等颜色；绘图区、测量值、通道零位和协议解码使用专门的视觉表达。相比普通表单软件，这部分已经形成 WiParse 自身的专业外观，是当前视觉系统中最值得保留的资产。

## 4. 主要问题与优化建议

### P0：一级导航过平，默认暴露的信息过多

七个文本标签全部放在 40 px 顶栏，并且所有面板默认开启。1440 px 宽度下可以容纳，但英文模式、窗口缩窄或系统缩放较高时，顶栏会显得拥挤。更关键的是，串口、仪表、波形、报告和计算器在视觉上完全等权，不能表达用户的主流程。

建议：

- 保留高频主入口：**串口、仪表、波形、数据、集成测试、报告**。
- 将计算器移入“工具”菜单或允许用户固定到顶栏；已有的面板显示设置可继续承担个性化入口管理。
- 给标签增加紧凑模式：宽度不足时缩短名称或收进“更多”菜单，而不是继续压缩文字。
- 当前标签用底部 2 px 蓝线表示选中状态，建议再增加轻微背景或字重变化，使选中状态在深色主题和高亮显示器上更稳定。
- 设置齿轮目前使用 Unicode 字符，建议改为内置矢量图标，避免字体缺字或不同系统下视觉重量不一致。

预期收益：减少顶栏噪声，使用户首先看到工作流而不是功能清单。

### P0：字号体系偏小，影响可读性和高级感

当前全局字号为 11 / 12 / 13 / 15 px，页面中还存在 9–10 px 的坐标、说明和图内文字。在 1440×900、Windows 125% 缩放或中文环境下，11–12 px 容易显得局促；大量小字也会让界面看起来像高密度调试面板，而不是成熟产品。

建议将默认字号调整为：

| 用途 | 当前 | 建议 |
|---|---:|---:|
| 辅助说明 / Caption | 11 | 12 |
| 正文 / 控件文字 | 12 | 13–14 |
| 标签 / 小标题 | 13 | 14–15 |
| 区块标题 | 15 | 16–17 |
| 关键测量值 | 16–28 | 保持，但统一数字字体和单位层级 |

同时提供“紧凑 / 标准”密度选项。紧凑模式保留当前密度，标准模式使用更大的字号和 32 px 控件高度。这样既照顾长时间阅读，也不牺牲产线用户的高密度需求。

### P0：各页面侧栏尺寸与行为不统一

当前侧栏宽度至少有 215、248、280、290、300 px 五套固定值。切换页面时，主内容起始位置会左右跳动，用户会感到每个页面像独立工具拼接在一起。固定宽度还会放大英文长文本、路径和设备名的截断问题。

建议：

- 建立统一侧栏规范：默认 272 px，允许在 240–360 px 之间拖动。
- 每个页面记住用户最后一次宽度。
- 支持折叠为 44–48 px 图标栏，给波形和日志更多空间。
- 所有侧栏标题、卡片内边距、表单标签宽度和按钮间距使用同一套组件。
- 路径、设备资源名等长文本统一采用“单行省略 + 悬停完整值 + 复制按钮”。

### P1：串口页左侧操作过于等权

串口页把刷新、开始/停止、新建、清空、选择目录、打开日志等操作纵向放成多个全宽按钮。全宽按钮连续出现时，每个动作都像主操作，页面显得笨重，且“清空”与“开始”距离较近，容易增加操作压力。

建议：

- 保留“开始/停止”为唯一全宽主按钮。
- “刷新端口”改为端口下拉框右侧的小图标按钮。
- “新建、清空”放在日志工具栏；清空使用次要危险样式，并在日志非空时才启用。
- “选择目录、打开日志”合并为路径输入行右侧的文件夹与打开图标。
- 文件名、保存开关和保存目录放进可折叠的“记录设置”，默认只显示当前文件名和保存状态。

这会显著减少左栏高度，使文件浏览区获得更大空间。

### P1：复杂页面容易形成“卡片和表单墙”

仪表、波形、数据分析和集成测试都包含大量参数。当前主要依靠卡片边框、分隔线、网格和滚动区组织内容。功能越多，边框越多，页面越容易显得碎。

建议：

- 仅一级区块使用完整卡片；卡片内部优先用留白、标题和细分隔线，减少重复描边。
- 高频参数直接展示，低频参数进入“高级”折叠区。
- 同一任务的参数、动作、结果形成清晰的纵向顺序：**选择 → 配置 → 执行 → 状态/结果**。
- 每个页面只保留一个视觉主按钮。次要动作采用普通按钮或图标按钮。
- 禁用状态除降低对比度外，增加明确说明，避免只靠颜色表达不可用原因。

### P1：页面工具栏缺少统一模式

波形和数据分析页都有顶部工具栏，但串口操作分散在侧栏和日志页签中，仪表页又使用设备架与设备卡内部操作。每个页面都能工作，但用户无法形成一致的肌肉记忆。

建议建立三层动作规则：

1. **页面级动作**放顶部工具栏，例如刷新、导入、导出、布局。
2. **对象级动作**放对象标题行，例如连接设备、移除文件、关闭页签。
3. **任务主动作**放配置区底部，例如开始采集、运行测试、生成报告。

页面工具栏统一高度 36–40 px，图标为 16 px，文本按钮只用于用户必须理解的动作。

### P1：最小窗口和响应式策略偏保守

程序默认 1440×900，最小 1280×720。对实验室大屏合理，但在 13 英寸笔记本、远程桌面和 Windows 125%/150% 缩放下容易受限。固定侧栏、固定按钮宽度和多栏页面会进一步压缩主区域。

建议：

- 将逻辑最小宽度目标降到约 1100 px，并在 1180 px 以下启用紧凑导航。
- 多栏页面在宽度不足时允许右侧配置区变为抽屉或下方面板。
- 工具栏允许溢出到“更多”菜单。
- 为 100%、125%、150% 缩放分别做视觉回归截图。

### P1：嵌套滚动区较多，操作焦点可能不稳定

仪表页和集成测试页存在多个独立纵向滚动区，报告与日志还包含水平/双向滚动。鼠标滚轮落在不同区域时，滚动对象可能突然变化，界面也会出现多条滚动条，降低整洁度。

建议：

- 一个视觉列尽量只保留一个主滚动容器。
- 日志、代码和波形等必须独立滚动的区域使用更明显的背景层级。
- 只有内容溢出时显示滚动条；滚动条宽度、颜色和悬停反馈全局统一。
- 固定页面标题和主动作，长参数区单独滚动。

### P2：底部状态栏价值可以更高

当前状态栏只展示当前页面的一条状态，结构简洁，但占用了固定 26 px 高度。对于设备工具，用户通常更关心全局连接状态、采集状态和后台任务。

建议把状态栏改为三段：

- 左侧：当前页面状态。
- 中部：串口、仪表、API 的连接摘要，用小圆点和简短文字表示。
- 右侧：后台任务、版本或更新状态。

若没有全局信息，可自动收缩为 22 px，避免显得空。

### P2：视觉细节还可进一步统一

- 圆角虽有全局令牌，但部分页面仍直接写入 6 px，应全部收敛到共享令牌。
- 页面中存在多处直接写死的字号、颜色和控件尺寸，建议逐步迁移到主题组件。
- 深色模式的强调色较克制，这是优点；应检查 `accent_soft` 在不同显示器上的可见度，避免选中态只剩很淡的蓝雾。
- 状态不能只依赖红、绿、橙颜色，建议配合图标或文字标签。
- 数值显示建议统一使用等宽数字或 tabular figures，使实时读数跳动时布局稳定。

## 6. 推荐视觉规范

### 6.1 字体和尺寸

- 标准正文：13–14 px。
- 区块标题：16 px，半粗体。
- 页面标题：18–20 px，仅在需要时出现。
- 控件高度：标准 32 px，紧凑 28 px。
- 图标按钮点击区域：至少 28×28 px，建议 32×32 px。
- 关键操作之间至少 8 px，区块之间至少 16 px。

### 6.2 层级

- 画布背景：最底层。
- 侧栏/工具栏：一级表面。
- 卡片：仅用于独立任务或对象。
- 绘图区/日志区：使用更深或更浅的“工作井”背景，强化内容区域。
- 弹窗：10 px 圆角，并与普通卡片有明确阴影或边界差异。

### 6.3 动作颜色

- 蓝色：主动作和当前选中。
- 红色：停止、删除、不可逆清空。
- 绿色：成功状态，不作为普通按钮色。
- 橙色：警告与需注意状态。
- 普通工具动作保持中性灰，避免页面出现多个视觉焦点。

## 7. 实施路线

### 第一阶段：低风险高收益，预计 2–4 天

1. 字号整体提升一级，并增加“紧凑 / 标准”密度配置。
2. 串口页缩减全宽按钮，折叠记录设置。
3. 统一页面侧栏宽度、标题、边距和长文本处理。
4. 统一顶部标签选中态，替换 Unicode 齿轮图标。
5. 收敛直接写死的 6 px 圆角、字号和状态色到主题组件。

### 第二阶段：信息架构优化，预计 4–7 天

1. 计算器进入工具入口，支持用户固定。
2. 建立统一页面工具栏和对象标题栏组件。
3. 波形、数据分析共享同一工作台骨架。
4. 集成测试按“预检—运行—结果”重排，并减少嵌套滚动。
5. 侧栏支持拖动、折叠和宽度记忆。

### 第三阶段：质量验证，预计 2–3 天

1. 建立 100%、125%、150% 缩放下的截图回归。
2. 检查浅色/深色对比度、色觉缺陷可辨识度和键盘焦点。
3. 检查中文、英文、长路径、长设备名与空状态。
4. 在 1100×720、1280×720、1440×900、1920×1080 下验证布局。

## 8. 验收指标

- 顶栏在 1100 px 宽度下不发生文字碰撞或设置按钮遮挡。
- 标准密度下，正文不小于 13 px，说明文字不小于 12 px。
- 每个页面最多一个主色实心按钮。
- 页面切换时侧栏主边界基本稳定，不再出现明显左右跳动。
- 常用任务从进入页面到执行不超过 3 个主要操作。
- 同一页面不出现三条以上同时可见的滚动条。
- 关键状态同时具备颜色和文字/图标表达。
- 在 125% Windows 缩放下，中文标签、设备名和路径不发生不可恢复的截断。

## 9. 评估依据与限制

本报告依据当前构建产物、运行配置和 UI 源码进行静态与运行状态交叉检查。重点证据包括：

- 主窗口默认 1440×900、最小 1280×720。
- 顶栏固定 40 px、状态栏固定 26 px，七个一级标签默认全部显示。
- 全局字号为 11 / 12 / 13 / 15 px。
- 各页面固定侧栏宽度分别约为 215、248、280、290、300 px。
