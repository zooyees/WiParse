# 任务规格书1：WiParse软件功能修正与增强

日期：2026-10-11；版本S1；主责：WiParse开发；协作：插件、Dongle、工位/测试。共同目标、字段、里程碑见[跨任务契约](00-system-contract.md)，上位要求见[系统方案R2](../../wireless-charging-automated-test-system-2026-10-10.md)。这是开发规格，非现有能力声明。

## 1. 目标与基线

将现有GUI仪表/API、Node Testing Hub、Rust波形/协议分析能力提升为可独立采集、可验证完成、可回放、可追溯的自动测试基础设施。保留现有手动仪表/串口/波形使用路径，避免自动测试占用设备时人工操作冲突。产品测试矩阵和专属状态规则属于插件，硬件捕获属于Dongle。

基线核查缺口：设备能力按类型/品牌推测；任务事件需要可靠查询；固定遥测无VBRG；显示解码有预算；GUI托管采集服务；缺原始多通道质量与结构化波形指标、统一时钟和错误处置。不得把通用60V/20A/300W默认范围作为DUT安全限值。

## 3. 接口详细约束

拟议 `wave.analyze` 入参：run/capture、批准项目内raw path/hash、channel roles、time window、algorithm/profile版本；返回job_id。结果为共同MeasurementResult，包含原始依据与quality，不返回大量点列给插件。`protocol.decode`同样路径/时间窗输入，统计与分块事件文件输出。

`check.evaluate`读取PL冻结的规则/limits，返回共同CheckResult，提供区间/持续/状态门控/缺失语义；不能从硬编码ChargeStateTracker阈值推断所有产品。输入采集质量不满足时不继续正常阈值判定。

`dongle.capture`主机适配器完成二进制校验、64位tick安全处理、boot/session/seq、quality和stream封装；自定义IO协议与旧串口日志分离。Host读取USB/WiFi事件和落盘的异步队列有容量/水位/丢失统计，禁止无界缓存。

job完成与仪器状态确认分开。armed需要型号专属读回；不支持确认时降级仅用于开发档，不能声明确定性抓取。设备主线程同一会话串行SCPI，不同设备并发且停止优先；大导出不能饿死健康处理。

## 4. 数据与工程要求

schema文件由SW维护唯一源，G0提供文档和样例/golden messages；PL/DG评审后冻结。新增结果采用共同模型，保留原串口日志和元数据。原始64位tick不以JS浮点数传递；窗口边界和各时钟domain明确。

落实独立服务身份与本机访问限制、参数schema/路径/命令权限校验；测量读取与危险写入分权限，run lease可限制设备与命令范围。不得让匿名远端请求切换电源；不在遥测/报告泄露网络口令。

每型号能力profile显式标识verified/experimental/unsupported、固件/选件范围。接收到无法保证raw的波形时指标质量拒绝，而不是自动猜格式。兼容旧UI路径不意味着旧自动化接口可绕过新lease。

## 5. 非功能与验证

按共同时间预算和工位最大负载测试，分别测timestamp误差、事件可见P99/极值、持久化窗口、内存上界、导出盲区。吞吐按批准R_peak和主机停顿预算，不填未测性能承诺。压力注入GUI卡顿、服务kill、迟到/错序响应、重复命令、慢磁盘/满盘、事件风暴、USB中断、时钟漂移和多客户端抢占。

分析测试覆盖正常/边界/明确故障/空数据/错通道/坏单位/短窗/缺失/重复/抖动/坏门限；独立参考值验证，不只用算法自生成样本。安全输出和具体仪器型号必须实物验收，transport mock不替代实物。

## 6. 提交物、依赖与完成定义

提交：服务与GUI/core实现、API/schema、模拟器与contract tests、参考波形/预期结果、型号验证表、故障注入报告、迁移/回滚和操作文档。优先顺序：SW01/02/03与DG ICD → SW04/05 → SW06/07/08/09 → 联合G2 → 高级驱动/UI/工业G3/G4。

依赖：DG提供capture ICD/模拟器/固件；PL提供产品配置和验收规则；外部提供保护反馈与示波器raw能力。完成条件：对应SW需求全有可查测试证据，共同SYS映射无孤项，既有手动/插件回归通过，危险/缺失数据不能误放行，工业档在G4前保持未批准标记。
