# WiParse 1.1.29 界面布局检查与修复

日期：2026-10-11。触发问题：集成测试 CMSIS-DAP 插件的“用例”文字与输入框重叠。

## 原因与统一修正

界面提前用 `allocate_exact_size` 或绝对矩形分配一整行/卡片后，再用 egui 0.31.1 的 `scope_builder` 绘制子区域。该 API 在结束时还会用子界面的最小矩形推进父布局。子区域较小或带内缩边距时，父级游标会回到已分配区域内部，造成随后标题、字段、按钮或卡片覆盖已有内容。

新增 `theme::scope_in_allocated_rect` 和 `theme::in_allocated_rect`：通过 `new_child` 创建独立布局，裁剪到已分配区域，并保持父级游标不变。正常流式布局仍使用 egui 的空间分配 API。统一替换 21 处绝对位置 `scope_builder` 调用及 1 处已分配日志编辑行的 `allocate_new_ui`；同时修正已有面板/按钮绘制辅助函数。

## 修复范围

| 区域 | 检查结果及处理 |
|---|---|
| 集成测试/插件 | 标题、版本、状态和操作按钮预留独立区域；移除重复的用例相关绘制；用例、目录提示、参数行按正常顺序分配空间。配置/输出在窄区域改为上下排列；参数标签与字段不足一行时分行，路径选择按钮不再挤压字段。 |
| 插件市场 | 地址输入框宽度计入文本边距；通道下拉宽度不再强制溢出。 |
| 波形分析 | 工具栏按宽度使用一行或两行，快捷键提示改为悬停提示，消除右侧提示与按钮覆盖；侧栏三个分区的高度之和符合可用空间。内嵌报告的波形页同步使用该工具栏。 |
| 数据分析 | 同类矩形绘制修正；修复小高度下 `clamp(140, body_h-160)` 下界大于上界导致 panic 的问题；等待提示宽度受容器约束。 |
| 串口/日志 | 侧栏、内容区及虚拟化日志行独立绘制；日志编辑行不再二次推进布局；修正双层 Frame 高度造成的底部溢出；查找/替换栏允许换行，工具栏有需要时显示横向滚动条。 |
| 测试报告 | 项目选择、刷新、标题、外部打开按钮、Markdown 表格行及面板独立绘制；预览内层 Frame 使用真实剩余高度，恢复底部边框。 |
| 仪表控制 | 仪表卡片/四宫格独立绘制；直流电源输出列按可用宽度分配，输出按钮完整显示，窄控制表格支持双向滚动；探针、USB 桥、Dongle 等三列工作台在宽度不足时改为纵向卡片。统一普通卡片填满所在列；Dongle DAP 页不再重复显示设备身份字段。 |
| 设备总览 | 模拟连接测试复现小区域下的轨道卡片坐标 clamp 反向边界异常。空间不足时改为可滚动设备卡片网格，避免重叠并保留点击进入设备控制台功能。 |
| 计算器/转换器 | 六个计算区域的独立矩形绘制不再影响其他单元；保留单元内滚动，较长表单可滚动访问。 |
| 主窗口/设置/弹窗 | 源码检查主导航、设置级联菜单、关于、路径选择、导出及确认弹窗的布局方式。系统文件选择器由 Windows 管理；本次没有改变其行为。 |

## 验证与可复现证据

- GUI 测试包含所有本地插件标题→用例→参数顺序回归，检测每一行高度和父级游标是否被回退。
- 布局几何回归覆盖 120–1200 点宽度、普通/多行/路径参数，断言标签、输入框、浏览按钮和配置/输出矩形在容器内且互不相交。
- 7 个主页面 × 中英文 × 深浅主题 × 100%/150%/200% 显示缩放 × 640×360、1100×720、1920×1080 三档逻辑尺寸，共 252 组无窗口 egui 渲染，检测渲染网格和坐标有效性。640×360 用于压力测试，产品主窗口的最小逻辑尺寸仍为 1100×720。
- 模拟连接后测试示波器、电源、电子负载、万用表、调试探针、USB 桥、WiParse-Dongle 及设备总览，中英文/三档尺寸共 48 组渲染。不向真实仪表、供电端口或固件发送命令。
- 通过 egui 的实际绘图网格和字体图集生成界面图，逐页检查主页面、CMSIS-DAP 表单和模拟连接后的工作台。导出器在 `ui_audit.rs`，软件光栅化脚本为 `scripts/render-ui-audit.py`。
- 证据目录：`evidence/ui-layout-2026-10-11/`，含 Rust 测试、最终 release 编译、打包日志和 `frames/` 界面图。
- 全量并行测试还发现项目索引测试使用 Windows 时钟生成临时目录存在同刻碰撞，测试目录改为 UUID；这是测试隔离修正，不改变生产索引逻辑。
- 布局测试使用隔离的 `WIPARSE_APP_ROOT`/`WIPARSE_CONFIG`，并关闭测试中的市场自动加载，避免后续检查改写用户配置或发起市场请求。

运行示例（PowerShell；目录均在仓库下）：

```powershell
$env:WIPARSE_APP_ROOT = "$PWD/tmp/ui-audit-runtime"
$env:WIPARSE_CONFIG = "$PWD/tmp/ui-audit-runtime/config.json"
$env:WIPARSE_UI_AUDIT_OUTPUT = "$PWD/evidence/ui-layout-2026-10-11/frames"
cargo test -p wiparse-gui
python scripts/render-ui-audit.py evidence/ui-layout-2026-10-11/frames
```

## 验证边界

上述检查包含源码审查、无窗口布局和软件渲染复核，不等同于实际多显示器 DPI 切换、所有 Windows 系统弹窗、真实硬件返回的全部动态状态和任意第三方插件内容的现场验收。模拟会话验证界面结构，不验证真实仪表采集或控制能力。新增长文本/参数仍应通过上述回归与图像复核。
