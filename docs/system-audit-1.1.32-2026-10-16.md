# WiParse 全功能检查与优化落实报告

版本：1.1.32。检查开始于 2026-10-16，发布验证延续至 2026-10-17，Asia/Shanghai。范围为当前仓库的七个主要工具、协议与文件处理、配置、插件、GUI API、MCP 和独立自动化服务。

本轮确认并修正了仪表面板控件不齐、操作按钮随文本散乱换行、Dongle 连接参数与操作脱节、串口历史查看不稳定、连续接收限速及部分页面在小窗口中的可用性问题。采用模块内布局组件、共享只读历史视图和增量维护，保持现有对外接口、文件格式、行数限制及测试判定契约。

本报告记录软件回归的覆盖与局限，不代表已完成全部真实仪表、DUT、驱动组合或工业工位验收。最终机器可读验证记录随发布包保存在 `docs/verification/release-1.1.32.json`。

## 问题清单与落实

严重度 P1 表示会影响操作对象、持续接收或查看正确性；P2 表示可用性、布局或资源效率问题。

| 编号 | 严重度 | 问题及原因 | 修正与优化 | 防止冲突的措施 |
| --- | --- | --- | --- | --- |
| F01 | P2 | 仪表数值框按内容宽度收缩，文本框与数字框高度不同，字段看起来悬浮且不齐 | 属性行统一标签列、编辑列、28 点控件高度及左侧起点，数值和文本编辑占满同一列 | 只修改仪表模块的 design 组件，未修改全局主题或其他工具的输入控件 |
| F02 | P2 | 操作按钮按标题长度换行，出现三加一、不等宽和末行错位 | 主操作单独占行，多操作按可用宽度组成等宽列；长标题在自身区域换行 | 保留原按钮触发的控制命令，新增几何和实际点击回归 |
| F03 | P2 | 参数与读数列比例不合理；窄窗口先显示读数和预览，设置被推至下方 | 增加参数列可用宽度；窄窗口先设置后结果；通道选择与参数卡宽度一致，标题标明当前 CH | 切换 CH 只改变编辑对象；应用设定仍不自动开启电源输出 |
| F04 | P1 | Dongle 部分 I2C 操作没有先应用当前填写的主机和服务端口，可能使用上次操作留下的地址 | 所有 I2C 事务和总线命令先派发当前 DongleSetLink，再派发操作 | 三个事务按钮分别通过真实鼠标点击验证命令顺序与参数；未修改固件协议 |
| F05 | P2 | Dongle 连接参数只在设备信息页，不便核对；直接全部展开又会挤走事务按钮 | 参数页显示主机和端口摘要，按需展开编辑；保持关键事务按钮靠近相关参数 | 使用与设备信息页相同的 ControlState，无第二份地址状态 |
| F06 | P1 | 向上滚轮取消跟随后，接近底部又自动恢复；满 5000 行后 FIFO 淘汰仍使正在看的内容变化 | 显式固定历史快照；只有日志区域向上滚轮触发；底部向下三角释放快照并跳至最新，恢复跟随 | 接收、保存、解析和测试继续；真实 FIFO 与 API 始终使用最新数据 |
| F07 | P1 | 如果只冻结正文，查找命中、选择和字符位置仍可能随实时行淘汰变化 | 冻结窗格的选择与筛选索引保持不变；新筛选在快照上执行；恢复跟随后重新建立实时索引 | 搜索结果、正文、复制和字符定位使用同一数据源，API 分页不切换到快照 |
| F08 | P1 | 每次最多读取 2048 字节后固定休眠 20 ms，持续流吞吐理论上受限于约 102400 字节每秒 | 连续有数据时继续读取并让出调度；无完整事件时仅保留短等待；已有传输超时仍生效 | COM、TCP 和 WinUSB 的选择及格式处理不变；TCP 对端关闭明确报错，避免空读忙循环 |
| F09 | P2 | 无数据监控仍约每 33 ms 重绘；后台页固定低频消费又可能形成积压 | 后台接收线程合并请求 GUI 唤醒；积压时继续快速消费；无数据时使用原空闲轮询 | API 原有主动唤醒保留，接收不依赖串口页面可见，测试和文件任务仍有各自驱动 |
| F10 | P2 | 满窗口后等长日志反复触发全部行宽扫描；附加串口没有帧消费预算 | 单调队列维护窗口最大字符数；附加串口按既有 400 条和 4 ms 限制消费 | 5000 行、8192 条接收队列和原日志内容不变；未用丢弃接收数据换性能 |
| F11 | P2 | 计算工具六张卡按屏幕高度均分，小窗口卡片太矮，计算按钮常只露出一部分 | 卡片保留至少 340 点高度，通过整页滚动浏览，卡内原有滚动与结果保持 | 只调整排版，不修改公式、单位、CRC、转换器或 API |
| F12 | P2 | 串口查找和分屏、跟随等设置挤在一条横向工具栏，常用选项容易被隐藏 | 查找区独立横向滚动，显示选项另起可换行工具栏 | 保留查找快捷键、大小写、自动解析、分屏与编辑模式行为 |
| F13 | P1 | Dongle 底层应用连接设置时无条件清空 I2C 和 TCP UART，重复应用会使 I2C 操作打断串口 | 相同端点不重置；端口改变只重建对应 TCP 接口，共用主机改变时才重建两类 TCP 连接 | 本机同时建立两个 TCP 连接，验证重复设置保留连接、I2C 端口变化后 UART 仍实际可收发，COM/WinUSB 不因网络参数被关闭 |
| F14 | P1 | 仪表数值编辑控件的标识随布局复用，旧的未确认输入可能在切换对象后因失去焦点而提交到新对象 | 工作区按设备隔离，参数区进一步按通道及任务隔离编辑状态 | 构造 CH1 未确认输入后切换 CH2 并确认，验证 CH2 数值不变；保留原有显式应用设定行为 |

## 跨功能不冲突设计

### 数据与展示分离

实时缓存继续保留最新最多 5000 行，API 的累计数和 dropped 不受历史查看影响。历史窗格使用当时文本的 Arc 引用，不复制每行字符串；淘汰时只停止移动该窗格的查看索引。复制、查找和协议悬停读取同一份历史文本。恢复、清空和重新勾选跟随时释放旧视图，重新同步导航与筛选。

历史快照最多保留当时的显示窗口，但持续接收后仍会额外保留已淘汰的旧文本；不能宣称没有内存成本。多窗格可以各自停留在不同时间，因此并非每个窗格必定共享同一次快照。它不增加实时 FIFO 的行数上限，也不改变完整录制文件的保存行为。

### 控制与展示状态分离

仪表 UI 布局不直接调用底层驱动，动作仍进入原有设备任务队列。切换通道和页签不发送设置命令，应用电压/电流不自动开启输出，缺少读数继续显示缺测标记。I2C 的连接更新与事务在同一设备队列中顺序执行，防止图上地址和实际操作对象不一致。底层连接更新保持幂等，只对确实改变的 TCP 端点断开重建，不使 I2C 操作关闭并行 UART。

### 契约和判定保持

遵循 `docs/specs/wireless-test/00-system-contract.md`：不修改跨任务 schema、单位、时间映射含义、任务与产品结论的区分；不绕过设备租约和质量检查；模拟结果不升级为产品 PASS。现有 API、插件参数、报告路径和数据格式保持兼容。

### 资源优化的取舍

本轮采用已确认瓶颈的增量修正，没有引入整套异步会话处理器、异步文件提交或新的丢弃策略。这样保留既有写盘错误传播、测试事件顺序和停止时刷新行为。将来若分离写盘线程，需要额外实现退出确认、错误持久化和测试证据顺序，不能仅将写入任务丢进后台队列。

尚需专门设计的极端输入包括长期无换行、超长单行、无限过载和慢磁盘。5000 行及8192 条限制不等于字节内存上限；本轮没有默默截断这类输入，也不宣称对无限过载零丢失。这些属于后续资源边界和现场验收事项，见此前串口资源分析。

## 串口 Release 资源对照实测

同机本地 TCP 合成输入，约 128 字节原始文本每行；普通场景短时采样约 8 秒，超限场景约 16 秒。CPU 为整个进程相对整机占比，工作集包含整个 GUI。基线时有本机打包工作，新版数据在编译结束后取得，数值用于观察量级与吞吐，不能据此承诺固定降幅或长期稳定性。

| 场景 | 1.1.31 CPU | 1.1.32 CPU | 新版工作集 MiB | 新版累计接收 / 发送 |
| --- | --- | --- | --- | --- |
| 未监控 | 0.36% | 0.86% | 170.9 | 0 / 0 |
| 连接但无数据 | 1.62% | 0.16% | 173.0 | 0 / 0 |
| 500 行每秒 前台 | 2.80% | 1.08% | 188.8 | 4610 / 4625 |
| 2000 行每秒 前台 | 2.94% | 2.60% | 191.0 | 19056 / 19121 |
| 500 行每秒 后台 | 0.41% | 0.17% | 174.5 | 4578 / 4578 |
| 500 行每秒 超过行数上限 | 2.03% | 1.16% | 192.3 | 8682 / 8698 |

首次未监控场景中，状态 API 最大延迟为 2675 ms，采样时私有提交明显增长；该组可能受冷启动或初始化影响，不能当作稳态响应或稳态 CPU。后续场景保留在原始数据中分别比较，未删除这一异常取样。

累计数在各自取样时刻读取，小差值包含采样时序和在途数据；巨大差值表示积压，不能直接等同于丢失。高负载时新版处理了更多数据，CPU 对比必须同时考虑实际吞吐，不能要求在工作量增加时 CPU 数值也必然更低。TCP 输入不是物理 COM/WinUSB 满速验收；没有把短时工作集变化解释为内存泄漏结论。

原始数据随包保存于 `docs/verification/serial-resource-1.1.31.json` 与 `serial-resource-1.1.32.json`，新版程序哈希一并记录。

## 仍需现场验证的范围

实物仪表/VISA/USB 驱动组合、真实 COM/WinUSB 持续高负载、磁盘满/拔盘、跨显示器 DPI、设备断开和长稳，以及 Dongle 捕获固件、独立保护闭环与工业 G2—G4 验收，不能由本机合成回归代替。`industrial_approved` 保持 false。本轮不发布在线更新 stable 清单。
