# WiParse 1.2.5 · 工程 Agent 与测试证据

发布日期 2026-11-12，沿用 egui 工作分支 cursor/four-job-shell-and-marketplace。GUI、CLI、设备服务及 MCP 版本同步为 1.2.5，无线充电插件为 0.1.2。

## 对工程人员的变化

| 场景 | 行为和适用范围 |
|---|---|
| 整表限值 | report.read 可按阶段精确匹配、计算同单位两列的差，再使用指定上下限。续扫累计记录有效、无效、排除与越限行。两个助手显示本地判定，阻止已识别的整表通过声明与实际扫描冲突。CSV 分段结束并不代表整表通过。 |
| 报告截图 | 链接的 PNG/JPEG 在本地解码。Windows OCR 使用系统已安装的识别语言，返回可见文字、像素尺寸及文件摘要。缺少 OCR 时保留像素结果及错误。精确幅度和时间仍需原始波形。 |
| 长任务与报告 | 项目 SQLite 为完成步骤保存证据摘要和内容。恢复或导出时校验摘要。显式保留的数据提取同步归档可复核的数据集、原始记录链接及曲线，可以在切换文件后写入报告。该选项会占用工程磁盘空间。普通预览打开有创建凭据的 AI 报告时在后台核验正文与附件。 |
| 仪表读回 | 对已连接的独立示波器，可给类型化 instrument.command 指定 verify 参数。宿主在原作业成功后发起一次指定通道的读数，登记设备身份、两个作业回执、主机查询窗口、单位、限值与不确定度。显示值比较与实物验证分开。 |
| 任务复核与工程配方 | 界面可复制任务 ID。自动化方法 agent.tasks 或 MCP 的 wiparse_ui 同名操作可按工程分页读取任务观察和最新检查点。agent.recipe 复用真实回执计算断充次数、双向死区范围和适配器用例覆盖。运行配方需要相应日志状态规则、双通道时序或适配器矩阵。 |
| 无线充电验证 | live 预检查对已审核的配置摘要、工位能力及保护状态。作业取得夹具租约，验证就绪和安全初态后发送一次刺激。插件保存原始观察、定位坐标和校验摘要。停止或取消先执行工位安全收尾并等待反馈。内置设备服务与默认未调试站点继续明确报告缺少的能力。 |

## 升级与调用

现有工程可直接打开。任务日志新增的表在保存新记录时创建。旧报告或缺少创建凭据的附件保留原有可读性及核验边界。跨电脑迁移工程时携带项目中的 agent-tasks.sqlite3、ai-reports 和 agent-datasets，并先关闭正在使用该工程的 WiParse。发布目录使用相对路径。

- 核查传输阶段 VIN 与 VBRG 差值时，先从文件确认列名和单位，再传 scan.column、scan.subtract_column、scan.where、scan.min/max。每个阶段使用自己的规则及续扫游标。
- 回放任务时，在工程任务菜单复制 ID，调用 agent.tasks 并传 task_id。继续读取时传返回的 next_after_seq 作为 after_seq。回放仅查询历史记录。
- 实机插件握手、方法及保护反馈要求见[无线充电插件接入说明](../../test-tools/plugins/wireless-charge-validation/README.md)。

## 验证记录

Windows 工作区回归通过 664 项，其中核心 331、GUI 327、设备服务 6。8 项沿用仓库忽略标记。新增覆盖包括不完整或越限扫描的结论、阶段筛选与差值续扫、断充配方、缓存淘汰及跨重启证据导出、归档曲线恢复和摘要篡改。任务记录收尾调整后，4 项日志回归复验通过。

插件全套 76 项通过。随后新增一例完整工位契约测试，无线充电专项 23 项全部通过，专项数量与全套有重叠。覆盖模拟工位采集、检查、归档，以及刺激后取消、安全反馈和释放租约。MCP 完成 TypeScript 构建、1 个任务回放、4 个报告及 20 个 Hub 转发检查。Python 合成盲评管道通过。

## 现场验收边界

本次未在通过 G4 批准的工位上给 DUT 通电，也未实测探头接线、仪器校准、跨设备时钟误差、丢行率及急停时延。已有软件可执行工位契约，使用真实夹具仍依赖现场提供兼容后端和经审核的产品限值。缺少独立专家裁决的实采留出集，不能计算诊断准确率或相对其他 Agent 的性能排名。
