# WiParse 全局 AI 接口

实现日期：2026-10-18。纳入 WiParse 1.2.0 发行包。

## 使用

设置菜单 **AI** 打开“AI 设置与助手”。选择服务预设，填写模型名称和 API Key，点击“测试连接”，确认后启用并保存。配置在所有工具间共享。

| 服务 | 预设地址 | 预设模型 | 接口 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash`，可编辑 | Chat Completions |
| 千问北京 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`，可编辑 | Chat Completions，流式兼容 |
| 千问国际 | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` | `qwen-plus`，可编辑 | Chat Completions，流式兼容 |
| OpenAI | `https://api.openai.com/v1` | 用户填写 | Responses |
| 自定义兼容服务 | 用户填写基础地址或完整端点 | 用户填写 | Chat Completions / Responses |

模型可用性以账户为准，不绑定固定版本；千问服务器地域必须与 API Key 地域一致，也可填写百炼业务空间专属域名。千问使用 OpenAI 兼容端点，本实现不调用 DashScope 原生 generation 端点。当前支持文本输入、文本分析与多轮对话。通用工程助手现已增加受限工具任务模式（见下文）；串口专用 AI 窗口对所选日志范围自动执行只读分析，设备启停及仪表命令另需允许控制，且受测试运行锁保护。不包括图像、语音或任意命令执行。

“深度思考”按厂商发送不同参数：DeepSeek 为 `thinking.type`；千问为 `enable_thinking`。预设默认关闭思考；部分模型不支持关闭，须按具体模型要求调整。千问预设启用流式兼容，服务端流式回复完成后统一展示最终文本；不显示 reasoning_content。Responses 当前采用非流式请求。Chat Completions 的 Agent 工具任务使用非流式原生 function tools，普通聊天保留原有流式行为。

API Key 使用 Windows 当前用户 DPAPI 加密后保存到 `ai.protected_api_key`，不是明文；跨电脑或用户迁移时重新输入。也可填写环境变量名称（如 `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY`），填写后优先读取该变量。非 Windows 平台使用环境变量，不保存本地密钥。切换服务预设或编辑服务器地址会清除旧服务器的凭据草稿；保存后才更改全局服务。

设置菜单 **AI** 打开当前页面的助手。窗口按所在工具显示页面说明和三条建议问题。点建议会把该问题填入输入框，并附上本页摘要，仍需确认后才发送。摘要只在点击建议或“加入当前页面摘要”时收集；打开窗口、切换工具或启动程序不会自动发送数据。

各页摘要有固定边界，不包含本地路径、密钥、仪器命令和原始采样：

| 页面 | 附带内容 |
|---|---|
| 串口工具 | 当前日志页最近 50 行，每行最多 400 字符 |
| 波形分析 | 最多 16 通道的缓存测量，以及最多 20 条协议帧摘录 |
| 测试报告 | 项目内最多 30 项的运行结论，加上正在打开报告的短摘录 |
| 仪表控制 | 最多 8 个会话的型号、资源、采集状态和最近日志 |
| 数据分析 | 曲线点数、单位、比例和阈值 |
| 集成测试 | 插件名、测试项目、选择数量和矩阵统计 |
| 计算器 | 六个计算器当前输入和已算出的标量结果 |

发送时的任务说明随页面变化，要求模型只依据摘要分析，不宣称已经操作仪器、写入串口、启动测试或改写结论。

## 内部调用

共享实现位于 `wiparse_core::ai`。GUI 安装唯一的 `AiService`，各工具通过 `crate::ai::service(ui.ctx())` 获取同一服务克隆。克隆共享配置与并发预算，不应为每次操作创建新的服务。

```rust
use wiparse_core::ai::AiRequest;

let ai = crate::ai::service(ui.ctx()).ok_or("AI service unavailable")?;
let task = ai.submit(AiRequest {
    purpose: "解释通信异常，列出证据与待验证项".into(),
    text: selected_context,
})?;
// 在后续帧中用 task.result.try_recv() 轮询，禁止在 UI 线程 recv() 阻塞。
// task.cancel() 取消等待；已发出的 HTTP 请求可能继续处理，直到完成或超时。
```

核心服务默认禁用，最大并发 2；连接测试也占用同一预算。请求输入上限 1 MiB，服务响应上限 16 MiB，超时可配置 5–300 秒。没有自动重试或重定向，防止重复计费或向重定向地址传递密钥。错误不回显服务器正文、请求文本或 Authorization。HTTP 状态、网络超时、响应损坏、输出截断、密钥不可用分别可识别。

通用助手回复呈现为建议。串口专用窗口的有限自动化见下节；两者均没有仪器输出、串口写入、测试执行或判定修改入口，不替代 `00-system-contract.md` 的采集质量与产品判定规则。

## 助手体验修正（源码更新，尚未重新打包）

- **连接测试与问答分开**：助手页也可点击“测试当前连接”，测试只发送简短探测，不携带对话或页面摘要。成功由客户端根据有效响应判断，不根据模型是否说“联网”判断。当前填写的配置可以先测试，必须保存并启用后才用于对话。
- **回复可读**：解析并缓存 Markdown，显示标题、强调、列表、引用、表格及代码块；代码可单独复制，整段回复可复制，亦可切换原文。长表格及代码横向滚动，正文自动换行。不自动获取模型提供的图片或读取其本地文件引用，网页链接仅在点击后打开。
- **连续追问**：上下文按 user/assistant 角色传输，不只发送最后一句。内存最多保留12轮、512 KiB（单轮超限仍保留最新轮），请求历史取最近最多10轮且不超过128 KiB；完整请求仍受256 KiB限制。新对话清除当前历史；切换服务器、模型、接口或凭据后不把旧对话传给新配置。历史不自动保存到磁盘。
- **上下文透明**：页面摘要须由用户选择并可编辑；发送成功受理后从输入草稿清除，已发送的摘要保留在对应轮次中。当前轮次草稿不会在请求失败时丢失。
- **状态与恢复**：显示连接成功、生成耗时、输入/输出 tokens；原始 usage JSON 收入折叠详情。认证失败、权限、路径/模型、限流/额度、网络超时提供不同提示。没有后台自动重试；用户可点击重试。取消不清除已完成对话。
- **保留已有内容**：达到输出 token 上限时保留已生成正文并标明“部分回复”，支持继续追问；无结束标志的损坏/中断流仍明确报错。超长正文限制预览，复制仍保留完整回复。
- **输入操作**：Ctrl+Enter 发送，Enter 换行；对话区显示在输入区之前。服务设置未保存或未启用时明确提示，避免分析请求静默使用旧服务器或旧密钥。

回归使用本地模拟服务覆盖两种接口的连续角色、短连接探测、部分输出保留、GUI两轮追问/401失败/再次连接测试、宽窄屏和明暗主题的 Markdown 显示。未使用用户的真实 API Key，云端服务实际调用仍需在用户环境验证。

## 串口专用 AI 窗口（2026-10-25）

串口日志工具栏的“数据分窗”已移除，改为“AI 窗口”。点击后右侧显示可拖动宽度的对话栏；再次点击或关闭只结束 AI 等待与 AI 监控，串口接收继续。右栏设置打开现有全局 AI 配置，无需重复填写服务或密钥，兼容既有 DeepSeek、千问与两类文本接口。对话仅存内存，切换工程清除旧工程对话和自动化授权。

- 数据分析：发送问题或点“分析数据”；默认附带当前数据，可关闭。单次最多100行、每行400 UTF-8字节，选中文本最多16 KiB；显示抽样边界，未保存的文件编辑不纳入采样。Markdown直接呈现，不显示动作JSON或usage原文。
- AI监控：先启动实时接收，再点“开始AI监控”；支持1–300秒，默认5秒，仅在有新增数据时发请求，最多一个串口AI请求在途。窗口内统计收到的行数和关键词提示，保留最多12条短异常样例；关键词提示不等于测试判定。监控使用有界定时采样，不保证捕捉全部瞬态，不替代原有实时采集、触发和保护。连续三次请求失败暂停监控，失败间隔退避；没有串口连接自动重试。
- 有限自动化：勾选“允许自动化”后，可要求AI启动/停止当前串口接收、开启/停止AI监控。默认关闭；授权对单个请求进行快照，发送时未授权的旧回复不能因事后勾选而获得执行权限。串口原始发送、任意命令、文件修改、仪器输出、产品判定修改均不支持。
- 宿主确认：启动请求与实际连接成功分别显示；15秒未确认或端口失败时明确报错。停止说明后台释放端口。切换工程、日志源、串口选择、波特率、会话或清空数据后，旧请求不得控制新目标。集成测试或串口测试运行中只允许分析；操作执行前再次核对测试锁与当前目标。
- 传输：复用唯一 `AiService` 及并发/超时/凭据规则。独立传输历史最多12条消息，展示最多40条记录，每条最多24 KiB。关闭数据附带时不发送原始行、选区或关键词样例。关闭窗口、换工程或AI配置时取消等待；已发HTTP可能继续消耗服务预算直至完成/超时。

串口动作协议是宿主内部文本契约，不改变插件设备租约、公共MCP或无线测试数据模型：

```json
{"reply":"可读的 Markdown 分析","actions":[{"type":"serial.start"},{"type":"monitor.start","interval_seconds":30}]}
```

仅接受 `serial.start`、`serial.stop`、`monitor.start`、`monitor.stop`；最多一个串口动作和一个监控动作。未知动作、额外参数、冲突动作或超范围间隔拒绝整组执行；普通文本仍可作为分析显示。模型声明与真实执行回执分开，不把模型说“已启动”当作连接成功。当前实现不请求厂商原生工具调用扩展，保持现有接口兼容性。


## 串口智能测试工作台增补（2026-10-25，后续调整）

此节更新同日第一版专用窗口：主入口改为“智能对话”，可对话配置监控目标、关键词及数值预警，启动监控、调用平台并继续分析实际结果。“监控任务”页集中呈现目标、周期、规则与状态。数据范围已于 2026-11-09 扩展为当前日志全范围、指定行范围、选中内容、本地日志库、仅提问，日志经过本地处理后发送有限统计与证据；输入区固定在底部。最近日志与选区不同时隐式发送。

预警由本地规则及时显示证据，云端负责异步分析；支持1–300秒、默认5秒，有异常时优先提交且最短1秒一次；慢响应不累积请求。相同规则2秒合并展示，累计次数保留；消息和样例保持有界。后台采样不混入手动追问的传输历史；主对话可展开监控结果。切换数据源会开启新对话并撤销控制权限。

AI可通过白名单平台目录调用设备清单/状态、类型化示波器/直流源/负载控制、测量、截图、源波形采集、单行Qi/AA55解析、进制换算、缓存指标、计算器状态及测试状态。只使用现有已连接会话；设备操作和串口接收启停需要“控制：开”。只读查询及AI监控无需设备控制授权。任意SCPI、任意串口发送、系统命令、擦除/烧录、任意路径仍不开放。

平台动作格式：

```json
{"reply":"先读取实际频率，再与日志关联分析。","actions":[{"type":"platform.call","method":"instrument.command","params":{"device_id":1,"command":{"ScopeMeasure":{"channel":1,"meas_type":"Frequency"}}}}]}
```

一次回复只执行一个平台调用；最多六轮调用，实际工具结果自动交回AI。设备任务通过`instrument.job.get`核对完成记录，accepted不等于已完成。排队前后核对工程/源/会话/授权和测试锁，已下发硬件任务取消或超时不伪装撤回或成功。完整分析、影响范围与限制见[评审记录](reviews/serial-ai-intelligent-workbench-2026-10-25.md)。

云端连续三次失败时只暂停AI分析，本地规则和预警继续；在监控任务页可恢复AI分析。修改服务配置同样暂停云端分析、保留当前本地监控，切换工程或日志源仍结束旧监控。后台监控保持接收唤醒，不依赖云端采样周期才显示本地预警。

`instrument.job.get`使用独立于串口测试通知的完成缓存，最近512项可重复查询。摘要有深度/条数/16KiB内容预算，原测试通知仍获得完整结果；记录过期或未完成时返回`pending_or_unknown`，不能当作成功。

## 2026-11-09：串口 AI 本地全范围文本处理

手动对话默认“当前日志 · 全范围”，不再直接上传最近 100 行。`log.files` 返回当前授权范围内的来源 ID；`log.analyze` 在后台流式处理全部来源，支持关键词、排除词、正则、行号范围、归一化分组、数值统计和阈值计数。AI 按需请求有限证据；“本地预分析”不调用 AI。

范围由用户决定，主机强制约束：当前磁盘日志只扫描当前文件；指定行范围包含首尾且上下文不越界；选中内容在本地分析并使用选区相对行号；日志库可递归扫描用户选择的目录、已打开的磁盘日志，以及当前主串口已落盘记录。AI 不接收目录绝对路径，也不能传入任意文件路径。

实时日志使用共享不可变行快照，保留现有 5,000 行显示上限，不复制完整日志字符串。已淘汰历史通过 `preceding_rows_unavailable` 明示；需要完整历史时，选择日志库中的落盘文件。未保存到磁盘且已淘汰的数据不可恢复。正在增长的文件仅扫描开始时的字节范围，并标记完整性存疑，不将半行当作完整测量。

本地查询单批默认 1 GiB / 15 秒工作预算，可调整为 64–4096 MiB；不足时返回主机签发的 `continuation`，继续只传 `{"cursor":"..."}`，结果累计，不可相加。每个窗口保留最多 4 个查询状态，全局最多 2 个扫描工作线程；每轮对话仍最多 6 次工具调用。一次扫描不等于无限制占用内存或无限制上传。

每份核心报告最多 6,000 UTF-8 字节（外层工具标识略增），列明覆盖范围、编码/超长行问题、分组截断和证据来源行号。支持 UTF-8 文本；无效 UTF-8 或疑似 UTF-16 的输入明确标记不完整，不能据此作出“全量正常”的结论。磁盘扫描不包含编辑器未保存修改。

自动 AI 监控继续使用有界采样与本地预警，保持既有云请求间隔、串口显示行数和设备控制授权流程。全范围扫描是手动分析工具，不应当作硬实时安全联锁。


## 2026-11-10 工程智能任务

## 2026-11-10 串口 Agent 执行闭环更新

串口专用助手选择“当前日志·全范围”等范围后，发送分析目标即授权在该范围内读取。模型按分析目标主动调用本地引擎取得分组、覆盖统计和有界样例，识别实际字段后继续检索、数值分析或事件归并；普通问答不预先扫描日志；不要求用户额外回复“开始扫描”“调用”“继续”。无需指定某一份样本文件，亦未内置某产品断充状态码。摘要模式上表的最近行数不限制专用助手的本地分析范围。

设置的 `ai.tool_mode` 默认 `auto`（界面“原生工具优先”），Chat Completions 使用原生工具调用；`json`（“JSON兼容模式”）适用于不支持 function tools 的网关。Responses 当前使用结构化 JSON 动作。原生请求保留匹配的 tool call ID、实际工具结果及服务要求的思考续接字段，但界面不显示内部推理。工具协议被服务拒绝时给出诊断，不自动重放网络请求。

原生便利工具：

|工具|用途|对应平台方法|
|---|---|---|
|`wiparse_log_files`|所选范围的文件清单和覆盖|`log.files`|
|`wiparse_log_analyze`|搜索、上下文、分组、数值统计、cursor续扫|`log.analyze`|
|`wiparse_log_events`|模型据实际证据定义状态规则，计数并分页取证|`log.analyze` 的 `events`|
|`wiparse_call`|当前权限下其他平台能力|枚举白名单|
|`wiparse_answer`|提交结果、完成/需业务澄清状态、证据引用|宿主终结校验|

`events` 支持 `active_pattern`、`inactive_pattern`（必填），以及 `entity_pattern`、`reason_pattern`、`timestamp_pattern`（可选，取捕获组1）、`context_lines`、`offset`、`limit`。状态工具不能与行过滤器混用，防止破坏时序。确认 active→inactive 才计数，初始 inactive、重复 inactive、歧义分别披露；相邻原因是关联而非因果证明。不同来源不拼接状态。

串口助手可通过 `engineering.inspect` 查看波形、数据分析、测试报告、测试工作区、计算器、仪表上下文；通过 `engineering.wave.measure`、`engineering.wave.frames`、`engineering.calc.evaluate` 复用实际后台引擎。这些属于只读分析，不需要开启设备控制。

串口任务最多32次模型工具动作、600秒；共享工作槽占满时本地排队。切换来源/范围、取消、测试锁和设备权限继续生效。结果附实际证据ID；标准最终文字可以直接呈现；常规只读确认循环和未完成目标收到反馈，连续无效执行最多纠正3次，有效工具后恢复纠正预算；仍无进展则明确失败。实时本地预警与云端周期分析仍是不同通路。

详见 [执行链评审与整改报告](reviews/serial-agent-execution-review-2026-11-10.md)。

## 复杂充电任务与 token 额度增补（2026-11-10）

软件 `ai.max_output_tokens` 可设64–262144，默认8192；旧配置保留原值。最大值是客户端允许的请求额度，具体模型可能只支持其中一部分；服务拒绝过大请求时请降低额度。连接探测仍最多256输出 token，普通分析不会自动提高已保存额度。输入总字节上限1 MiB、HTTP响应体16 MiB，与模型上下文 token 数不是同一概念。

原生工具任务执行后可直接返回普通 Markdown 最终报告，不要求模型必须额外调用 `wiparse_answer`。未执行有效后续工具的纯计划会收到有界协议反馈；回复截断单独提示，不执行其中不完整动作。活动记录给出协议类别，避免泛称模型没有能力。

新增 `wiparse_log_timeline`（对应 `log.analyze` 的 `timeline`）：

```json
{
  "timestamp_pattern": "(\\d{2}:\\d{2}:\\d{2}\\.\\d+)",
  "timestamp_unit": "clock",
  "start_time": "20:05:09.865",
  "end_pattern": "CHARGE_END",
  "fields": [
    {"name":"vin","pattern":"VIN=([0-9.]+)","unit":"V","scale":0.001},
    {"name":"iin","pattern":"IIN=([0-9.]+)","unit":"A","scale":0.001}
  ],
  "power_pair": ["vin","iin"],
  "max_points": 48
}
```

以上示例适用于带时钟时间、VIN/IIN毫伏/毫安及CHARGE_END标记的日志；实际字段、单位、正则和结束标记必须从当前证据识别，不能假设产品都采用这个格式。`timestamp_unit` 支持 `clock`（HH:mm:ss.fraction）、`s`、`ms`、`us`；可选 `start_pattern` / `end_pattern` 指定实际周期标记，数值 `scale` 转为所声明单位。功率配对要求单位V、A，且仅对同一条带时间记录相乘，不跨行猜测。可用 `source_ids` 和行范围限制来源，不与包含/排除行过滤混用。

宿主直接显示本地提取的曲线与全样本统计；曲线是有界分桶均值，不是原始全部采样点，峰值应读取全样本统计。缺失值不插值，文件不拼接，倒退时间跳过并计数；跨午夜推断也会标注。每次最多4个来源，遗漏或裁剪标志不为零时按来源分批分析。只有观测起止的跨度不等于已确认的完整充电时长。

最终 Markdown 报告由模型解释实际工具证据，可在对话复制。当前不自动把对话报告写入测试报告库，也不把图表自动嵌入导出文件。完整评审见 [复杂工程任务报告](reviews/serial-agent-charging-workflow-2026-11-10.md)。

## Agent工作流、上下文与消息队列增补（2026-11-10）

串口及通用助手共享会话内任务/证据组件：

- `agent.plan {steps:[{id,title,state,deliverable?,evidence_ids?,reason?}]}`：最多12项，状态pending/running/done/blocked；完成引用实际证据，阻塞说明具体原因，不静默删除未解决目标。
- `agent.evidence {evidence_id}`：从有界账本召回历史结果，保留来源与裁剪标记，不把历史值称为新测量。
- `agent.help {method}`：按需查询参数与单位，减少所有规则常驻。原生便利函数分别为 `wiparse_plan`、`wiparse_evidence`、`wiparse_help`。

这些是当前AI任务会话内管理方法，不是可脱离会话直接调用的通用GUI RPC。外部MCP/Agent SDK适配必须携带宿主会话与权限，不应把函数名直接当成全局后端接口。原有数据/设备RPC保持原契约。

证据最多48项、详情总预算512 KiB，精简事实索引最多16 KiB并附可用ID。原生任务固定初始请求与历史，把变化的宿主状态放到已有工具消息之后；保留配对ID及服务所需续接字段。JSON兼容模式不丢掉动态上下文。此调整改善可缓存前缀条件，不保证服务缓存命中。

原生串口支持一轮最多4个独立只读调用，宿主依次执行、统一回传；不批量执行设备、监控配置或管理动作。普通问答不再预先扫描整份日志。复杂任务检查已声明的未完成目标，要求继续或明确阻塞。串口工具预算32次/10分钟；通用助手默认16轮，可选择4/8/16/24/32轮。

串口分析中可继续提交问题，按FIFO排队；支持查看、删除、编辑到输入及清空。最多16条/64 KiB，队列满时输入不丢失。正常完成自动继续，取消/失败/来源变化后暂停。来源、范围和提交时授权被冻结并在执行时复查，排队文字不会自动转到新文件或自动获得新设备授权。队列在内存中，关闭后暂停保留于当前进程，不提供跨重启持久化保证。

顶部采用三行固定头部，日志预分析入口移入“…”菜单；输入区固定在底部，分析中显示“排队发送”。撤销设备控制会同步收回旧排队项权限。实时数据按执行时可用范围处理，不为每条排队消息复制整个原始日志。

用量展示以服务usage为准，统计输入、输出及缓存Token；未提供的字段显示未知。串口包含当前任务和当前会话累计，服务失败不推断零成本。缓存Token是输入的子集，不额外加到total，不硬编码模型价格或节省比例。

本轮没有安装外部Agent SDK。详见[智能性评审](reviews/ai-agent-intelligence-review-2026-11-10.md)和[开源框架评估](reviews/ai-agent-open-source-integration-2026-11-10.md)。

## 工程任务结果、文件曲线与时钟对齐（2026-11-11）

原生和 JSON 助手均支持终态 `needs_input`。它用于缺少工程输入（如设定电压），同一来源上补充输入时保留未完成目标。已授权的本地读取直接执行。保存文件使用 `report_file` 交付类型，对话内总结使用 `report`。完整周期时长需要已确认的边界，通信核查需要真实解码证据。无法获得时将对应目标标为 blocked 并写明原因。

数据页已有文件时，先 `data.inspect` 获取候选选择器，再按需执行下例。默认逐行读取；只有明确第一条是表头时设置 skip_first_record。缺列或空字符串计入 missing，存在但无法转换的值计入 invalid。若正则选择器本身只匹配数字，不匹配的记录记为 missing。没有有效记录时返回失败和覆盖范围。统计使用所有有效数值，时间轴缺失或倒退的行无法进入时间曲线，计数单独返回。

```json
{"method":"data.extract","params":{"fields":["csv:2","csv:3"],"units":["V","A"],"timestamp":{"selector":"csv:1","unit":"ms"},"skip_first_record":true,"retain_dataset":true}}
```

用返回的 query_id 调用 `data.present`。不传 timestamp 时使用从 1 开始的记录序号。当前保留一份文件提取数据集，上限 250,000 条；超限仍完成统计，返回超限行数。模型读取摘要，本地点列进入绘图和报告。生成文件报告时向 `report.create` 传实际提取或展示结果的 evidence_id；报表 CSV 保留原单位和空值，图表显示单位可随界面作换算。

`agent.align` 接受同一会话中 log.analyze 和 wave.frames 的真实证据 ID、日志来源、两个对应边界的帧索引与待换算的日志秒数。仅在已观测边界之间插值。操作方若掌握校准记录，可给出 calibration 的 first_pair_error_s、last_pair_error_s 和 residual_rate_bound_ppm；返回误差为依赖这些假设的条件上界。未知参数应省略。记录序号不作为物理时间，两个时间点的重合不足以证明因果关系。

运行 `python scripts/summarize-ai-tasks.py <应用日志>` 可离线查看任务终态分布、完成时延、首证据时延和每个已完成任务的 Token 分布。按时间顺序传入同一测试窗口内无重复的日志文件。请求缺失、提供方未报告 Token 或存在失败尝试的任务不进入 Token 分位数；查看输出分母后再做成本对比。任务终态是宿主记录的交付结果，工程结论正确率需另以标注样本评估。

## 工程 Agent 任务与取证

串口和工程助手可在任务内修正目标。查看任务进度可以区分待办、已验证与阻塞项。工程的任务索引保存在 `projects/<project>/agent-tasks.sqlite3`。任务记录中的历史证据可用于起草继续调查的问题。打开草稿后应先核对当前数据源和设备读回结果。

开启串口监控后，本地规则命中首个告警会冻结该行与此前最多八条已接收日志。监控页可展开查看。每行最多保留 600 字节摘要，行号按本次监控接收顺序计数。该缓冲属于当前监控任务，采集文件仍是完整记录。规则按到达宿主的顺序处理，无线侧时序或串口上游丢样需结合设备时间戳和采集状态核实。

对打开的文本执行 `data.extract` 时，结果包含解码后文本的 SHA-256。保留数据集并生成报告后，报告内的 `source-rows.csv` 记录每个保留点的回源位置。按行提取给出原文行号（从 1 开始），按帧头提取给出解码后 UTF-8 文本中的字节偏移（从 0 开始）。清除显示、跳过表头及时间轴换算均独立于这个坐标。数据集点数上限和全文件扫描行数可在结果中分别核对。

### 重跑基线和对标

`python scripts/benchmark-engineering-agent.py --output seeds.json` 运行 12 个确定性软件种子，输出每个任务的测试入口与结果。此组可用于开发回归。工位采集的独立盲评数据应单独存档。

`python scripts/summarize-ai-tasks.py <日志> --reviews <评分文件>` 可按正确交付计算 Token 成本。评分文件是任务 ID 到布尔值的映射。脚本累计有任务归属的所有请求，包含失败和重试。评分、终态或使用量不全时，成本结果保留为空。

`python scripts/compare-engineering-agent.py <已评分结果.jsonl>` 处理跨版本、模型或人工流程的同组任务。每行应含 arm、task_id、category、capture_group、rubric_sha256、correct、critical_failures、total_tokens 和 elapsed_ms。填入冻结评分规范的摘要。正确率使用独立工位记录为分母，并给出 Wilson 95% 区间、关键错误明细和 P50/P95 时延。计费缺失用 null；人工流程的 Token 指标保留为空。仅当所有组使用同一套案例和评分规范时才生成对照表。

### 大文件调查与报告回源

在数据分析页打开原始记录，可以要求 AI 指定分帧方式、字段和单位，保留提取结果，再画图并生成报告。超过 250,000 条输入的文件走本地分页曲线和完整表导出路径；源记录缺少有效时间戳时，统计和可绘制记录数分别列出。串口 log.analyze 的多来源时间线有独立的保留预算，必要时按来源和时间窗分段，或在数据分析页提取完整文件。

打开生成的 Markdown 报告，点击原文定位链接可核对源行或解码后字节位置。对波形测量和协议帧，点击采样区间可跳转至波形页并放置时间光标。已载入的匹配通道直接定位；重新打开工程时可选择原始波形，程序校验通道及解码样本摘要。文件名和通道名称相同但样本不同会提示不匹配。

从任务记录恢复调查时，宿主核对报告摘要、设备会话和作业回执。对结果未知的写操作，先在设备控制页查看实际状态，再决定是否重新提交对应操作。盲评工具的输入输出及现场验证边界见 [工程 Agent 候选记录](reviews/engineering-agent-candidate-2026-11-11.md)。
