# WiParse 全局 AI 接口

实现日期：2026-10-18。纳入 WiParse 1.2.0 发行包。

## 使用

设置菜单 **AI** 打开“AI 设置与助手”。选择服务预设，填写模型名称和 API Key，点击“测试连接”，确认后启用并保存。配置在所有工具间共享。

| 服务 | 预设地址 | 预设模型 | 接口 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash`，可编辑 | Chat Completions |
| 千问北京 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`，可编辑 | Chat Completions，流式兼容 |
| 千问国际 | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` | `qwen-plus`，可编辑 | Chat Completions，流式兼容 |
| OpenAI | `https://api.openai.com/v1` | 用户填写 | Responses |
| 自定义兼容服务 | 用户填写基础地址或完整端点 | 用户填写 | Chat Completions / Responses |

模型可用性以账户为准，不绑定固定版本；千问服务器地域必须与 API Key 地域一致，也可填写百炼业务空间专属域名。千问使用 OpenAI 兼容端点，本实现不调用 DashScope 原生 generation 端点。当前支持文本输入、文本分析与多轮对话。通用工程助手现已增加受限工具任务模式（见下文）；串口专用 AI 窗口在用户开启自动化后，允许宿主执行有限的串口接收启停及 AI 监控动作。不包括图像、语音或任意命令执行。

“深度思考”按厂商发送不同参数：DeepSeek 为 `thinking.type`；千问为 `enable_thinking`。预设默认关闭思考；部分模型不支持关闭，须按具体模型要求调整。千问预设启用流式兼容，服务端流式回复完成后统一展示最终文本；不显示 reasoning_content。Responses 当前采用非流式请求。

API Key 使用 Windows 当前用户 DPAPI 加密后保存到 `ai.protected_api_key`，不是明文；跨电脑或用户迁移时重新输入。也可填写环境变量名称（如 `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY`），填写后优先读取该变量。非 Windows 平台使用环境变量，不保存本地密钥。切换服务预设或编辑服务器地址会清除旧服务器的凭据草稿；保存后才更改全局服务。

设置菜单 **AI** 打开当前页面的助手。窗口按所在工具显示页面说明和三条建议问题。点建议会把该问题填入输入框，并附上本页摘要，仍需确认后才发送。摘要只在点击建议或“加入当前页面摘要”时收集；打开窗口、切换工具或启动程序不会自动发送数据。

各页摘要有固定边界，不包含本地路径、密钥、仪器命令和原始采样：

| 页面 | 附带内容 |
|---|---|
| 串口工具 | 当前日志页最近 50 行，每行最多 400 字符 |
| 波形分析 | 最多 16 通道的缓存测量，以及最多 20 条协议帧摘录 |
| 测试报告 | 项目内最多 30 项的运行结论，加上正在打开报告的短摘录 |
| 仪表控制 | 最多 8 个会话的型号、资源、采集状态和最近日志 |
| 数据分析 | 曲线点数、单位、比例和阈值 |
| 集成测试 | 插件名、测试项目、选择数量和矩阵统计 |
| 计算器 | 六个计算器当前输入和已算出的标量结果 |

发送时的任务说明随页面变化，要求模型只依据摘要分析，不宣称已经操作仪器、写入串口、启动测试或改写结论。

## 内部调用

共享实现位于 `wiparse_core::ai`。GUI 安装唯一的 `AiService`，各工具通过 `crate::ai::service(ui.ctx())` 获取同一服务克隆。克隆共享配置与并发预算，不应为每次操作创建新的服务。

```rust
use wiparse_core::ai::AiRequest;

let ai = crate::ai::service(ui.ctx()).ok_or("AI service unavailable")?;
let task = ai.submit(AiRequest {
    purpose: "解释通信异常，列出证据与待验证项".into(),
    text: selected_context,
})?;
// 在后续帧中用 task.result.try_recv() 轮询，禁止在 UI 线程 recv() 阻塞。
// task.cancel() 取消等待；已发出的 HTTP 请求可能继续处理，直到完成或超时。
```

核心服务默认禁用，最大并发 2；连接测试也占用同一预算。请求输入上限 256 KiB，服务响应上限 2 MiB，超时可配置 5–300 秒。没有自动重试或重定向，防止重复计费或向重定向地址传递密钥。错误不回显服务器正文、请求文本或 Authorization。HTTP 状态、网络超时、响应损坏、输出截断、密钥不可用分别可识别。

通用助手回复呈现为建议。串口专用窗口的有限自动化见下节；两者均没有仪器输出、串口写入、测试执行或判定修改入口，不替代 `00-system-contract.md` 的采集质量与产品判定规则。

## 助手体验修正（源码更新，尚未重新打包）

- **连接测试与问答分开**：助手页也可点击“测试当前连接”，测试只发送简短探测，不携带对话或页面摘要。成功由客户端根据有效响应判断，不根据模型是否说“联网”判断。当前填写的配置可以先测试，必须保存并启用后才用于对话。
- **回复可读**：解析并缓存 Markdown，显示标题、强调、列表、引用、表格及代码块；代码可单独复制，整段回复可复制，亦可切换原文。长表格及代码横向滚动，正文自动换行。不自动获取模型提供的图片或读取其本地文件引用，网页链接仅在点击后打开。
- **连续追问**：上下文按 user/assistant 角色传输，不只发送最后一句。内存最多保留12轮、512 KiB（单轮超限仍保留最新轮），请求历史取最近最多10轮且不超过128 KiB；完整请求仍受256 KiB限制。新对话清除当前历史；切换服务器、模型、接口或凭据后不把旧对话传给新配置。历史不自动保存到磁盘。
- **上下文透明**：页面摘要须由用户选择并可编辑；发送成功受理后从输入草稿清除，已发送的摘要保留在对应轮次中。当前轮次草稿不会在请求失败时丢失。
- **状态与恢复**：显示连接成功、生成耗时、输入/输出 tokens；原始 usage JSON 收入折叠详情。认证失败、权限、路径/模型、限流/额度、网络超时提供不同提示。没有后台自动重试；用户可点击重试。取消不清除已完成对话。
- **保留已有内容**：达到输出 token 上限时保留已生成正文并标明“部分回复”，支持继续追问；无结束标志的损坏/中断流仍明确报错。超长正文限制预览，复制仍保留完整回复。
- **输入操作**：Ctrl+Enter 发送，Enter 换行；对话区显示在输入区之前。服务设置未保存或未启用时明确提示，避免分析请求静默使用旧服务器或旧密钥。

回归使用本地模拟服务覆盖两种接口的连续角色、短连接探测、部分输出保留、GUI两轮追问/401失败/再次连接测试、宽窄屏和明暗主题的 Markdown 显示。未使用用户的真实 API Key，云端服务实际调用仍需在用户环境验证。

## 串口专用 AI 窗口（2026-10-25）

串口日志工具栏的“数据分窗”已移除，改为“AI 窗口”。点击后右侧显示可拖动宽度的对话栏；再次点击或关闭只结束 AI 等待与 AI 监控，串口接收继续。右栏设置打开现有全局 AI 配置，无需重复填写服务或密钥，兼容既有 DeepSeek、千问与两类文本接口。对话仅存内存，切换工程清除旧工程对话和自动化授权。

- 数据分析：发送问题或点“分析数据”；默认附带当前数据，可关闭。单次最多100行、每行400 UTF-8字节，选中文本最多16 KiB；显示抽样边界，未保存的文件编辑不纳入采样。Markdown直接呈现，不显示动作JSON或usage原文。
- AI监控：先启动实时接收，再点“开始AI监控”；可选择15/30/60/120/300秒，仅在有新增数据时发请求，最多一个串口AI请求在途。窗口内统计收到的行数和关键词提示，保留最多12条短异常样例；关键词提示不等于测试判定。监控使用有界定时采样，不保证捕捉全部瞬态，不替代原有实时采集、触发和保护。连续三次请求失败暂停监控，失败间隔退避；没有串口连接自动重试。
- 有限自动化：勾选“允许自动化”后，可要求AI启动/停止当前串口接收、开启/停止AI监控。默认关闭；授权对单个请求进行快照，发送时未授权的旧回复不能因事后勾选而获得执行权限。串口原始发送、任意命令、文件修改、仪器输出、产品判定修改均不支持。
- 宿主确认：启动请求与实际连接成功分别显示；15秒未确认或端口失败时明确报错。停止说明后台释放端口。切换工程、日志源、串口选择、波特率、会话或清空数据后，旧请求不得控制新目标。集成测试或串口测试运行中只允许分析；操作执行前再次核对测试锁与当前目标。
- 传输：复用唯一 `AiService` 及并发/超时/凭据规则。独立传输历史最多12条消息，展示最多40条记录，每条最多24 KiB。关闭数据附带时不发送原始行、选区或关键词样例。关闭窗口、换工程或AI配置时取消等待；已发HTTP可能继续消耗服务预算直至完成/超时。

串口动作协议是宿主内部文本契约，不改变插件设备租约、公共MCP或无线测试数据模型：

```json
{"reply":"可读的 Markdown 分析","actions":[{"type":"serial.start"},{"type":"monitor.start","interval_seconds":30}]}
```

仅接受 `serial.start`、`serial.stop`、`monitor.start`、`monitor.stop`；最多一个串口动作和一个监控动作。未知动作、额外参数、冲突动作或超范围间隔拒绝整组执行；普通文本仍可作为分析显示。模型声明与真实执行回执分开，不把模型说“已启动”当作连接成功。当前实现不请求厂商原生工具调用扩展，保持现有接口兼容性。


## 串口智能测试工作台增补（2026-10-25，后续调整）

此节更新同日第一版专用窗口：主入口改为“智能对话”，可对话配置监控目标、关键词及数值预警，启动监控、调用平台并继续分析实际结果。“监控任务”页集中呈现目标、周期、规则与状态。数据范围已于 2026-11-09 扩展为当前日志全范围、指定行范围、选中内容、本地日志库、仅提问，日志经过本地处理后发送有限统计与证据；输入区固定在底部。最近日志与选区不同时隐式发送。

预警由本地规则及时显示证据，云端负责异步分析；常规15–300秒，有异常时优先提交且最短5秒一次。相同规则2秒合并展示，累计次数保留；消息和样例保持有界。后台采样不混入手动追问的传输历史；主对话可展开监控结果。切换数据源会开启新对话并撤销控制权限。

AI可通过白名单平台目录调用设备清单/状态、类型化示波器/直流源/负载控制、测量、截图、源波形采集、单行Qi/AA55解析、进制换算、缓存指标、计算器状态及测试状态。只使用现有已连接会话；设备操作和串口接收启停需要“控制：开”。只读查询及AI监控无需设备控制授权。任意SCPI、任意串口发送、系统命令、擦除/烧录、任意路径仍不开放。

平台动作格式：

```json
{"reply":"先读取实际频率，再与日志关联分析。","actions":[{"type":"platform.call","method":"instrument.command","params":{"device_id":1,"command":{"ScopeMeasure":{"channel":1,"meas_type":"Frequency"}}}}]}
```

一次回复只执行一个平台调用；最多六轮调用，实际工具结果自动交回AI。设备任务通过`instrument.job.get`核对完成记录，accepted不等于已完成。排队前后核对工程/源/会话/授权和测试锁，已下发硬件任务取消或超时不伪装撤回或成功。完整分析、影响范围与限制见[评审记录](reviews/serial-ai-intelligent-workbench-2026-10-25.md)。

云端连续三次失败时只暂停AI分析，本地规则和预警继续；在监控任务页可恢复AI分析。修改服务配置同样暂停云端分析、保留当前本地监控，切换工程或日志源仍结束旧监控。后台监控保持接收唤醒，不依赖云端采样周期才显示本地预警。

`instrument.job.get`使用独立于串口测试通知的完成缓存，最近512项可重复查询。摘要有深度/条数/16KiB内容预算，原测试通知仍获得完整结果；记录过期或未完成时返回`pending_or_unknown`，不能当作成功。

## 2026-11-09：串口 AI 本地全范围文本处理

手动对话默认“当前日志 · 全范围”，不再直接上传最近 100 行。`log.files` 返回当前授权范围内的来源 ID；`log.analyze` 在后台流式处理全部来源，支持关键词、排除词、正则、行号范围、归一化分组、数值统计和阈值计数。AI 按需请求有限证据；“本地预分析”不调用 AI。

范围由用户决定，主机强制约束：当前磁盘日志只扫描当前文件；指定行范围包含首尾且上下文不越界；选中内容在本地分析并使用选区相对行号；日志库可递归扫描用户选择的目录、已打开的磁盘日志，以及当前主串口已落盘记录。AI 不接收目录绝对路径，也不能传入任意文件路径。

实时日志使用共享不可变行快照，保留现有 5,000 行显示上限，不复制完整日志字符串。已淘汰历史通过 `preceding_rows_unavailable` 明示；需要完整历史时，选择日志库中的落盘文件。未保存到磁盘且已淘汰的数据不可恢复。正在增长的文件仅扫描开始时的字节范围，并标记完整性存疑，不将半行当作完整测量。

本地查询单批默认 1 GiB / 15 秒工作预算，可调整为 64–4096 MiB；不足时返回主机签发的 `continuation`，继续只传 `{"cursor":"..."}`，结果累计，不可相加。每个窗口保留最多 4 个查询状态，全局最多 2 个扫描工作线程；每轮对话仍最多 6 次工具调用。一次扫描不等于无限制占用内存或无限制上传。

每份核心报告最多 6,000 UTF-8 字节（外层工具标识略增），列明覆盖范围、编码/超长行问题、分组截断和证据来源行号。支持 UTF-8 文本；无效 UTF-8 或疑似 UTF-16 的输入明确标记不完整，不能据此作出“全量正常”的结论。磁盘扫描不包含编辑器未保存修改。

自动 AI 监控继续使用有界采样与本地预警，保持既有云请求间隔、串口显示行数和设备控制授权流程。全范围扫描是手动分析工具，不应当作硬实时安全联锁。


## 2026-11-10 工程智能任务

默认打开“智能任务”，保留“摘要对话”。详见 [完整设计与能力边界](plans/engineering-agent-20261110.md)。

助手按“读取证据→本地计算→提出调用→宿主执行→核对结果”工作。默认仅本页；跨工具和界面调整由用户开启。设备与测试调用逐次显示参数确认，执行前重新验证工程、来源及测试锁；无任意 shell、SCPI、文件路径、烧录、擦除或串口发送。

支持串口本地日志检索统计与启停、波形区间测量与协议帧检索/解码、数据曲线全范围统计、报告索引与当前报告证据搜索、已配置测试项与测试生命周期、本地工程计算、受限仪表操作及截图。结果标注 E 编号、质量、范围与单位，异步作业等待实际完成。截图当前只供页面显示，文本模型不读取像素。

日志每块最多 1 GiB / 15 秒且支持游标续查；不是只能分析最近100行。实时已淘汰且未落盘的行无法恢复。报告全文检索独立于400,000字节的界面预览限制，按覆盖率与游标报告进度；数据曲线统计固定查询开始时的截止点，后续新增数据明确排除，来源替换则中止。

任务默认8轮（4/8/12可选），工作时限4分钟、单工具90秒，已受理测试通过独立运行UUID在宿主持续跟踪；可取消、复制、导出分析记录。停止等待不撤回已发送设备动作，未知结果不自动重试。来源或工程变化终止旧任务，不在重启后自动重放。串口原有本地告警与监控仍独立运行，AI不承担硬实时保护，也不改写正式产品判定。


## 2026-11-10 AI缺陷整改接口

本轮依据 `docs/reviews/ai-capability-defects-review-2026-11-10.md` 修正。完整边界和验收见 `docs/reviews/ai-remediation-2026-11-10.md`。

通用助手新增 `evidence.get`、`log.files`、`log.analyze`、`serial.monitor.configure/start/stop`、`wave.timing`、`testing.status/propose/apply/select/pause/resume`。工具参数以原生 `engineering_agent::catalog/validate` 为唯一执行契约；这是GUI助手工具，不表示CLI/MCP同步开放全部新的写接口。

日志分析复用串口AI当前数据范围；报告搜索使用工程内报告ID或当前报告全文、本地分片和续扫游标，支持多报告证据，不能直接提供路径。`report.inspect` 显示 report_id 和 source_id 对应关系。`report.search` 不再接受 offset，示例上限8；续扫只传 cursor。

测试启动返回 accepted 和运行UUID，后台完成跟踪独立于AI对话。testing.apply 只把已验证、未过期草案应用到未保存编辑区，要求人工复核保存后重新预检。暂停在测试项之间生效，不能把请求受理视为已经暂停。

证据编号在会话中不复用；最多保存128条本地证据，最多8条进入当前模型上下文，evidence.get 可以读取同工程历史记录，过期或工程不匹配则明确拒绝。取消/超时的在途动作也进入导出。证据页面跳转不恢复被替换的历史文件。

仪表完成只表示设备API调用结束，不代表实际输出达到目标。缺少测量和明确容差时 physical_verified=false。AI不改写正式产品测试判定。
