# R46 串口实时显示与波形预算修正

## 发现的问题

串口日志使用每两秒查询，不能及时反映接收；更严重的是 onScroll 以 scrollTop 减小推断用户翻阅。有限行窗口替换、筛选、字体或尺寸变化也会触发浏览器滚动，因此可能误置 following=false，随后不再刷新。没有现场运行记录，不能把用户本次异常唯一归因于这一事件，但原代码确实存在此路径。

波形的“打开文件”和“添加文件”实际都调用追加逻辑，连续打开不同文件会保留旧文件，累计触发总采样点预算。默认 2048 MiB / 每点预留 48 字节约允许 4473 万点；一个文件能打开不代表多个文件能同时保留。原有错误把采样点和元数据混在一起，且追加先按完整预算解析，再检查合计，可能额外占用内存。

## 修正及实时性与资源平衡

串口日志显示改为事件驱动：宿主在 API 操作、主串口/附加串口接收及后台加载提交后比较日志版本，仅变化时发送 serial.log.changed。版本使用视图身份、内容 epoch、绝对行数、加载状态、错误和选中页，FIFO 长度恒定时仍能识别新数据。没有内容变化不产生日志刷新通知。

Tauri 使用认证的本机长连接订阅事件，通过 IPC Channel 唤醒日志工作区。页面订阅在离开工具或断开服务时释放。订阅按类型过滤，不把逐行 serial.line 或仪表大数据负载重复传给串口界面；原 CLI/MCP 无过滤订阅行为保留。关闭空闲订阅会清理容量，避免反复切页耗尽订阅数。断线显示明确提示并退避重连，重连首次同步当前尾部；不会静默退回日志轮询。检测到旧 Host 缺少此事件会明确要求更新。

宿主原本在窗口隐藏时将数据唤醒延迟 500 ms。现在有实时日志订阅时，仅在有数据到达时，宿主按可见实时视图使用 33 ms 接收唤醒（不因订阅而空闲强制刷新宿主画面）；订阅离开并回收后恢复后台策略。

通知以约 33 ms 的最小启动间隔合并到一个运行任务和一个最新待办，低数据率下首次更新立即开始，高数据率下不为每行执行一次 React 渲染。每次最多读取 500 行，原宿主保留行数和记录设置不变。宿主列表新增总绝对行数，避免 FIFO 满后反复先读错误的尾部再补读。相同页面文本不重复替换行数组。这里是事件驱动的按需读取，不是定时查询日志；连接状态等独立面板仍保留自己的状态检查。

暂停跟随仅由明确向上滚轮、上翻键或操作滚动条触发；字体缩放和程序滚动不暂停。暂停不停止接收和写盘；底部下三角/最新按钮重新同步尾部。数据接收、宿主提交、桥接读取和界面绘制都有调度成本，33 ms 是界面调度间隔，不是硬实时延迟保证。

波形“打开”替换当前库，“添加”保留旧文件；文件目录打开使用替换语义，报告/工程链接仍按原有打开流程。“打开替换”在新数据成功解析后才提交，取消/文件错误/超预算都不清掉当前库；重复追加同路径去重。追加解析前扣除已有/本批已加载点数，只把剩余容量交给解析器。采样点和来源超限分别提示用量与处理办法，不提高默认预算、不截断原始数据。

## 影响与验证边界

更新 GUI 和 WiParse-Host.exe 必须配套，发布目录包含两者。CLI/Service/MCP/插件接口保持兼容，事件目录新增能力，默认事件订阅保持原语义。波形解码算法、测量、导出和报告未改动。保留旧版本，不覆盖用户安装/工程/密钥。

验证结果、桌面模拟流证据和交付身份另见 docs/verification/next-candidate-20261109-r46。新增前端回归覆盖暂停意图、FIFO 尾部、历史页和失效读取；原生覆盖分片事件/非法响应、预算恰好满/超限/重复/替换失败；宿主覆盖主/辅页、清空、空闲不发通知、过滤订阅和关闭回收。真实设备、长时压力、多 DPI 仍需现场验收；不能把有界设计推导成未经测量的 CPU 占用降幅。

## 最终结果与交付

前端 110 项、Tauri 原生 67 项（3 项可选样本测试不在常规套件中）、工作区 578 项（9 项忽略）通过；TypeScript/Vite、GUI、Host、CLI、Service 发布构建通过。本轮重新运行 SCP 实测：30,000,000 点加载及绘图通过，CH2 278 帧/60 个干净数据帧，CH3 无帧，CH4 六帧且无干净数据帧，结果与之前一致。782 份源码身份冻结。

实际窗口使用匹配 R46 的 GUI/Host，在独立 QA 目录运行本机 TCP 模拟器。日志正常推进，向上滚轮后停在 3570 行且内容保持；底部下三角恢复至 8780 行，已有 3780 行移出 FIFO；最大化仍保持跟随；停止后观察到 14690 行、页范围 14191–14690、9690 行移出 FIFO。页面仍限 500 行，宿主仍限 5000 行。该模拟器名义发送 200 行/秒，不将其当作吞吐/延迟基准，也不将停止前后发送数当作无损捕获证明。桌面测试未启用写盘；工作区的最后批次写盘回归已通过。

波形窗口实际检查：先打开双通道 UART 文件，再打开单通道三点文件，库中只保留后者；随后添加 UART 文件，两文件三通道同时存在并显示。超预算、取消/失败保留和去重由原生回归覆盖。没有调整用户配置、默认预算或原始采样。
