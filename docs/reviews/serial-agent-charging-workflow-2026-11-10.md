# 串口 AI 复杂工程任务故障评审与扩展实施方案

日期：2026-11-10。基于原 egui 分支，保留当前未提交的前轮整改。

## 现象与证据边界

用户请求从指定日志时间开始分析一轮充电、计算时长、绘制功率曲线、检查协议并形成报告。界面只出现 log.analyze 活动后显示“模型未提交有效执行请求”。没有本次 HTTP 原始响应，因此不能断定服务不支持工具或 token 已耗尽。代码能够确认宿主与模型协议冲突、有效终结路径过窄、修复反馈不足，以及复杂任务所需时序/图表能力缺口。上一轮模拟通过只覆盖了严格遵循终结工具的模型，不代表真实服务的常见回复形式已兼容。

## 问题分级

|级别|代码问题|影响|
|---|---|---|
|P0|原生 function tools 请求仍包含“只返回 JSON、无外部文字”的旧动作说明|模型可能在普通 content 中返回 JSON 或最终文字，与宿主预期冲突|
|P0|已经调用工具后返回标准最终文字仍被拒绝|真实工作已发生，用户却只得到泛化失败|
|P1|一次协议修复后停止，诊断不区分无动作、参数错误、截断|难以定位真实原因，用户被错误引导去检查模型能力|
|P1|只支持聚合数值，缺少时间序列与同记录功率计算|无法可靠计算指定周期或绘制可追溯曲线|
|P1|不能在对话内展示实际计算曲线|模型可能仅描述“将绘图”或编造图表|
|P1|输出参数最大32768、默认2048，配置与服务限制混为一谈|复杂工具和长报告容易截断，思考模型可用正文更少|

## 实施范围与顺序

先记录本方案，再修改代码、统一验证、生成EXE预览。不会以扩大重试次数替代能力开发。

### 1. 协议与任务闭环

- 原生模式与 JSON 兼容模式使用各自明确契约，不同时要求函数调用和 JSON envelope。
- 原生模型实际执行过工具后，接受标准最终文字；保留结构化终结工具及其证据校验。仅说明未来计划、没有执行过后续工具时继续反馈。
- 对无效协议最多进行三次有界纠正，反馈具体类别，不重放已执行的设备操作。输出截断单独说明，不当成模型不支持工具。
- 失败显示可定位的错误类别和已保留的证据，清理执行中状态。只读分析仍不需要逐次确认。

### 2. 通用时序引擎

- 扩展本地日志 Query，以模型从实际样例推导的时间、数值和周期边界正则取数，不依赖某一份日志或固件格式。
- 支持时间文字 HH:mm:ss.fraction 与数值秒/毫秒/微秒、开始时间/开始标记和结束标记；提供来源和行号、观测起止时刻、时长及边界是否确认。
- 支持数值单位缩放；只有同一条带时间记录同时包含电压、电流，才计算 P=V×I，不跨行盲目配对。没有直接功率或可配对值时明确缺失。
- 使用有界点数及可解释降采样保留时间跨度；计数、峰值与有效样本统计按全扫描计算。时间倒退、缺时间、周期末尾未确认等质量信息不可隐藏。
- 原有扫描分片、取消、范围/来源隔离继续有效。跨文件不连接充电周期。只报告被读取范围内的事实。

### 3. 曲线、协议与报告

- 将实际时序结果直接绘制在串口 AI 对话工作台，配套统计与来源说明；文本报告可复制，不使用任意外部路径或虚构图片链接。
- 模型可在同一任务中结合日志上下文和已有协议解析工具继续检查通信。未提供解码规则、原始帧或成功/失败字段时，只能给出日志层证据，不能声称完成电气协议合规检验。
- 周期时长、功率曲线、协议观察、异常、证据与限制构成最终 Markdown 报告。已有 Markdown 组件显示正文；计算图表来自本地引擎。

### 4. Token 与资源

- 软件输出 token 上限提高至262144，默认提高至8192；旧设置不强行覆盖。具体模型支持上限仍以服务响应为准，不根据软件上限承诺服务能力。
- UI、配置验证保持一致；连接探测继续短输出。输入与响应字节预算独立说明并适度扩大，保留并发、取消与有界日志取证，避免上传所有日志浪费token。
- 不自动提升用户已设置的输出额度，不因错误自动重发付费请求或设备操作。

## 验收

使用本地模拟模型和多种合成日志验证：一次用户请求，原生工具实际取数，返回普通最终文字也可完成；JSON兼容模式仍可执行；指定时间、周期边界、数值单位、同条记录功率、缺失/倒退时间、跨文件及点数上限正确；窄栏曲线无越界；token配置边界一致。然后执行Core/GUI回归及发布构建。

不依赖用户提供私有日志，不使用真实付费密钥、不操作物理硬件；真实模型对私有字段的推断质量仍需实测，不能由合成测试代替。

## 已实施结果

- `protocol.rs` 将原生工具与 JSON 兼容要求分开；`host.rs` 在已取得后续实际工具证据后接受标准最终 Markdown，终结工具仍可使用。修复反馈附完成原因、调用数量及验证类别，最多三次；无效请求不执行设备操作。
- 新增 `log_analysis/timeline.rs` 及 `wiparse_log_timeline`，归一到 `log.analyze.timeline`；支持时间/字段/边界规则、单位缩放、同记录功率计算、跨午夜标注、倒退时间跳过、完整有效样本统计及有界分桶曲线。每次时序提取最多处理4个来源，额外来源行及报告裁剪明确标记；大目录应先选来源ID分批分析。
- 新增对话内真实 egui_plot 图表，可切换数值字段；缺失值不凭空填充，按来源分开。图表标明分桶均值及完整样本统计、缺失/倒退时间和周期边界限制。此版本报告以对话 Markdown 呈现和复制，未新增自动归档到测试报告库或把图表嵌入导出文件的功能。
- 工具完成后移除对应“执行中”条目，避免活动记录仍显示旧状态；标题不再把 Markdown 的 `###` 原样显示。
- 软件输出上限从32768提高至262144，默认从2048提高至8192。旧配置原值保留；输入预算从256 KiB提高至1 MiB，响应体上限从2 MiB提高至16 MiB；单条消息展示上限1 MiB，对话文本总预算8 MiB。字节预算不等同模型 token 上下文窗口，服务实际额度不由客户端决定。
- 核心299项、GUI275项，共574项回归通过，另8项跳过。新增端到端复现指定起点→原生时序工具→实际功率/时长→普通 Markdown 最终回复，不需要第二条用户消息。窄栏220/420像素、双主题真实图表渲染通过并人工检查PNG。
- 不对既有日志行数、保存、接收、设备授权、测试锁和本地预警流程做修改。新日志字段为可选项，不启用时不执行时间序列正则。

## 尚未宣称完成的能力

没有本次真实模型响应，因此本次修复不能证明截图唯一原因；已针对代码中可确认的兼容缺陷及能力缺口修正。未调用付费服务、未做真实仪器/私有日志验收。功率推导需要实际字段和单位；协议质量判断需要相应帧或状态字段。仅有无时间文本、互不对应的电压电流、缺少周期边界时应明确证据不足，不能补造完整曲线或时长。

当前协议检查复用已有 `parse.line`、`parse.metrics`、波形协议帧工具与本地全文检索；不新增未知私有协议解码器，也不把日志关键词次数当成通信错误率。波形/仪器上下文必须核对来源和采集时刻，不能仅因当前另一个工具存在数据就认定属于本轮充电。
