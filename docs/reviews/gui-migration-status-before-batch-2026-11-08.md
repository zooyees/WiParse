过渡桥的单次响应读取上限为 16 MiB，AI 身份信息上限为 64 KiB；超限或连接异常时提示操作结果未知，避免误判为未执行。日志历史查找额外使用每页 1 MiB 的原文预算，保留完整行和准确游标，遇到超过该预算的单行则明确中断；普通页面读取和超长单行仍需后续分块协议及性能验证。

项目和插件切换时，面板按数据目录、项目、插件目录和插件缓存手动编辑的会话参数、额外参数和预检选项；返回或刷新插件时重新读取默认配置并恢复对应编辑，切换后要求重新预检。数据目录上下文变化但尚未重新加载时禁止启动。单元测试覆盖项目、插件、数据目录切换及插件刷新，不涉及项目文件写入。该缓存只存在于进程内；配置持久化、意外退出、不同路径别名及新旧程序端到端隔离仍需完成和验证，不能认为项目隔离已全部完成。

监控工作区在数据目录、项目或活动插件变化时重新创建编辑界面，避免旧编辑框内容留在新上下文；未提交的串口、仪器或规则编辑会暂时阻止切换及预检，用户可以应用或取消，修改完成后重新读取当前状态。前端构建和现有测试通过；切换期间的端到端竞态、后端对数据目录身份的完整绑定仍需验证和完善。

核心库已有资源文件锁，覆盖同资源、COM/VISA 串口别名、跨进程互斥和进程退出释放的自动测试；Windows 普通 COM 的 `SerialSession`、Dongle COM UART、独立服务 UART 采集、按确切资源名称打开的 VISA 会话及使用明确序列号的 FT4222 会话已接入。不同 VISA 别名、Dongle 的 WinUSB 路径、按索引打开的 FT4222 及 USB/VISA 物理别名仍未全部接入；不遵守该锁的第三方程序也不受约束。尚未实机验证，不能据此宣称设备独占已经实现。

设备会话的打开、设备描述、命令分发、测量读取、示波器截图和源波形读取、负载目标值设置及调试输出读取已从旧界面抽取到核心库，旧界面使用同一实现；模拟设备、电源、负载、示波器源波形和 USB 拔插相关测试通过。这只是可复用的会话层，设备线程、操作队列、状态和所有权仍在旧 GUI，尚未迁移到独立服务。调试输出读取尚未进行实机验证。

独立自动化服务的内存租约已将 COM 数字形式和对应 ASRL 名称视为同一资源，并阻止取消中的采集被别名重入；服务的七项单元测试通过。该服务尚未接管旧界面的仪器会话，其租约不等同于完整的跨进程设备所有权。

独立自动化服务目前仍按既有协议将本机访问令牌明文写入数据根目录；GUI 和 Node 客户端依赖该格式。迁移到受当前用户保护的凭据及同步升级全部客户端之前，不能把该通道视为完成安全隔离。

Windows 上曾观察到配置原子重命名偶发 `EPERM`。现对共享占用类错误增加有界重试，保留原文件和事务回滚；注入测试已覆盖短暂和持续失败，但仍需真实环境长时间回归，不能据此认定该问题已彻底消除。

开发阶段用用户提供的 TX 日志验证了本地导入的字节一致性，并通过现有解析器识别到 1388 个接收块、526 个观察事件和 2 个告警恢复候选；也用临时工程运行了日志分析的预检、冻结和证据归档。解析器将产品结论保持为 INCONCLUSIVE；这些离线检查不代表仪器、RX 或完整测试通过。

## 发布前不可省略

以复用现有 Rust 核心和功能为原则，完成各页面的原有功能迁移与必要适配，确认兼容接口的启动、退出、安全和数据一致性，并完成新旧功能和性能基准；实机连接、异常恢复及数据兼容验证后，执行 [五轮检查计划](ACCEPTANCE-PLAN.md)，每轮分别提交报告并关闭问题。最终通过才打包并部署到用户指定目录，备份用户数据并核对实际启动文件哈希。
