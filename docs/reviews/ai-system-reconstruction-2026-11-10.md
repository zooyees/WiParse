# AI 系统能力重构评审与实施规格（2026-11-10）

## 结论
此前调整主要改善了调用循环和展示，但没有解决工具入口分裂、数据理解依赖猜测和任务交付停留在聊天文本的问题。本轮按“用户目标→本地数据发现→平台执行→可核验证据→报告交付”重构；不把提示词变长视为智能提升。

## 已确认缺陷
1. 串口助手与全局助手拥有不同的工具注册与宿主分发，串口入口缺少 PWM/死区、数据统计、报告检索、测试配置等能力。模型知道软件功能不代表入口能执行。
2. 日志只有筛选和模型指定正则；模型常在看到真实字段前猜单位、状态码和时间格式。模板分组不是业务语义，关键词命中不是事件次数。
3. 测试启动只返回 accepted，模型只能反复询问 testing.status；轮次和 token 被轮询消耗，完成进程也不等于产品通过。
4. 曲线与结论主要留在会话，缺少持久化 Markdown、数据、证据文件，难以复核和跨电脑交接。
5. 全局助手默认摘要模式，用户需要先理解两种助手模式，默认入口不能操作软件。

## 实施边界及验收
- 抽出唯一 canonical 宿主分发，串口通过有界进程内代理复用；保留已有串口接收/AI监控命名兼容，避免同名动作语义变化。
- 本地结构发现支持常见 key=value / key:value / JSON 标量，报告真实数值范围、单位和状态值分布、示例行与候选提取正则；不推断私有码意义，字段/状态数量有界且说明省略。
- 新增 testing.wait：宿主轮询匹配 run_id 的任务，模型仅收到最终结果；取消、替换和超时独立报告。
- 新增证据驱动报告生成：主机分配工程内相对目录，输出 Markdown、原始工具证据 JSON、实际曲线 CSV/PNG；无真实数值时不伪造曲线。
- 默认使用可执行 Agent，原摘要入口保留为兼容选项。用户只读分析无需重复确认；设备控制保持已有授权、测试互斥和来源绑定。
- 验证使用真实本地引擎、宿主调度和模拟供应商响应。模拟响应只能证明执行链，不能证明真实模型在所有私有日志上的语义正确率。实际设备与付费供应商不在自动验证范围。

## 影响与兼容性
保留现有 provider/key 配置、串口参数/保留行数、插件契约及原有工程。新增工具均采用不透明 ID 与主机分配路径，不开放 shell/任意路径。新能力通过原 GUI 主线程队列访问 UI 状态，耗时扫描保留后台执行和取消标志。失败状态不触发输出动作自动重试。

## 开源 Agent 取舍
本轮不引入第二个运行时替换已有设备权限层；采用成熟 Agent 的结构化工具、任务状态、证据召回、异步等待模式。直接接入 SDK 不能修复本地工具不可达和数据结构未知，也不能保证减少 token。后续以真实任务成功率、用户补充次数、供应商用量和处理延迟评估模型/SDK，保持统一宿主契约。
## 本轮落地与验证记录

已落地：
- App 的 canonical 分发接收独立执行状态；串口通过有界进程内队列复用全局执行器，接通波形时序/协议、数据统计、报告、计算器以及测试只读/草案/等待能力。跨项目、数据源变化、取消与过期请求检查在宿主执行前重新进行。
- 新增 `log.analyze {discover:true}`，识别常见键值/JSON 标量的数值范围、附着单位、状态分布、首末证据行和候选数值正则。限制最多 64 个跟踪字段、每字段 8 种状态、返回前 8 个字段，明确说明省略。纯 CSV 列头和私有二进制语义仍需进一步解析。
- 新增 `testing.wait`，在宿主按真实 run_id 等待；运行替换、等待超时及进程退出独立处理，明确不把退出码等同产品通过。
- 新增 `report.create/open`：基于保留证据生成工程内 UUID 目录、Markdown、JSON、PNG/CSV；相对链接可随目录迁移，图像在既有报告工具内显示。图片由实际工具点列产生，缺失点不连线；模型结论仍须人工判读。
- 全局 AI 默认进入 Agent 模式；串口保留原有队列与数据范围选择。
- 批量调用只允许读取/纯计算；视图修改和报告写入不混入只读批次。

控制边界：串口入口本次不扩大测试执行授权。测试启动、停止与配置应用仍通过全局 Agent 的明确操作确认。串口可查看配置、生成草案、等待已有测试；仪表/串口原有控制链保留。两种会话的模型循环尚未合并，但工程处理代码已共享，避免复制计算与设备处理实现。

验证：全量 Core 307、GUI 285 项通过，共 592 项，8 项忽略；日志见 `tmp/ai-system-20261110/tests.log`。覆盖新增字段发现、混合单位、状态数量上界及真实报告 PNG/CSV 生成。最终批处理分类调整另行执行串口助手回归。未进行真实供应商付费调用或实际仪器操作，因此尚未测得真实模型任务成功率和 token 节省比例。源码已实现，不以 mock 测试证明模型的业务推理正确。

后续衡量必须使用同一组任务和相同模型，记录：任务完成率、用户澄清次数、工具调用数、上下文用量、首个有效结果耗时、报告证据完整度。当前仍缺少私有协议字典、日期时区推断和持续监控的硬实时保护；不得把这些能力宣传为已完成。
