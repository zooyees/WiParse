# MT5820 无线充电研发测试实施方案

对象：MT5820 TX，MT5788 RX；示波器 Tektronix MDO3014、RIGOL 832 系列电源通过 VISA 连接；RX VOUT 接电子负载，RX 控制通过 WiParse I2C。实际 VISA 地址、负载型号、通道映射、接地与探头、产品额定值及 MT5788 I2C 协议仍需填写。任何限值都由产品负责人在执行前给定，不能从示例日志倒推。

本方案规定动作和判据。当前插件已支持已有日志的历史故障分析；下表中的仪器联动、实时采集和电气判定尚需实现，不能将表格视为已经运行的功能。

## 工位准备

1. 记录输入的 DUT 序列号、板卡版本、TX 固件、RX 型号/固件，绑定示波器、电源、负载及 Dongle 的实际身份；逐台确认设备型号和连接状态。
2. 明确电源通道、电压/限流、输出通道、RX VOUT 负载接法和安全停止顺序；可控供电及负载只使用产品允许的设置。I2C 地址、寄存器地址、字节序、访问权限和有效写入值由 RX 接口规范提供，未提供时不发送寄存器命令。
3. 示波器为每个测试配置采集方案：例如 CH1=VIN、CH2=VBRG、CH3=桥节点或可安全连接的 VGS、CH4=RX VOUT 或事件标记。4 通道不足时分两次，记录是否同一次事件；浮地节点使用适当额定值的差分探头，连接与保护由测试工程师核对。
4. 记录日志源、波特率和接收质量，确认时间来源。先武装采集并确认就绪，后施加刺激；依据实际硬件信号确定复位释放时间，不能将电源控制命令返回时刻当作复位释放。

## 可执行测试项

每项均记录实际工况、配置版本、原始波形、串口日志、仪器身份和测试开始/结束时间。下面的 L、U、T 等表示产品配置中需明确的数值；缺失时该判据不允许显示 PASS。

| 项目 | 具体动作和采集 | 判定与证据 |
|---|---|---|
| 冷启动 | 移除 RX；示波器武装后按工位策略断电、上电；采集 VIN、VBRG、启动标记与 TX 日志 | 供电曲线和启动时间落在产品 L/U、T 内；固件启动证据与物理边沿对应；保存波形和日志 |
| Dongle 复位 | 供电稳定后通过已确认的复位线路触发，捕获复位脚、VIN/VBRG 和日志 | 从实际复位释放到启动标记的时间满足 T；复位类型与产品约束一致 |
| 无 RX 待机 | RX 移离，保持供电，采输入功率、PING/桥节点和日志 | 稳定段输入功率、PING 周期满足对应 L/U；不出现未配置的持续输出 |
| RX 建链 | 放置 MT5788，必要时经已批准 I2C 操作设置 RX；采状态日志、VIN/VBRG、RX VOUT | 指定时间内出现产品定义的建链事件且 RX VOUT 达到目标范围；缺少 RX 接口时标记不可执行 |
| RX 移除 | 在稳定供电时移除 RX，记录日志及输出电气响应 | 产品定义的退出状态和输出停止时间满足 T；不能只依据 `Start CHG` 是否消失 |
| PING 频率 | RX 移离，采集多个完整 PING burst 的桥节点或电流 | 仅计算 burst 内相邻有效上升沿；频率与 burst 间隔分别满足产品范围 |
| 低/额定功率 | 按产品指定负载点设置电子负载，待稳定后采 TX 输入及 RX 输出 | TX/RX 电压电流、状态和持续时间满足各自限值；报告测量点及时间窗 |
| 负载上升/下降 | 用电子负载从设定点 A 切换到 B，再从 B 回 A，分别采集 | 按配置评估 VOUT/VBRG 的过冲、欠冲和恢复时间；动态负载能力不足时不执行自动阶跃 |
| 输入欠压/中断 | 在批准工况下按产品规定降压或短时关断，记录状态与波形 | 欠压触发/恢复阈值、停桥及重启时间满足产品规则；不将软件命令完成当作电气结果 |
| 输入限流 | 逐步施加产品允许的负载，记录电源读回与 TX 状态 | 不越过电源和 DUT 保护边界；限流或降额行为与产品规则匹配 |
| 通信超时 | 使用 MT5788 接口或外部装置制造经确认的通信中断 | 保护码、输出停止和恢复满足产品规则；未提供 I2C 协议前不自动执行 |
| 正常 EPT | 通过已定义 RX 命令或允许的人工操作触发正常结束 | 原因和关闭行为符合产品规则，不将所有 EPT 一律判失败 |
| 温度降额 | 记录传感器来源，使用受控环境或经产品批准的注入 | 实际温度或注入值、降额点、恢复点和滞回满足配置；注入不能冒充物理温度 |
| 桥臂 A/B 死区 | 分别测同桥臂上、下管 VGS；同步采集并进行通道 deskew | 按器件门限配对 H→L、L→H 边沿，分别比较最小死区；带宽/采样/同步不满足则无法判定 |
| FOD 与恢复 | 按产品和安全方案选择测试物或 RX 条件；记录 `FodCnt`、`FO Alert!`、状态与桥节点波形 | 对照指定测试物、触发阈值、停桥时间、锁存/复充策略判定；日志字段单位和原因码须产品确认 |
| 历史故障复现 | 导入提供的 MT5820 日志，分析告警前后事件；之后在受控工况复现并采真实波形 | 比对告警、原因和重新建链顺序；物理是否停桥、允许不允许复充须产品规则与波形共同判定 |

## 真实样例的首个定位案例

提供的终端导出中，接收块 `17:27:47.726` 包含 `FodCnt = 5` 与 `FO Alert!`，随后可观察到复位桥压输出、`EPT_REASON:2000`，接收块 `17:27:58.100` 出现 `Start CHG`。这些是日志文本观察，并非经同步的电气发生时刻；原因码的含义、时间精度及该复充是否符合产品策略尚待确认。

落地顺序：先用现有“分析已有串口日志”定位并保存该候选；随后补齐真实串口字节、示波器预触发和产品限值，按工位连接采集 FO Alert 前后的 VBRG/桥节点；最后取得 MT5788 寄存器接口，增加受控触发和恢复操作。未完成相应接口前，实时自动测试和产品 PASS/FAIL 保持阻断。
