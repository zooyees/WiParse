# AI 平台能力与跨工具数据流评审

## 根因
串口 AI 的文本统计、数据分析页面的曲线、波形分析页面的原始采样各自独立。已有工具名称增加了，但缺少有来源、单位、范围和完整性信息的数据交付契约。模型不能用调用名称弥补数据没有进入目标工具的问题。

## 本轮目标
打通日志结构发现 → 本地时间序列提取 → 数据集 ID → 数据分析实际绘图 → 统计与报告。原始点列不上传模型；禁止模型直接提交一组自造点作为测量数据。

## 能力评审
|领域|已有能力|核心缺口/处理方向|
|---|---|---|
|串口|采集控制、日志筛选、事件/曲线、本地搜索定位|补本地数据集交付；来源变化必须使旧请求失效|
|数据分析|当前曲线统计|补实际导入与页面展示，保留单位/物理时间，不能拿几十个摘要点冒充完整数据|
|波形|原始测量、PWM、死区、协议、视图|仍缺通用计算派生波形和不同采样时钟的同步契约，不能靠模型猜对齐|
|仪表|类型化控制、采集、任务结果|物理闭环需回读和容差，命令成功不等于验证通过|
|集成测试|配置草案、预检、执行、等待|串口入口只读/草案/等待，执行仍走全局明确确认；不能擅自扩大授权|
|测试报告|检索、证据报告与图片|建立来源到报告的引用链，说明缺失/截断与历史性|
|计算器|确定性计算|计算值与实测值必须分清，维度与缺失参数需检查|

## 交付契约
数据集绑定当前串口授权范围和本地查询 ID。保留实际逐条提取值和秒制时间，设置明确内存上限；超过上限时拒绝完整导入并提示缩小范围。扫描不完整时不可默认为完整数据集。目标数据页面有后台载入或实时数据时禁止直接覆盖。模型只能提交查询 ID，目标读取主机数据。图表和模型统计明确区分摘要与原始提取点。

## 后续竞争力指标
以完整任务成功率、人工补充次数、首个有效结果耗时、原始数据驻留内存、工具错误恢复率、供应商实际 token 用量评估；不能用新增工具数或模拟模型响应宣称业务智能达到行业领先。日期/时区、多设备时钟对齐、私有码字典、硬实时保护仍须专项实现验证。

## 落地结果
- 新增 `data.present {query_id}`：串口和全局 Agent 通过共享宿主执行器调用，导入后切换到数据分析页面。
- 时间序列提取新增 `retain_dataset:true`。后台扫描同时保留逐条提取值，返回给模型的仍是有界摘要；不接受模型提交点数组。
- 数据集最多保留 250,000 条记录，超限拒绝导入，不把截断数据冒充完整曲线。每次最多 8 条展示曲线，多文件分别成曲线，不进行未经证明的时钟同步。
- 支持 V/mV、A/mA、C/°C、W/mW、Hz/kHz；页面增加功率和频率类型，电压/电流按原页面 mV/mA 单位转换，横轴改为秒。未知单位拒绝导入，避免偷偷套用电压单位。
- 保存来源、提取规则与质量信息。缺失字段、缺失/倒退时间影响完整性；存在这些问题时使用散点显示，不跨缺失记录画连接线。统计仍基于全部已导入实际点。
- 数据页正在加载或接收实时数据时拒绝覆盖。验证通过后才替换图表；不修改原始日志，不保存或更改设备参数。
- 导入数据不允许套用旧的帧筛选规则重新解析，需重新执行本地提取；旧阈值关闭，避免继承不相关的判定条件。
- 修正任务计划的曲线完成判定：实际 data.present 成功可作为曲线交付证据，失败不能标记完成。

## 验证与边界
全量 Core 307 / GUI 288 项通过，共 595 项，8 项忽略。新增跨工具测试从真实本地 Scan 引擎提取 1,000 条记录；模型摘要最多 8 点，数据页面实际拥有 1,000 点/通道，秒制横轴、mV/mA 转换及同记录 V×A 功率均验证。忙碌实时页面和未知单位失败时保留之前曲线。最后增加的曲线交付判定另执行 workflow 专项回归。

当前完整点列保留在进程内，查询缓存淘汰或关闭软件后需重新提取；未实现数据集持久仓库。超大数据不能无限驻留内存，需选定来源/时间范围。界面最终导入是有界本地转换，尚未做 250,000 条记录的交互延迟基准。模拟/本地测试不证明真实供应商的业务推理准确率。没有发布新 EXE 或调用真实仪器。

## 使用方式
在串口 AI 选好日志范围后，直接提出：“提取 VIN 和 IOUT，计算功率，并在数据分析工具中展示充电过程。”宿主契约指导 AI 先发现真实字段，再提取并呈现；用户无需输入内部查询 ID。没有时间字段或单位依据时，应指出具体缺失信息，不允许虚构时间轴、单位或补齐数据。
