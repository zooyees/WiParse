# FPGA Testing Hub 联合整改实施基线

日期：2026年10月18日。配套 [整改报告](fpga-testing-hub-ui-remediation-2026-10-18.md) 与 [F01 至 F16 综合评估](fpga-firmware-test-2026-10-18/report.md)。本文件是本次整改的架构实施基线，供软件工程和插件开发共同执行；不声称用户逐字段审批过新的 UI 协议。

## 一 已确认的产品边界

单 DUT、单运行，不支持多工位并发。最多500个配置，实际数量按仓库显示。TBT 表示待测试。所有采集时点以复位释放确认后的 T0 为准；支持 DC 电源复位和 Dongle 复位。波形任务为截图，可选读取源波形；任务重叠预检阻断。日志支持普通 COM 和 Dongle UART；测试模式由插件接管串口。DUT 实际身份以用户输入为准。HEX/BIN 下载本版本不实现，接口保留且启用时阻断。限值允许修改后立即使用，报告保存实际限值。AI 支持本地和公网，遵循既定外发授权与脱敏策略。保留异常恢复和证据，不以模拟宣称实机验收。

## 二 文件责任与交接

- 软件工程独占后续 Hub 宿主修改：`workspace.rs`、宿主 UI/API/控制和通用 schema/UI 支持；负责最终组合验收和唯一打包。
- 插件开发独占插件目录、schema 生成源及生成文件、FPGA recipes 与业务测试；不再修改宿主文件。
- `test-tools/lib/hub/`、`runner.mjs` 等共享基础文件由软件工程负责；插件开发如需变更，提交具体需求，由软件工程实现或明确移交单个文件后再改。
- 交接前不覆盖已有宿主改动；双方确认文件清单和未完成项后，软件工程接管。生成 schema 时不顺带覆盖对方文件。
- 架构工位只维护本轮报告和契约，不并行启动 Cargo 或打包。公共验证脚本由软件工程维护；插件专项脚本由插件开发维护。

## 三 字段来源与分层

| 类别 | 权威来源 | 常用界面 | 高级或只读 | 冲突处理 |
|---|---|---|---|---|
| 配置基本信息 | 配置文件 | 名称、启用、超时 | ID、排序、标签、版本；ID仍有受控重命名入口 | 文件名/ID冲突经迁移或事务修复，不静默重写 |
| DUT 适用条件 | 配置文件 | 产品/FPGA型号、板卡适用条件、身份要求 | 条件来源 | 不自动当作本轮实测身份 |
| 本轮实际身份 | 用户本轮输入 | 产品序列号、操作员、必要实际板卡信息 | 治具/环境记录可选；单工位不新增工位调度 | 不被配置默认值静默覆盖；不满足适用条件则预检阻断 |
| 仪器绑定要求 | 配置角色与类型 | 需要的角色、设备类型、选择结果 | 精确资源过滤、厂商/型号等 | 设备匹配不唯一或不可用则预检阻断 |
| COM 参数 | 配置文件 | 端口、波特率 | 数据位、校验、停止位、流控 | 与 Dongle 专用参数分支互斥 |
| Dongle UART 参数 | 配置文件与设备枚举 | Dongle身份、UART通道、波特率 | 其他受支持通信参数 | 物理身份和通道必须精确匹配 |
| 固件 | 文件与配置登记 | 文件、格式、目标 | 实际计算的SHA256、保留的下载参数 | 下载开启阻断；不能用人工哈希替代文件校验 |
| 复位 | 配置文件 | DC/Dongle方式及相关参数 | 固定实现常量仅诊断可见 | 不兼容角色或确认方式阻断 |
| 日志与波形 | 配置文件 | T0相对时点、时长、截图、源波形选项 | 缓冲/预算等技术参数 | 时间重叠、预算不足、引用错误阻断 |
| 判定 | 配置文件 | 类型、条件/指标、上下限、单位、必需性 | ID、证据引用和非默认匹配次数 | 非法规则不保存/预检；运行层也拒绝错误PASS |
| AI | 全局服务配置＋用例启用策略 | 是否辅助、允许证据、服务状态跳转 | 安全策略详情 | 无授权不外发；凭据不进入配置或报告 |
| 结果与来源 | 冻结运行快照 | 当前状态、上次结果标识 | run/attempt、配置/限值哈希和来源 | 旧结果不充当当前内容的结论 |

保留现有配置结构兼容：本轮不要求重做 DUT 数据模型或引入继承系统。现有配置中的身份值暂展示为“配置记录/约束”，实际本轮身份继续走用户输入。若旧执行路径会用配置值覆盖实际输入，由插件明确阻断或修复，并记录迁移。单纯 UI 隐藏不能改变运行值。

## 四 界面契约

1. 默认仅显示当前业务节；九个既有分组可继续使用，“全部”是辅助视图。先实现分组内可读布局，再考虑合并导航。
2. 语义顺序由插件声明，不依赖 JSON 键排序。Hub 负责标签、控件、宽度与响应式；不能按 FPGA plugin ID 写业务分支。
3. 基础通用能力包括字段顺序、标签本地化、短/普通/长字段宽度、常用/高级分层、条件可见、只读/隐藏常量、数组摘要及展开详情。软件工程定义实际 UI Schema 属性并提供一个最小样例，插件随后对齐；不得双方独立发明同名不同义属性。
4. 高级项集中收纳；不存在的可选属性不再逐项生成加号墙。展示默认值不能擅自污染草稿；写入默认值与移除可选值的语义须有契约。
5. 规则按类型编辑，摘要与详情分离；类型显示一次；引用可选择和定位。时间轴预览与任务编辑是不同能力，不能混称已实现。
6. 必需 widget 不支持时给明确诊断；兼容降级要有标识。UI能力协商完整协议可进入R1，但本轮使用的声明必须被真实实现和验收。
7. 暂停仅在当前项归档与清理完成后生效；不冻结 T0 后的采集时钟。未声明暂停能力不提供可用暂停操作。原宿主和新控制栏共享一个状态源，最终只保留一个权威控制区。

## 五 状态契约

配置状态、预检状态、执行状态、历史结果分别维护，避免一个 PASS 标签代表多种含义。

| 维度 | 状态与约束 |
|---|---|
| 编辑 | 未修改、已修改、保存中、保存失败、只读；切换保护和保存冲突可见 |
| 预检 | 未预检、已失效、进行中、通过、阻断；修改相关内容/选择/参数后失效，不能启动 |
| 运行 | 空闲、启动中、运行中、等待暂停、已暂停、恢复中、停止中、已完成、异常待恢复 |
| 单项 | TBT/TESTING/PASS/FAIL；ERROR/ABORTED/SKIPPED/INCONCLUSIVE保留，不强行折算为FAIL或PASS |
| 历史结果 | 显示“上次结果”和所属版本/哈希；与当前内容不同则明确过期，当前内容保持待测试 |

启动要求已保存、预检有效、所选非空且无运行冲突。运行中所选配置与本轮参数固定；暂停保留锁。未确认设备停止不得直接释放租约并启动下项；应进入恢复必需并阻止后续设备访问。所有禁用操作提供原因和下一步。

## 六 发布阻断和关闭证据

F01—F08沿用原报告P1；F09—F16沿用P2，不能把16项统称原报告全部发布阻断。下表规定本轮交付门槛，不以“代码已修改”代替关闭。

| 编号 | 本轮所需证据 | 责任 |
|---|---|---|
| F01 | 空组合、缺pattern、错误次数/引用均不能PASS；保存/预检及运行层回归 | 插件 |
| F02 | 悬挂/迟返回操作的deadline、停止、取消确认；未知状态阻止下项。缺合格适配器阻断硬件模式 | 插件＋宿主适配契约 |
| F03 | 截图后Stop，源波形调用为0，保留已得证据 | 插件 |
| F04 | Dongle通道0/1精确匹配，缺通道阻断 | 插件 |
| F05 | 租约后异常受清理保护；正常可释放恰好一次，未知硬件状态保留租约并有恢复记录 | 插件＋宿主 |
| F06 | 真实runner的失败重试、未完成恢复，新attempt关联旧run，旧证据不覆盖 | 插件＋宿主入口 |
| F07 | 增量归档、内存有界回归、日志批量持久化、规模与停止延迟证据；未完成目标最长老化压力测试不得宣布长期老化已验收 | 插件；集成记录限制 |
| F08 | result/journal/matrix/report写入失败不留下伪正常终态、不提升FAIL，重启可诊断恢复 | 插件＋宿主状态 |
| F09 | 20项文件名/ID一致，Hub无结构错误，可编辑保存预检 | 插件 |
| F10 | 真实页面从空白创建日志/数值/组合规则，无源码编辑、无加号墙和重复类型 | Hub＋插件 |
| F11 | 顶层及嵌套规则的依赖、输入、结论一致；未实现能力不假装可用 | 插件 |
| F12 | AI关闭/未授权/超时/错误/空allowlist/inputs交集覆盖，不能提升结论；required未完成按契约处理 | 插件 |
| F13 | 单位、角色、确认方式校验；无实机精度证据不得声称T0精度达标 | 插件；宿主展示 |
| F14 | Hub快照绑定实际执行内容，入口发现差异有一致处理；全面合并发现可后续，不能错用可变仓库 | Hub＋插件 |
| F15 | 中文报告、递归规则/实际限值/身份/有效证据链接及等待进度可读 | 插件＋Hub |
| F16 | 默认测试入口确实执行插件回归并包含关键异常断言，运行时版本说明准确 | 插件＋集成 |

F01—F08任何确定性判定或资源安全缺陷未关闭，不得以普通硬件测试版本交付。对本轮明确标识的模拟验收包，允许将F07目标最长老化、F13实机计时等外部验证作为未完成项记录，但软件可控的正确性、取消与归档回归仍须通过；硬件能力不合格必须在入口阻断。不能静默降级、默认勾选验收通过或将不执行故障分支当作关闭。

本轮真实20项业务配置验收必须同时覆盖UI任务与真实Hub/runner调用链；模拟运输不修改业务限值以制造PASS。保留失败及边界用例，不能仅用20项全PASS作为充分证据。

## 七 需双方在实现交接中落实的事项

无需新增产品决策即可推进：软件工程先确定可执行UI属性及示例，插件据此提交字段声明；双方列出当前不支持的规则/设备能力并明确阻断；集成验收记录具体目标时长、吞吐、设备适配和实机证据范围，不能编造数值。目标最长老化或硬件精度指标未给定时，继续完成本轮模拟UI验收，将未确定指标记录为后续实机验收输入，不停止无依赖整改。

双方以本基线和整改报告关闭R0，统一冻结后由软件工程一次构建打包。跨工位完成通知按各自工具授权要求执行；本文件本身不提供任何额外通信权限。
