# AI 分页、协议及上下文整改记录

日期：2026-11-10。基线：`cursor/four-job-shell-and-marketplace`，WiParse 1.2.2，egui。依据：`ai-wiparse-fit-and-token-efficiency-2026-11-10.md`。本次沿用当前工程工作区，不切换 GUI 框架。

## 结论

已修复报告分页在宿主结果压缩时跳过正文的问题，以及原生调用与 JSON 兼容模式（含错误恢复分支）混用协议的问题。上下文优化以保留完整证据、参数查询和平台能力为前提；没有通过缩小日志范围、降低监控频率或取消设备控制来减少输入。

本次预览同时包含此前已完成但尚未打包的“测试报告 AI 侧栏”。最终产物、源码快照和构建校验见包内 `preview-manifest.json` 与 `docs/verification/ai-context-20261110/`。

## 1. 正确性整改

| 问题 | 根因 | 本次实现及验证 |
|---|---|---|
| 80 行页面只收到 16 行，下页却从 81 开始 | 通用压缩递归替换数组，保留旧分页游标 | 48 KiB 内按原结构完整传递；超过预算不暴露可跳项游标，返回明确的证据分页指引。205 行连续读取及目录 24 项回归通过 |
| 大结果无法在后续轮次找回 | 先压缩再入缓存，24 KiB 以上只保存摘要 | 原结果先入宿主缓存；单项保留至 1 MiB、会话总量至 8 MiB/48 项。`agent.evidence` 可按 UTF-8 JSON 片段分段读回，校验游标边界。超限、过期明确告知 |
| 超长报告行只保留行首 | 每行截断 4096 字节，无续读行内位置 | 增加 `start_byte` / `next_byte`，保留原始行号；同一长行可以跨页读取，中文长行往返验证通过 |
| 原生模式同时要求 JSON envelope | 共用旧 CONTRACT，再追加原生指令 | 原生模式使用专用执行约定和函数 schema；JSON 模式保留各宿主实际支持的 envelope。新增结构化 `wiparse_report_read` |
| JSON 模式修复提示要求调用原生函数 | 重试提示硬编码 native functions | 重试指令按实际配置选择；JSON 重试仍输出 `platform.call` action，不再要求不存在的原生函数 |
| 自动监控每轮包含手动多阶段任务说明 | 监控与手动任务共用完整 prompt | 独立监控说明；保留原有 JSON 动作、平台方法目录及实时权限，不改变设备授权、规则配置和串口捕获行为 |

报告分页约定：将 `next_line` 作为下一次 `start_line`，将 `next_byte` 作为下一次 `start_byte`；`next_line` 为空表示没有下一页。`line_complete=false` 表示当前行还有后续片段，不表示该行被丢弃。`encoding_lossy=true` 仍明确暴露无效 UTF-8，图片像素仍不由文本模型自动读取。

证据分页约定：`agent.evidence {evidence_id,offset:0}` 获取第一页，继续使用返回的 `next_offset`；`encoding=utf8_json_fragment` 表示片段组合后才是完整 JSON。较小结果仍直接返回原结构。缓存不是永久存储，原始工程文件与已有报告仍是持久依据。

## 2. 上下文与资源优化

- 原生请求不再同时发送完整串口平台文字目录、本地日志文字目录和重复的 JSON 协议说明。函数方法枚举、按需 `agent.help`、`platform.catalog/invoke` 均保留。
- 计算器完整参数说明只在相应页面/跨工具目录或按需帮助中加载。
- 删除历史中与当前请求完全相同的末尾用户消息。只删除精确重复，不删除先前约束或宿主证据消息。
- 原生工具结果由匹配调用 ID 的 tool message 传递，不再另复制一份截断结果到用户历史。
- 固定初始请求前缀保留；后续宿主状态更新不重复用户问题，历史任务证据指向初始上下文或可召回证据。
- 证据索引去掉空字段，增加报告页行范围、实际返回行数和后续位置，避免用日志摘要代替所有领域的来源说明。
- 保留已有本地搜索、统计、事件提取、完整扫描游标、25 万条本地点列、设备 job 等待、取消与来源绑定。未改变串口最大行数、AI 监控间隔或本地告警机制。

### 固定组件测量

以下为同一工具方法范围的 **UTF-8 序列化字节**，不是模型 Token、计费金额或真实任务完成率。比较项为审查报告已列明的固定契约/目录、函数定义、领域说明和通用传输前缀；不包含动态日志、历史、状态、HTTP 包装及少量组装短句。新增原生报告函数和证据 offset schema 的开销已计入。

| 场景 | 整改前列明组件 | 整改后列明组件 | 说明 |
|---|---:|---:|---|
| 串口手动分析，当前日志、设备控制关闭 | 26,965 B | 12,826 B | 保留 49 个可调用方法；新增报告读取函数使 native functions 从 9 变为 10 |
| 报告页独立 Agent，允许应用操作 | 9,935 B | 6,968 B | 保留 13 个方法；新增结构化报告分页函数 |

方法可发现性检查：48 个规范 Agent 方法、102 个不同平台方法均保留。上述减少不等价于真实费用同比下降；按需帮助会在需要时新增一次调用，但避免每轮加载所有不相关参数说明。

## 3. 用量可观测性

每次实际 AI 请求完成后，以 `wiparse_ai_usage` tracing 事件写入既有应用日志（GUI 默认 `logs/wiparse.log`，遵循原日志位置及配置）。记录：

- 可验证为 UUID 的任务 ID、耗时及请求成功/失败。
- purpose、payload、历史、函数定义、工具历史和宿主状态更新的字节数。
- 提供方实际返回的输入、输出、缓存、总 Token 和 usage 完整性。

记录不包含问题正文、原始日志、系统提示、回复、服务器地址、API Key 或工具参数。测试验证敏感样本不会出现在测量输出中。未返回 usage 保持未知，不计算零成本；失败请求也不假定免费。这里的 success 是请求成功，不冒充业务分析完成或产品测试通过。默认日志级别为 info；关闭该目标日志后不会强制另写隐蔽账本。

## 4. 验证记录

1. 全量：核心 315 项通过、2 项既有忽略；GUI 297 项通过、6 项既有忽略。包含日志取证/曲线呈现、串口搜索跳转、权限撤销、取消/来源变化、设备模拟任务、报告图片、Mermaid 和明暗主题布局等既有回归。
2. 补齐协议恢复分支后：串口 AI 模块 48 项通过（含新增原生/JSON 重试一致性用例）。
3. 分页：真实临时报告读取 205 行连续分页；宿主 Session 接收/证据记录连续 205 行；目录数组保留 24 项；中文长行分片重组；大 Unicode 证据分段重组与非法游标拒绝。
4. 初次全量并行测试中，一个既有 TLS 握手取消测试超时；单独复测与最终串行全量均通过。没有放宽取消超时断言或删除测试。
5. 修订了旧测试对“压缩后仍保留跳项游标”“重复把工具结果写入用户历史”的预期，新增断言验证原始证据留存和实际下一轮结果传递。

全部验证使用本地合成数据、模拟服务和测试设备；未调用付费模型、未操作真实仪器，因此不宣称已证明特定模型的分析质量、实际计费节省或硬件验收。

## 5. 保留的边界与后续路线

- 共享 Agent 继续一次一调用，串口 Agent 继续最多四个独立只读调用；各自 prompt 已准确说明实际限制。未在此次正确性修复中改造设备调度并发。
- 平台 `params` 仍需通过目录、帮助和既有宿主校验获取具体参数；本次增加了报告分页的原生 schema，未把 102 个平台 API 重写为新执行框架。
- 模型上下文容量及流式 usage 支持不做未经端点验证的硬编码。保留输出上限与字节保护，不将统一字符换算冒充精确 Token 预算，也不向未知兼容服务器强塞新参数。
- 自动监控保留无新增数据跳过、错误退避和本地规则即时告警；未启用可能漏掉未知异常的“仅变化才上云”默认过滤。领域工作流封装与监控策略扩展需用固定数据回放验证召回与时效后再推进。
- 本次完成优先正确性整改、证据可恢复和低风险上下文优化；真实模型成本/任务成功率基准、所有参数 schema 统一及新的领域工作流属于后续架构路线，不以本次本地测试替代其验收。
