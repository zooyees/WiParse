# WiParse 工程 Agent 候选版开发与验收记录

日期为 2026-11-11。交付基于 WiParse 1.2.2 的 `cursor/four-job-shell-and-marketplace` 工作树。实施前的快照、未提交文件和恢复说明位于 `backups/WiParse-1.2.2-pre-agent-20261111-210929`。该快照包含本机配置，限本机恢复。

## 用户可操作的变化

| 场景 | 操作与结果 | 当前边界 |
|---|---|---|
| 串口或工程助手收到复合任务 | 对已识别的分析交付逐项跟踪，可在当前任务补充或修正目标，查看哪些目标仍待证据。 | 宿主目前显式识别充电时长、绘图、协议检查和报告文件。模型可通过计划工具声明其他目标；自然语言解析仍需真实任务检验。 |
| 继续工程调查 | 在任务记录中选择历史任务，载入目标、未决项和近次证据定位信息，再提交继续调查。 | SQLite 保存项目内索引；原始采集文件移走后仍需重新定位。重新打开任务得到可编辑草稿。 |
| 发现实时串口告警 | 监控页可展开首个告警，查看同一任务中触发前最近八行与命中行。跨接收批次保留前文，模型暂停时本地规则仍可触发。 | 冻结的是送达宿主的文本。上游丢样、示波器采样时刻和 Dongle 时钟需分别测量。 |
| 生成数据分析报告 | 使用 data.extract 保留数据集，再展示和生成报告。结果内含解码后文本摘要，Markdown 中可打开逐点来源索引。 | 原文行号从 1 开始；帧头分割使用解码后 UTF-8 字节偏移。超过 250,000 个输入记录时，概览保留分段边界、极值和缺值样本，完整可绘制记录写入临时表，生成报告时导出 full-records.csv。 |
| 测互补驱动死区 | 波形测量区分两个换向方向、双路同时导通和同一桥臂关断后重开。有效区间才进入死区统计。 | 物理探头校时仍由工位核实，软件不自动认证。 |
| 调查无线充电回放 | 在 Markdown 报告中直接看待调查项、观测值和下一项测量。详细 JSON 附原始观测指针、窗口和校验值。 | 回放使用模拟输入与示例限值，产品判定维持 INCONCLUSIVE。 |
| 导入工位记录 | 插件新增只读 recorded 模式。按测试目录内的 ID 读取工位、固件、时钟域、检查项和原始片段；分别记录缺失与待复核。 | 该入口需要结构化记录。不会向真实设备发命令。工位输入声明和摘要不能单独证明设备校准。 |
| 比较批次与成本 | 插件可对比两个已存档批次的有效同窗测值。开发脚本可重跑 12 个软件种子，核算每次正确交付 Token，并按同组盲评结果计算正确率区间。 | 未录入工位盲评结果时不能推算正确率或 Token 节省比例。 |

## 前一中间版本的验证记录

- Windows 核心库 319 项、GUI 309 项、设备服务 6 项通过。常规运行另有 8 项标记 ignored。凭据测试在当前 Windows 用户的加密上下文完成。
- 插件套件共 286 项通过。其中无线充电 21 项，覆盖原文缺失、模拟与录制模式隔离、报告链接、批次比较、校验错误、超时和取消。全套验证发现示波器串口插件测试还写死历史版本 0.6.2，已改为校验随附说明与实际 manifest 的版本一致。
- 测试 Hub 与实际 HTTP 设备服务进程完成 4 组回放，每组 37 项。正常结果 PASS，异常结果 FAIL，缺测和质量问题各为 INCONCLUSIVE。四组的产品批准均为 false。
- 12 个可重跑的软件种子全部通过。另单跑 4 通道、每通道 100 万点波形传递测试，本机一次观测的 UI 交接时间为 0.746 ms，共享采样缓冲。这个数字只覆盖内存交接。
- CLI 新增本地 wave measure。实读仓库内两份示波器原文件，Tektronix ISF 的 CH1 共 100,000 点，Rigol WFM 的 CH3 共 30,128 点，两份均有 0 个无效样本。把同一通道同时选作互补对时返回 WAVE.SECOND_CHANNEL_MISSING_OR_IDENTICAL。
- 逐任务成本脚本以两项模拟评分检查失败成本计入分子、缺失 usage 时结果为空、不同样本组拒绝匹配。此处不含线上模型成绩。

## 本轮开发完成度核对

| 路线图 | 核对的实际调用链 | 验收边界 |
|---|---|---|
| 基线与公平对标 | freeze-engineering-benchmark 冻结任务、来源摘要与量规，run-engineering-benchmark 记录各组退出、耗时和用量，review-engineering-benchmark 隐去运行组信息并复核附件摘要，compare-engineering-agent 汇总相同案例 | 向评审者单独分发 review 目录。提交物正文若自报模型名称仍可能破盲，需记录。缺少独立受试者、实采隐藏集、线上模型成绩。 |
| 任务执行 | 串口与共享入口复用 Workflow 登记目标、核验产物和纠正目标。待处理队列绑定来源和权限。任务启动、设备命令分发、接受、完成及恢复分别写入工程记录 | 恢复时重新验证文件与设备会话。未确认操作记录沿任务恢复链传递，操作员的读回只对相应操作和恢复分支生效。 |
| 全量数据到报告 | data.extract 本地扫描、历史分页、完整 CSV、原文索引共用同一记录位置。报告支持源文件重选及摘要核验。波形报告保存通道解码采样 SHA-256 和从零开始的采样索引，协议帧按解码时窗关联信号通道。报告链接可直接激活相应工具 | 曲线概览与原始样本区分。波形回源需要原始文件或已打开的同一通道。协议索引指向主信号通道，多线总线还应核对解码配置。 |
| 设备执行与捕获 | 设备任务凭据包括设备 ID、作业号和宿主会话。串口监控插件记录命中行、前后文、采集缺口、命令提交和返回，停止与启动通过串口状态读回。服务 capture.correlate_window 对不同来源做同步锚点拟合、时窗分类和质量检查 | 示波器驱动回执与物理停机验证分开。Dongle 厂商传输由正式 ICD 决定，规范化事件入口可用于已捕获数据。 |
| 诊断配方 | 无线充电插件输出传输区间、EPT、输入与 Qi 通信分母、VIN/VBRG、PWM、双向死区、适配器矩阵与批次差异。同步缺口、缺少校时和限值分别处理 | 线上检测来自本地触发器。适配器与工位配置、探头校时、保护和产品限值需实际确认。当前 station.json 为 UNCOMMISSIONED，正式 live 工位入口仍受未集成的设备后端限制。 |
| 现场放行 | 可复现软件回归、盲评包、版本备份和 EXE 预览属于软件交付。获得设备后以同一批采集执行故障注入、双模型、人工参考和长稳试验 | 60 个独立实采任务、物理保护响应、72 小时稳定性及工业批准尚未取得。 |

本轮改动后的验证结果单列；上方中间版本数据仅作历史基线。操作说明见 [AI 接口](../AI_INTERFACE.md)。
