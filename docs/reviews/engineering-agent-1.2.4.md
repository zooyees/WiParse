# WiParse 1.2.4 工程 Agent 候选版评审

基线为 1.2.3（8cb1a65）。本次参照《工程契合度评审》《Agent 智能评审》、硬件数据 Agent 路线图与当前执行代码，比较任务执行、完成判断、证据读取及实测条件。

| 维度 | 1.2.3 表现和缺口 | 1.2.4 调整及剩余问题 |
|---|---|---|
| 工具编排 | 串口可处理独立只读批次，共享助手拒绝任何多调用响应。读取通道概况、报告索引常需两次模型往返。 | 共享助手对同轮 2–4 个独立读取先做整批范围和参数检查，再通过宿主逐个执行，按调用 ID 回传结果。写操作、计划变更、依赖上一结果的任务单独提交。节省的是工具之间的模型往返，设备操作时延仍由驱动决定。 |
| 目标与完成判据 | 时间线有点列即可满足绘图目标。工程师明确要求在数据分析页展示时，可能收到摘要而页面未打开。 | 增加页面展示交付类型，只有 data.present 返回成功并含实际记录数才完成。串口与共享助手共用判据，补充通用画图请求仍可采用回复中的曲线。自然语言同义词和省略语仍可能漏识别。 |
| 停滞恢复 | 共享助手反复提交未完成答案可能耗尽模型预算。 | 连续两次出现同一未交付清单且没有新增证据时，若尚未取证，宿主可按当前页读取一次；继续无进展时返回缺项并保留历史结果。只读权限关闭时，宿主不会自行扩大范围。 |
| 证据成本 | 每次追加证据都重新序列化整个账本计算容量。翻页时也反复重建整条 JSON。 | 增量记录字节数，引用共享不可变证据，首次分段读取时缓存编码。内存上界需同时计入留存详情及已构建的页缓存。模型使用量和成功交付率仍需同任务、同模型实测。 |
| 领域与现场能力 | 示波器采样、日志、报告和设备回执可以定位。环境缺少已验收工位、独立盲测样本及双模型测试凭据。 | 现场项目继续单列。真实物理根因、额外驱动、多模态图像解释、长期漂移和现场保护仍需独立开发或验证。 |
| 可恢复性 | 任务重开可载入已验证报告。挥发性设备读回与数据来源须重新核对。 | 保持 1.2.3 的恢复语义。未知设备写动作不得由批量路径重发。恢复后的多数分析中间结果仍需重算，这是长任务与成熟专业 Agent 的实质差距。 |

上述对比针对本仓库标记的能力和历史评审。没有与商业 Agent 的同期、同条件真实对比数据，不据此给出排名或 Token 节省百分比。

## 集中验证

核心库 322 项、GUI 315 项、设备服务 6 项、插件 286 项通过。8 项按测试声明忽略。模拟模型经本机 HTTP 发出两个独立读取，下一次模型请求同时含原 ID 匹配的两个工具结果，包括失败结果的配对亦有单测。混入设备变更、跨页未授权或重复读取时整批拒绝。百万行异常、报告回源、工程任务恢复等既有回归继续通过。MCP 通过本机模拟后端的 4 项报告与 20 项 Hub 分派检查。未使用真实客户日志、客户 API 密钥或现场仪器来生成这些数据。
