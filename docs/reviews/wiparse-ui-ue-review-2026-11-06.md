# WiParse 界面与交互检查记录

## 范围和依据

基于当前 `wiparse-gui` 主路径的源码、主题组件、已有界面评估、用户提供的 Testing Hub 截图，以及七个主页面的无窗口渲染预览检查。预览覆盖默认空态，几何测试覆盖中英文、亮暗主题和多种缩放；当前 Windows 窗口捕获未能可靠展示目标程序，真实数据、动态操作及设备状态仍需在应用内逐页验收。

## 共性问题

| 范围 | 发现 | 影响及处理 |
| --- | --- | --- |
| 顶部导航 | 窄窗口采用隐藏滚动条的横向导航，程序切换页面时选中项可能在可视区之外 | 本次在活动页面发生变化时滚动显示选中项；隐藏导航的可发现性仍需实机评估。 |
| 底部状态 | 多页面仍从状态文案推测颜色；“未连接 / disconnected”会命中已连接，“扫描完成”可能被标为忙碌 | 修正这些明确的误判，长状态截断并可悬停查看；彻底改为业务层明确状态仍需后续各页面协作。 |
| 统一视觉 | 全局已有 4/8/12/16 间距、28 像素控件高度和 200 像素侧栏基准，但页面仍存在局部手写尺寸与嵌套滚动 | 本次统一数据分析“应用”按钮高度；后续需要逐页检查密度、对齐和缩放，避免简单机械放大所有控件。 |
| 窄窗口 | 共享侧栏根据可用宽度压缩，仍需检查内容是否被截断或出现嵌套滚动 | 已有共享侧栏几何测试；不能替代真实内容及多 DPI 的视觉检查。 |
| 信息层级 | 插件表单由通用配置结构生成，用户截图显示英文键、逐字段展开与过长纵向表单 | 根因涉及插件领域表单及 Testing Hub 渲染能力；不宜仅靠统一边框或颜色解决，须按测试任务组织配置，保留校验和结果追溯。 |

## 主要页面

- 串口与波形：无窗口预览中，波形页的协议栏在 1100 像素宽窗口占用 360 像素，压缩图和工具条。本次按窗口宽度分配协议栏，给波形区域更多空间；长行、多个通道和实际交互仍需核验。
- 仪器：现有单台工作台已建立属性对齐；总览、连接状态和失败信息仍应以真实设备状态为准。电源与负载操作不能因视觉改动变成失焦即下发。
- 数据分析：实时数据已到达时仍显示等待提示，本次按帧数切换提示。预览中目录区大量留白，而规则区固定 220 像素；本次改为按窗口高度分配，实时源进一步压缩信息区，为规则编辑留出空间。
- 测试报告：目录层级和长名称在小侧栏仍需核对；保持打开、定位附件及历史记录的既有操作。
- 测试工具和无线插件：需用已配置真实测试项检查空态、配置、运行、错误和报告。当前阶段版的无线功能及开发中的恒流测试均未完成实物验收，不能以界面整齐替代功能验证。
- 计算器：较矮窗口已有单列策略，正常高度仍有卡片内部滚动；需用真实最小窗口和不同语言核验。

## 本次验证和边界

源码修改集中在导航可见性、状态呈现和数据分析提示，不改变仪器设定或测试判定。测试与实际打包部署结果以交付记录为准。完整的逐页屏幕审查和更大范围布局优化尚未完成，不应将本次改动表述为全软件视觉整改完成。

## 二次调整：回应用户对视觉变化不足的反馈

第一次改动以状态与边界问题为主，视觉变化有限。此次进一步调整全局深色背景、面板和输入框的层次，在主导航加入清晰的品牌区；测试工具的非配置型插件增加配置区比例，将空输出提示居中、弱化内部路径信息；插件列表使用更清晰的选中提示。配置工作区标题改为左对齐，矩阵用整行显示当前详情对应的测试项，并将内部锁定代码改为可读提示。

在离线预览中检查了常规测试工具页面及 500 项矩阵。七个主页面的多语言、主题、缩放几何测试与 500 项测试均通过；这些是演示或模拟数据，不等于真实仪器及用户配置的完整界面验收。无线插件的未完成功能没有因本次界面调整而被标记为完成。

另外使用 20 项 FPGA 示例与当前插件的实际配置结构做离线渲染；针对缺少分支标题的配置，界面优先使用配置元数据中的类型名称，避免显示没有含义的“选项”。示例测试结果来自模拟运行，不代表真实设备通过。

## 面板间距调整

根据用户标注的串口界面，窗口内容外边距由 8 调整为 4 像素，串口侧栏和主区之间由 16 调整为 6 像素，串口主区内边距由 12 调整为 6 像素，侧栏卡片内边距与卡片间距也相应收紧。仪器、数据分析、波形、测试报告及 Testing Hub 的主要面板间距统一为 6 像素。侧栏默认及最小宽度仍为 200 像素，控件高度维持 28 像素。
