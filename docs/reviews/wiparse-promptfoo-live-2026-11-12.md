# WiParse 串口 Agent 真实模型评测与修复

评测使用 WiParse 1.2.5 的串口助手入口。每个场景打开同一份 10 行合成日志，在隔离工程中使用真实模型服务、任务管理器、本地扫描引擎和证据系统。多轮场景在同一会话中运行。没有读取工程师的现场日志，也没有向设备发送命令。Promptfoo 作为开发工具读取固定轨迹，评分时不再请求模型。

## 缺陷与修改

| 实际失败 | 影响 | 修改 |
| --- | --- | --- |
| 用户要求“不要读日志、调用工具或画图”，规则解析把顿号当作新指令的开始 | 主机虚构了画图交付，对正确的换算答案发起四轮重试 | 保留并列否定的作用域。对明确禁止工具的独立概念解释，发送单条文本请求 |
| 模型先说要扫描，在回复正文中附上 working 工具 JSON | 主机接受了文字承诺，下一轮没有证据可用 | 识别带前言的待执行工具信封，反馈协议错误。工具请求须经原有宿主入口校验和执行 |
| 扫描覆盖全部行，但返回的首尾样例只覆盖部分匹配行 | 模型漏掉中间一次状态转换，并给出了错误的精确次数 | 在回执中说明样例行的覆盖范围。对明确要求统计状态转换的任务，引导使用本地事件计数和相邻观测，检查精确计数的取证过程 |
| 显式要求建计划，模型仍可能只口头分解 | 最终答复无法核验两个交付分别完成与否 | 在原生调用路径优先提供建计划工具，结束时检查实际计划，并保留已有权限校验 |
| 串口标签页 ID 与日志文件 ID 混淆；计划拿正确的单源扫描结果也可能被主机拒绝 | 多次重写计划，无法引用已完成工作的回执 | 区分串口标签 ID 与本地日志 ID。仅完整扫描单一来源时，才将其实际日志 ID 绑定到汇总证据 |
| 宿主已精确数出两次切换，却只承认计算器能交付“计算”结果 | 计划的计数步骤被反复拒绝 | 对完整且无规则歧义的本地状态计数回执，允许作为计算证据。普通样例行、部分扫描、仅有文件清单的回执均不满足此条件 |
| 续问携带旧任务描述，但有效扫描详情可能只剩摘要 | 模型重复提议扫描或无法回答“第二次” | 传入最新续问及最近的非管理回执，保留任务 ID 和证据编号 |

## 评测口径

- **任务理解**要求给出 2500 mV 的换算结果，明确禁用日志与工具。检查答案和宿主实调次数。
- **任务拆解**要求建立两项计划、统计状态由 1 到 0 的次数，并列出相邻原因码。真值为两次，分别与 UV、THERMAL 相邻。重复的 0 不构成新事件；相邻原因码不能直接证明物理根因。检查宿主扫描覆盖率、计划状态和证据引用。
- **多轮续问**在上述统计之后只询问第二次的原因码，明确禁止重扫。检查是否沿用同一任务、保留证据、给出 THERMAL，以及是否重复调用扫描工具。
- 每个场景每个版本只采一个真实会话。Token 是服务端报告的输入加输出，包括命中缓存的输入；不等于真实账单。时延包含远端生成和本地处理，不据此推断 P95。

缺少千问凭据，千问三项均记录为未运行。以下数据只能描述 DeepSeek 在本次 WiParse 宿主与样例中的表现。

## 真实结果

| 场景 | 旧版 → 候选核心判定 | 模型请求 | 总 Token | 会话用时 |
| --- | --- | ---: | ---: | ---: |
| 单位换算，禁用工具 | 失败 → 通过，2500 mV = 2.5 V，未调工具 | 4 → 1 | 22,273 → 282 | 3.92 → 0.70 秒 |
| 建计划、去重、关联原因码 | 失败 → 通过，两步完成，均有扫描证据 | 4 → 7 | 28,538 → 59,151 | 8.21 → 18.70 秒 |
| 原任务两轮续问 | 失败 → 通过，第二轮答 THERMAL，新增扫描 0 次 | 5 → 4 | 26,338 → 32,029 | 7.59 → 10.83 秒 |

Promptfoo 核心断言由 0/3 变为 3/3，两组评分引擎错误均为 0。三项合计 Token 从 77,149 增至 91,462。解释题少用了 21,991 Token；两项日志任务在候选中完成了旧版漏做的取证。不能据此宣称整体更省 Token。复杂任务的完整扫描、结果回传和计划更新是后续压缩上下文时应分别计量的部分。

现场问题仍需关注答复长度。拆解题要求“一句话”，候选用一句话给出了结论，也附上了明细；最后一个续问只要代号，候选给出 THERMAL 后又补了一句依据。上表“通过”衡量事实、实际执行和证据连续性，未将这两处格式偏差计为严格格式通过。三个样例已参与故障定位，适合作为回归哨点，不能当作独立盲评或供应商排行榜。

### 复核

评分汇总以服务端回传的累计用量计算，每次多轮会话只取最后一轮的累计值。原始回答、唯一任务 ID、每轮宿主调用、计划和覆盖证据可在两个轨迹目录中核对。构建包无须安装 Promptfoo，评测人员可使用仓库内的运行入口离线重新评分。[评分与资源用量](../verification/promptfoo-agent-20261112/scores.json) · [基线轨迹](../verification/promptfoo-agent-20261112/initial) · [候选轨迹](../verification/promptfoo-agent-20261112/shipping) · [运行说明](../../tools/agent-eval/README.md)

### 回归与发布范围

Windows 工作区回归 692 项通过，9 项按配置跳过，0 项失败。包含 DeepSeek、千问请求契约的本地用例；在线模型只测了 DeepSeek。实测覆盖串口助手的离线日志分析，没有操作真实串口、仪表或测试台。发布目标为 Windows x64 的 EXE 预览目录，包含 GUI、CLI、服务、MCP、插件、运行时及调试符号。
