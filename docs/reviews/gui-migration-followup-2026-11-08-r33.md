# GUI 迁移持续检查 R33（2026-11-08）

## 发现的问题

报告页面在工作区保留后，原先只按“已连接/当前可见”触发索引刷新，没有绑定主窗口当前工程。旧工程读取完成较晚时可能覆盖新列表；待移出确认只保存测试项，确认时却读取最新 indexed.project，可能把旧确认应用到另一工程的同名测试项。原生端已有当前工程检查，但此处前端使用新工程作为参数，不能靠该检查识别用户最初确认的工程。该风险来自代码审查，未通过实际移出数据制造破坏性复现。

## 最终修正

- 主窗口向报告工作区传递当前工程 ID，显示的索引必须匹配该工程。
- 目录读取以请求序号和可见性/连接/工程上下文隔离；迟到成功、错误和 loading 收尾均不能覆盖新状态。A→B→A 也视为新的上下文。
- 待移出确认同时保存原工程和原测试项，展示和提交均校验当前工程、索引工程与原确认工程。提交使用原确认参数。
- 隐藏、断开或切换工程时关闭添加/移出浮层、清除旧索引及临时提示；已打开报告的阅读会话继续保留。
- 添加/移出完成后只更新原上下文，迟到反馈不会在另一个工程展示；操作不会自动重试。

修改仅涉及前端 7 份源码/测试文件，增加 2 个文件。没有变更 Rust 核心、解析器、设备执行、插件或 MCP，也没有调整报告生成格式和本地证据解析规则。
