# WiParse GUI 全功能迁移完成度核对

日期：2026-11-08。核对对象：R23 工作区源码。旧版基线是当前工程仍保留的 egui 可见界面及其执行实现；新版是 React/Tauri 工作台。历史截图、规格要求和“后端存在命令”不单独算作已迁移。交付测试包 R20 与修正版预览 R23 需区分，本报告不对 R20 追认 R23 的修正。

## 结论

**所有功能尚未迁移完毕。主要工作台和主要业务链已接入，但仍有实际功能缺失、行为不等价和未完成验收。当前不能作为无功能退化的旧版完整替代。**

此前“主要模块已实现”的进展描述只能理解为主流程覆盖；不能据此推导“旧版全部功能已迁移”。本次细项核对发现的批量测试操作、探针烧录/擦除、WIDA、协议多通道及 HTML 分析等，属于真实差距，不能都归入“仅缺实机验证”。特别需要纠正：**调试探针固件烧录/校验/擦除在旧版已有执行实现；FPGA 测试插件尚未实现的 HEX/BIN 下载是另一个功能。**

本次覆盖全部七个工具、设置及运行/发布基础设施。下表按用户操作拆分，不用菜单数量、测试数量或随意百分比表示完成度。同一功能有多个状态维度，不能将“代码已接入”当作“现场验收通过”。本次为代码与已有证据评估，没有运行用户的 R20 窗口、实物设备或外部模型，没有修改运行源码或重新打包。

本次 **119 项**：M 已接入 **85**、P 部分 **10**、G 缺失 **19**、C 路径改变 **3**、O 旧版未实现 **2**。条目粒度并非等权，不计算总完成百分比。当前 **738 个运行源码/测试文件**的集合与 SHA256 均匹配 R23 冻结记录，差异列表为空。见 [逐项机器清单](../verification/migration-completeness-20261108/feature-inventory.json) 与 [源码身份](../verification/migration-completeness-20261108/source-identity.json)。

## 判定方法

- **M 已接入**：找到新版可见入口与执行路径；这只表示静态功能链存在。
- **P 部分**：有对应能力，但操作、范围、状态或输出与旧版不完全等价。
- **G 缺失**：旧版有界面及实现，新版没有等价可用路径。
- **C 改变**：界面/路径被有意替换，不直接算功能消失，但需按实际流程确认。
- **O 不计迁移缺口**：旧版本身未实现的预留目标，不纳入本次完成率。

验证栏：**A** 为 R23 或来源清楚的自动证据，**L** 为历史候选的有限桌面观察，**S** 为本次静态核对，**V** 为专项/真实使用待验。A/L 不代表该行所有细节已穷尽验证；实物/真实 AI/完整 DPI/长时均无本轮通过记录。证据编号见文末。

要求：按工具建立工作区状态模型，区分会话内状态和用户配置；数据规则读取并兼容写回原配置。测试“数据→报告→数据”“波形→报告→波形”“计算卡片→其他卡片→返回”“助手→其他页面→返回”。不能用保持全部后台轮询常开来换取不卸载；设备对象仍只有原执行者。
