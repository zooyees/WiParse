# AI 统一平台接口接入记录

日期：2026-11-10。

## 问题与调整

原先串口 AI、全局 Agent、GUI API 分别维护能力列表，导致平台已有功能无法被 AI 发现，或不同入口走不同实现。本次将现有 API 能力目录移到 core，GUI API 继续使用同一份目录。

新增 `platform.catalog {filter,offset,limit}` 与 `platform.invoke {method,params}`。当前目录有 115 条示例、102 个不同方法，覆盖 serial/log、instrument/scope、wave/protocol、项目/插件测试、报告、计算、界面和设备服务。AI 可分页查询后调用已登记接口；仍保留专用高层工具供常见任务低成本使用。

统一调用通过现有 GUI/API 实现，不复制设备驱动。嵌套 method 决定真实权限与目标页面，不能伪装成只读。未知方法被拒绝，不开放任意 shell。串口 AI 的设备/测试操作仍需控制授权和具体参数确认；只读分析不增加确认。

设备 job 继续等待既有结果接口；其他异步 API 的“已接受”不表示加载完成或物理验证成功。超时结果未知时不自动重放输出改变命令。暂停/停止测试拥有明确的锁例外，不开放其他占用设备的操作。

补上了已声明但未实现的 `convert.expr`，复用现有计算器求值器。平台返回结构中的常见凭证键被递归遮盖。AI 主动切换串口来源后衔接新绑定，保留任务并要求重新读取新来源；用户自行切换仍按既有规则取消旧请求。

## 不能混淆的覆盖范围

102 个**已发布 API 方法可被发现与转发**，不等于每个 GUI 控件都已拥有专用自动化接口，也不等于全部真实硬件均已验证。依赖 WiParse-Service 的方法需要相应服务运行；设备方法需要真实目标与设备能力支持。目录里的 params 是示例，不是完整 JSON Schema，更不是可直接套用的默认设备参数。

因此不能据此宣称“所有 GUI 功能已完成 AI 化”。仍需要逐页补齐未发布的细粒度操作、完整参数 schema，以及真实设备场景验收。串口日志提取至数据分析页面已有 `log.analyze(retain_dataset:true) → data.present(query_id)` 专用路径，避免把大量采样点送给模型后再传回。

## 验证范围

自动测试验证目录中每个已登记方法都可以构造调用、获得由嵌套方法派生的权限与页面；未知/伪造权限被拒绝；目录分页与敏感配置遮盖正常。该验证是路由与权限验证，不会对 102 个方法逐个执行真实硬件或文件写操作。
