## 当前架构与原版本的关系

```text
React 工作台
  ├─ Tauri 命令 → 共享核心：离线波形、数据、报告、文件处理
  └─ 受保护 companion 桥 → egui 兼容宿主
                              ├─ 原串口/设备队列
                              ├─ 原测试/插件执行器
                              └─ 原 AI 会话、授权、监控引擎
CLI / MCP ────────────────────┘
```

相对旧 egui 单体，新界面的布局、Markdown、主题、导航和组件复用更容易统一；离线处理不必经过旧绘图循环，原始波形共享及精确视口索引减少重复扫描。沿用成熟解析器、驱动和插件判定，避免迁移时制造两套控制逻辑。桥接已有身份/协议/实例校验和受保护凭据；未知结果不自动重放，宿主退出保护保留活动任务及未保存状态。

代价是 WebView、Tauri 与宿主同时存在，内存、IPC、配置和版本匹配复杂度高于单进程；设备执行仍受宿主调度影响。`App.tsx` 约 141 KB、原生命令入口约 100 KB，部分类型/错误处理和页面编排仍集中。现在不适合直接删除宿主或把所有仪器状态复制到 React。后续应按业务域提取命令类型、错误映射和状态转换，再考虑独立执行服务；不得同时保留两条设备命令执行路径。

本批 Vite 构建仍有单块超过 500 kB 的提示：最大压缩后脚本 523.58 kB（gzip 171.71 kB），报告/AI/文档编辑已有独立块。后续应测量冷启动和页面首次打开，再按业务域继续分割；不能仅提高警告阈值就当成优化完成，也不能把文件体积直接推断成界面卡顿原因。Rust 发布构建还有原有未使用项等警告，本轮未以无关清理扩大冻结批次。

## 本次问题、修正与影响

### 1. 实时解析规则切换混入旧数据（P1，已修）

原生实时解析修改帧头/筛选词时重建列，但保留了旧规则未完成的尾帧；新规则可能把旧内容重新解释，形成错误数值或空帧。前端又一直读取可变规则，异步返回有机会覆盖新规则状态。

现把规范化帧头、筛选词及串口来源作为实时解析代际；变更时清除结果、尾帧、统计/缺口状态，重新读取最近保留日志。每轮请求固定规则，迟到回复必须匹配当前代际。无效/重复筛选词不消费日志。输入采用 150 ms 初始延迟合并编辑，正常更新及追赶周期保持原逻辑。新增旧半帧含新帧头/新筛选值、状态复位和规则键测试，原最大帧/行数限制不变。

影响限数据分析实时模式和该模块提示文本，不发送串口命令，不改变日志记录、波形数据或插件判定。最后一帧仍等待下一个帧头完成，这是有意保留的流式语义。

### 2. 报告切换后旧图片继续排队（P2，已修）

旧实现仅阻止卸载组件更新，却继续提交旧报告尚未开始的图片请求，挤占新报告读取队列。现将队列按报告所有者取消，保持跨报告最多三个并发、去重和原缓存预算；更换/关闭报告时删除尚未运行的任务。处理同步异常、读取失败和无效图片返回，避免队列卡死/持续加载。代际设计支持 React StrictMode 清理后再次运行。

新增并发/去重、切换取消、新报告继续、StrictMode 重放、异常释放槽位回归。已进入原生调用的任务仍可能完成，但旧组件不会使用结果；没有声称实现底层 I/O 强制取消。Markdown 正文、图片内嵌与证据路径边界保持原逻辑。

### 3. 保存依赖硬链接的兼容性（P1，已修）

波形导出、数据 CSV、截图保存、无线日志导入使用“临时文件硬链接到目标”实现不覆盖发布。这要求目标文件系统支持硬链接，对非 NTFS 介质等不合适。

四个 Windows 入口改用同卷移动发布，保持写入完成/同步/关闭后再发布，且不替换已存在目标、不允许跨卷复制删除回退。采用规范化 UTF-16 长路径；保留各入口临时文件所有权及失败清理。成功/既存目标保护、中文名、长路径、两个并发写入只有一个成功均有原生测试。非 Windows 仍走原逻辑，本轮不扩大平台范围。

依据 [Microsoft MoveFileExW 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)，零标志不启用替换/跨卷复制。本机测试介质不是 FAT/exFAT/SMB，不能把 API 兼容性调整写成这些介质实测通过；不保证断电后的持久性或所有网络文件系统原子语义。

### 4. 损坏 WFM 帧头可能过量分配和错误回退（P1，已修）

标准结构读取曾在验证附加帧头是否存在前，用文件声明的 FastFrame 数量预分配数组。极小损坏文件可声明巨大数量。标准冒号版本标签读取失败后，又可能落入不兼容的历史固定布局，掩盖错误。

现先以溢出检查计算所需帧头边界，验证文件长度和曲线偏移，再分配；标准标签只用标准读取器，历史非冒号导出仍保留旧布局兼容。新增极端计数、缺失帧头/曲线偏移，以及“固定布局看似能读的标准损坏文件不得回退”回归；重跑共享核心、旧 GUI、新壳及正确 SCP 样本。

不改变正常 WFM/ISF/CSV 原始采样、量化、协议或导出格式。这是可证明的输入健壮性问题，不能据此断言先前缺少符号的 Windows `0xc0000409` 就由它造成。
