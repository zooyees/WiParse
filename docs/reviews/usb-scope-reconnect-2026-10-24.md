# 示波器 USB 拔插后无法重连：分析与修正

日期：2026-10-24。基于当前 1.2.2 工作区，保留工作区其他未提交修改。

## 现象与结论边界

用户报告：示波器连接后拔掉 USB，再插入，示波器报错；查找能够发现资源，但不能连接。

代码审查确认了下面的生命周期缺陷，足以造成类似现象。尚无该次仪器报错码、VISA 日志或现场设备拔插复现，不能据此断言仪器屏幕报错的唯一原因。

1. 工作线程在命令、测量、截图、波形读取报错后仍保留旧会话及 VISA 句柄；界面也仍保留已连接记录。同一地址再次连接会被界面拒绝。
2. 发现资源时，对包括已连接设备在内的资源另外打开会话发送 `*IDN?`。这使同一 USBTMC 设备承受重复打开和探测，并不能检查原会话是否仍有效。
3. 底层 `read_bytes` 对大多数负状态，只要有部分字节就返回成功，包括连接丢失等错误。大块读取遇到这类故障也可能继续重试，掩盖失效会话。
4. 空白 `*IDN?` 回应也被视为有效身份，可能把未正常响应的设备标为连接成功。

VISA 对“资源可枚举”和“已打开会话可通信”有不同语义。NI 文档将 `VI_ERROR_INV_OBJECT` 定义为会话引用无效，将 `VI_ERROR_CONN_LOST` 定义为会话 I/O 连接丢失：[NI viRead 文档](https://www.ni.com/docs/en-US/bundle/ni-visa-api-ref/page/ni-visa-api-ref/viread.html)。因此，查找到地址不代表旧句柄能够恢复。

## 已落实修改

- VISA I/O 记录连接丢失、无效句柄、资源消失及通用 I/O 故障；即使上层可选查询吞掉错误，失效标记仍保留。
- 失效后的读、写和设备清理不再向该旧句柄发送后续 I/O；二进制读取立即失败，不将部分波形作为成功数据返回。
- 兼容有部分字节的正常超时回应；普通超时、可选属性不支持不直接标记连接丢失。
- 工作线程在任务边界关闭失效会话，先释放设备和其资源管理器，再通知界面移除连接。其他仪表会话保留。旧设备 ID 的排队命令不能作用于新设备 ID。
- 手动查找时，使用已有 USB 会话做只读身份检查；失败则先关闭旧会话再枚举、探测新资源。请求 1 秒探测超时后恢复原配置；不支持该属性的 VISA 实现仍允许查询，因此不能承诺所有驱动都遵守 1 秒上限。
- 扫描复用有效会话的身份，避免重复打开正在使用的设备。API/快速重复连接也不能再为同一 SCPI 地址创建重叠会话。
- 界面对已有错误记录的设备允许显式重连，按 FIFO 顺序先断开再连接；断开时清理关联的当前测量缓存。
- 空身份回应报告为连接错误。

未新增后台高频轮询；空闲时的拔线在下一次通信或手动查找时识别。不会自动重发采集、配置、电源输出、复位命令，也不改变仪表输出状态。

## 验证与现场复测

验证结果：

- 核心全量测试：260 项通过，1 项跳过。最初沙箱运行的两项 Windows DPAPI 凭据测试失败，沙箱外复核全量通过；与 USB 修改无关。
- 仪表界面回归：4 项通过，包括健康 USB 会话扫描保留、故障会话关闭、其他仪表保留，以及既有设备页面和输出安全测试。
- 底层 VISA 故障注入：部分超时数据仍兼容；4 种致命状态不能作为部分成功；断线中止块传输；可选属性或普通超时不误标失效。
- 具体测试日志：`tmp/usb-hotplug-gui-tests-final.log`，核心最终结果对应 `cargo test --offline -p wiparse-core --lib -- --test-threads=2` 的沙箱外输出。
- 最终发布版 EXE 模拟运行：10 轮断开/重连通过，同地址重复连接被工作线程拦截，另一台模拟直流电源的会话始终保留。记录：`tmp/usb-reconnect-runtime-682a391dff7740819669922e859dac15/result.json`。模拟脚本使用驱动的标准 `DEMO::Oscilloscope` 地址；早期自定义模拟地址会被驱动归一为该地址，已修正脚本后重新验证。

故障注入测试使用替代 VISA 函数或替代 Transport，不宣称硬件实测通过。

现场应分别验证：

1. 连接后空闲拔线、插回、查找、连接，再执行测量、截图及波形读取。
2. 波形传输中拔线，确认任务失败、旧会话退出；插回后可重新查找和连接。
3. 同时连接示波器与另一台仪表，只拔示波器，另一台应持续可用。
4. 连续完成至少 10 轮拔插，检查无“已连接”残留、重复会话或重复命令。

若新会话仍无法打开，需根据界面日志中的 `viOpen` / `*IDN?` 原始错误区分设备未完成枚举、驱动未恢复、其他软件占用和仪器自身通信错误。不要以发现资源成功替代通信验收。
