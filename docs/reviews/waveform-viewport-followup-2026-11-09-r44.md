# 波形视口调度与多通道一致性 R44

## 问题与本轮实现

此前每次范围变化都取消并重设 40 ms 等待，持续滚轮/拖动可能推迟到停手才发起读取；即使请求已发出，后续输入也会丢弃它的成功结果。叠加读取则在主通道更新后清空曲线并单独发起，主/辅通道容易短暂不在同一视口，来源较多时还会同时启动所有读取。

R44 新增单个运行任务加一个可替换待办任务的队列。新输入不重置固定节流时点，同来源已完成的成功视口可以推进画面，最后目标随后补齐。慢请求期间中间待办合并，不累积队列。切换来源、主通道、显示通道或离开页面立即使旧任务失效；已开始的原生调用不能强制中断，但其结果不会提交，也不再启动该批次剩余通道。

每个视口作为一个完整批次读取，最多 3 个原生调用并行。主通道和成功的叠加通道用同一个状态提交，全部使用相同 X 范围。主通道失败也会等本批已启动的工作结束后再交出队列；部分叠加失败则保留其它曲线，并列出失败通道及原因。视口错误独立于用户操作错误，成功刷新不会清掉其它操作的错误提示。

空文档和文件操作期间，添加协议通道、批量解析等入口正确禁用；处理函数也有空来源/忙碌状态保护，移除最后一路的操作同样有边界保护。

## 影响范围

改动仅涉及 React 波形工作区、两个前端辅助模块、相应测试与一个翻译条目。Rust 原生读取、极值索引、测量、解码、报告、仪器控制、CLI、Service、MCP 和插件没有源码变动。原始采样与采样上限不变，每通道桶数仍按已有规则限制在 32–2048；主通道仍为 1500。波形增删、测量光标、解码门控及报告语义不变。

同一来源正在交互时，允许先显示一个已完成的中间视口，这是避免持续输入时完全停止更新的必要变化；画面坐标和所有曲线都属于该已完成批次。不能把它冒称为最新目标已经完成。来源变化则严格拒绝旧结果。

## 验证

最终前端 107 项通过，TypeScript/Vite 与 Tauri 发布构建通过，779 份源码冻结。新增 8 项测试覆盖连续输入不重置节流、1000 次待办合并、慢任务串行及来源失效、过期错误抑制、失败恢复/清理、三路读取并发上限/一致提交、主通道失败等待其它工作完成、部分叠加失败及来源失效后停止启动剩余读取。

实际桌面使用最终 R44 二进制：空文档选择 DDSSS 后批量解析/添加/报告/解码正确禁用；打开 UART 双通道样本后 CH1/CH2 同时显示；横向缩放、滚轮平移及二维拖动后两条曲线保留。切换 CH2 为主通道仍保留 CH1 叠加，CH2 原始极值为 1.2–1.7 V；进入计算器并返回后主/辅通道状态保持。实际读数和截图见 next-candidate-20261109-r44/desktop.json。

原生 64 项和 SCP 实测按 R38/R43 依赖链及确切原生源码身份继承，其它未变化组件同样按身份继承，不宣称全部重新执行。没有真实仪器/AI请求，也没有操作系统 CPU/内存或帧率基准，不报告未经实测的占用降幅；本轮证明的是队列和并发上限、连续输入进展及界面状态正确性。

## R45 最终收敛

最终复查补充：主通道读取一旦失败，不再启动该批尚未开始的叠加通道；已开始的最多三路仍等待完成，避免无效读取拖延下一目标，也避免遗留并行任务。加强已有失败测试，验证七通道请求主通道失败时只启动前三路，其余四路不启动。

R45 前端 107 项、TypeScript/Vite、Tauri 发布构建重新通过，779 份源码冻结；相对 R44 仅视口读取模块及对应测试变化。成功读取路径不变，桌面检查明确继承 R44，并非声称重跑整套 R45 桌面验收。原生 64 项/SCP 及其它组件按源码和二进制身份继承。交付和身份记录见 docs/verification/next-candidate-20261109-r45。
