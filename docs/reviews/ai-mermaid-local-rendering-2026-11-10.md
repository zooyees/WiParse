# 串口 AI Mermaid 与流式显示实施记录

日期：2026-11-10。基于当前 egui 分支，不涉及 Tauri 迁移。

## 原因

聊天 Markdown 原先把 `mermaid` 围栏当作普通代码。AI 的 stream 选项也只是在 HTTP 响应全部读完后解析 SSE，原生工具调用还会强制禁用 stream。因此仅增加图表绘制，无法实现真正的增量显示。

## 实施

- `test_report/mermaid.rs`：本机 Rust 解析、布局、SVG 生成，再由 resvg 栅格化进入 egui。不开浏览器，不执行 JavaScript，不请求远程字体、图片或渲染服务。
- 聊天 Markdown 自动识别 mermaid 围栏；250 ms 防抖，最多两个后台渲染任务。源码继续变化时丢弃过期结果；解析失败保留同一增量图表的上一有效图，并标记当前源码失败。
- 支持适应宽度、缩放、滚动、复制源码、展开源码、用户选择路径后导出 SVG/PNG。当前源码未成功渲染时禁用导出，防止导出旧图而未察觉。
- 使用明暗主题和本机中文字体。导出的图像采用导出时的主题。
- 输入最多 32 KiB、512 行；图结构最多 128 节点、256 边；SVG 最多 2 MiB；栅格最长边约 1024 像素。保留八个最近图表状态，CPU 中不重复保留已上传纹理的像素数组。
- 禁止 HTML、外部链接、click 指令、初始化指令和外部资源；SVG 图像加载回调也禁用。图表是说明材料，不改变硬件状态或测试判定。
- `ai/streaming.rs`：逐行读取 Chat Completions SSE，每约 100 ms 发布最新正文快照；保留响应总量、超时、取消限制。不向界面发布 reasoning、JSON 兼容协议原始正文或未校验的工具参数。临时正文预览最多 256 KiB，达到上限后明确提示等待完整响应，避免持续重复排版大文本；完整响应仍按原有总量限制接收。
- 原生工具调用保留流式模式；按调用 index 拼接 name/arguments/id，完成后才解析和验证工具。截断工具调用不执行；正文达到输出上限时沿用原有不执行动作的处理。
- 串口聊天显示“正在生成（尚未完成）”的临时 Markdown；正式结果继续走现有权限、证据与工具闭环。

## 使用与兼容边界

在 AI 设置中启用“流式显示回复”，使用支持 Chat Completions SSE 的服务。原有配置中的 `stream:false` 不会被强制改写；非流式仍能在收到回复后渲染图表。Responses 协议维持现有非流式限制。

原生工具参数内的最终答案不会逐字预览，只有普通正文提供实时预览。这样避免把不完整工具参数误作最终分析。图表源被分成很小的碎片时，要等待约 250 ms 的短暂停顿后重绘。

渲染器采用 `mermaid-rs-renderer 0.3.1`，不是官方 Mermaid.js。优先使用简单流程图、时序图、状态图；不承诺所有 Mermaid.js 扩展语法、HTML 标签、布局指令与交互行为完全兼容。无法解析时显示错误与源码，不静默显示成成功。图表像素上限用于聊天预览，SVG 导出保持矢量。

本次不改变串口采集、设备控制或日志存储线程。没有调用真实付费 AI 或操作实际仪器；自动测试与本地渲染证明不能替代用户配置服务的端到端验收。
