## 1. 当前架构与职责

新入口是 Tauri 2 / React / TypeScript；本地波形、数据和报告由 Rust 原生适配层处理。协议解码、仪器驱动、串口引擎、插件运行器继续复用既有实现。兼容宿主 `WiParse-Host.exe` 仍负责设备会话和测试执行，保留 egui 恢复界面。因此这是新 GUI 加兼容设备宿主的迁移架构，并非已经移除 egui 的纯 Tauri 后端。

本地桥验证产品、协议、实例身份、所需能力与凭据；只允许类型化的写操作。MCP/CLI/插件使用匹配身份；未知超时和 5xx 不经另一通道重放。Next 退出时不强杀宿主，有采集、测试或未保存内容时保留宿主恢复。

### 隐藏宿主事件循环阻断（r6）

桌面冷启动修复通过后发现宿主隐藏时后续 GUI API 超时。原 Windows winit request_redraw 依赖隐藏窗口未持续接收的内部重绘消息，业务队列与退出检查也因此停止调度。修正 vendored winit：仅隐藏窗口以注册的专用应用消息排队 RedrawRequested，仍在原窗口线程执行；可见窗口原路径保持不变，不直接发送系统 WM_PAINT。[Microsoft WM_PAINT 文档](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-paint) 明确系统消息边界。

诊断版真实窗口下插件激活完成；5 次配套 CLI 只读状态请求均成功，耗时 1385/59/63/49/57 ms（含进程和凭据开销，不作为正式性能基准），无采集、无运行。证据见 r6/hidden-wakeup-runtime.json。首屏插件改为读取宿主实际 selected；未激活时明确提示选择，避免显示 FPGA 已选而全部编辑却禁用。源集合补入 vendored 依赖和嵌入图标。

r6 故障预览仅提交过插件选择，未启动测试、串口或仪器；其空闲宿主无法正常随父进程关闭，核对 PID/路径、monitoring=false、instrument_devices=0 后仅清理该测试进程。后续诊断版退出按实际结果单独记录。r6 不作为可用交付。
