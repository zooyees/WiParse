# 无线 live 执行层门禁：待实现对接契约

状态：设计草案，尚未接入或通过台架验证。本文不授予硬件操作权限，也不表示现有 `wiparse.fenced-wireless/1` 已支持这些字段。当前无线插件的 live 入口仍拒绝执行；replay、recorded、dry-run 和通用仪表路径维持各自行为。

## 职责和边界

WiParse 插件负责发起有明确目标的任务、检查用户授权与配置、展示受阻原因和保存不含密钥的结果。无线台站服务负责本轮 TX 日志采集、就绪判定以及所有受约束的 FT4222 访问。门禁必须位于台站服务的实际 I²C 执行路径，不能仅由插件检查响应、模型输出或前端配置替代。

对 MT5820/MT5788，服务在本轮 RX 工作状态经 TX 日志确认之前不得执行相关 FT4222 I²C 操作。若服务不能确定型号或不能保证所有内部调用均经过门禁，则按需要门禁处理。型号、就绪规则、超时和物理连接来自用户批准的台站配置，不由 AI 猜测。

## 执行身份

每次执行应以服务端校验的 `station_id`、`case_id`、`run_id`、`attempt_id`、`capture_id`、设备身份、配置摘要和租约会话绑定。设备重连、租约变化、采集重启、配置变化或重试必须生成新的会话或尝试标识，使旧就绪状态失效。客户端提供的标识只用于关联，不能代替台站服务对连接与配置的核验。

可见的就绪证明至少包含本轮采集身份、来源标识、连续性与丢失状态、识别规则版本、匹配位置和时间、判定有效期及台站服务产生的不可由客户端任意伪造的引用。日志时间与主机或其他仪表时间没有同步证明时，不推定跨设备先后或因果关系。日志含敏感信息时，默认只回传必要位置及脱敏摘要，原文读取遵循现有授权。

## 执行状态

1. 获取有效租约并校验台站、设备、配置及保护状态；启动与当前 attempt 绑定的采集。
2. 实时读取本轮 TX 日志；来源不明、丢行、截断、不完整、规则不匹配、超时或取消时，不产生可用就绪状态。
3. 台站执行器在每次受约束 I²C 操作前原子地检查同一租约与采集会话的就绪状态、有效期和取消状态。状态过期、连接变化或保护失效时拒绝调用；不允许客户端将旧证明换成新会话的许可。
4. 返回与操作身份绑定的执行结果。超时或断线使执行结果未知时，不自动重发；由设备状态读取和明确的后续操作决定处理方式。取消、失败和结束均执行台站安全退出，安全退出结果无法确认时如实报告。

原子性和不可伪造引用的具体实现由台站服务确定；单纯在请求中传入布尔值、时间戳、日志文本或客户端计算的哈希不能满足要求。服务升级后还必须声明明确的协议版本、执行器能力和不满足条件时的拒绝语义；调用方只能在经审查的契约与实现均可用时接入，不能凭配置开关解除现有阻断。

## 对接和验收

### 会话崩溃围栏与恢复边界

服务内部原型在打开台站硬件前，以 SQLite 事务写入设备及本轮身份对应的 `active` 会话；重启或收尾后遗留的 `active`／`unknown` 记录会阻止该设备的新会话。安全动作先于事后记录的场景依靠此事前围栏保持阻断；围栏写入失败时不得打开硬件。该机制只在所有执行器使用同一可信账本、同一规范化物理设备身份且账本不被替换或回滚时成立，这些部署和身份条件仍需实现并验证。

`unresolved_sessions` 为内部只读清单，不是公开恢复接口。未来恢复必须明确区分：有权限的现场人员完成检查与操作、可信独立设备反馈证明安全、记录反馈来源和时间，并以事务关联操作人、设备身份及待恢复记录；不得由 AI、客户端布尔值、普通命令成功或关闭句柄自动解除围栏。当前尚无可用的可信反馈、现场授权和恢复实现，因此所有遗留会话仍保持阻断，也可能因硬件打开失败产生需人工处理的保守阻断。不得通过更换账本或删除记录绕过。

内部 `recovery_inventory` 在一个只读事务内返回未决会话、命令和安全动作的准确总数及每类最多 100 项摘要，并明确标记截断；可信账本、可信反馈与恢复能力始终报告不可用。它不提供清除或 live 接口。后续接口必须满足以下条件后才允许实现恢复事务：

- **身份**：由台站受信设备适配器取得并绑定规范物理设备标识、连接代次及台站身份；用户输入的地址或模型输出不能充当证明。
- **账本**：固定受保护的台站账本位置和权限，并以外部受信锚点校验单调代次及完整性；发现丢失、替换、回滚或无法校验时默认拒绝。仅 SQLite 事务或摘要本身不足以证明未回滚。
- **反馈与授权**：独立安全路径采集经批准的物理状态读回，绑定当前设备、连接代次、时间与有效期；现场操作人身份及权限由独立授权机制验证。不可用、过期或不一致均拒绝。
- **恢复原子性**：在唯一设备所有权下重新核验以上条件，以事务记录操作人、反馈引用、受影响记录及结果，处理并发和重启；不能重放结果未知的命令。硬件读回到提交之间发生状态变化时必须拒绝或失效。

这些条件是尚待实现的接口契约，不代表已存在可信适配器、人工恢复 UI 或防回滚能力。恢复前还需按不同台站拓扑确定可验证的安全状态与紧急停机行为。

实现前需确定台站服务代码归属、设备型号识别来源、TX 日志与 FT4222 的绑定方式、受约束操作集合、已批准的 RX 工作识别规则、证明的服务端生命周期，以及取消和安全退出的具体动作。服务端需提供可审计的接口说明和测试替身，插件端再按能力协商和版本校验接入。

最低验证应覆盖：本轮就绪后允许预期操作；旧日志、跨设备或跨尝试证明、丢行、截断、超时、取消、租约或设备会话变化均不触发 I²C；并发任务不能互借就绪；失联或超时造成未知结果时不重发；安全退出失败可见。模拟与真实设备记录分开，记录实际型号、配置、日志来源和操作结果。缺少外部服务或台架时标记未执行，不将本草案视为功能完成。
