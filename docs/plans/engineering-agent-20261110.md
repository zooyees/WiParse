# WiParse 工程 AI 能力评估与落地方案

日期：2026-11-10。基线：cursor/four-job-shell-and-marketplace / fa62efe，egui 1.2.2。

## 1. 现状与主要问题

平台已有统一的 AI 服务配置、DeepSeek/千问等兼容接口、可读 Markdown 和串口专用助手。串口侧已有本地全范围日志检索、监控任务、规则告警及部分平台工具调用。其余页面以一次性摘要问答为主，无法自主追问数据、分步计算或核对动作结果。结果是模型可能声称无法访问工具，或者依据有限摘要给出过度结论。

需要解决的核心问题是“模型提出下一步，主机执行真实工具并提供证据”的闭环，而不是进一步扩大原始数据上传。文件总量、当前显示行数和发送给模型的证据量必须独立管理。测试配置数量按实际项目显示，500 是容量上限。

## 2. 借鉴与取舍

- [OpenHands agent 架构](https://github.com/OpenHands/docs/blob/main/sdk/arch/agent.mdx)：借鉴动作与观察分离，执行结果回送模型的循环。
- [LangGraph 人工介入](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/human-in-the-loop.mdx)：借鉴在具体工具调用前审阅参数、暂停和拒绝。当前版本保留内存任务及显式导出记录，不宣称已实现持久化自动恢复。
- [smolagents](https://github.com/huggingface/smolagents)：借鉴小型工具集合与受限运行环境。WiParse 使用原生 Rust 状态机，不引入 Python agent 运行时，不允许模型生成任意代码执行。

本次复用现有 AiService、设备工作线程、测试插件生命周期和本地数据算法，保持 GUI/CLI/MCP/插件接口兼容。

## 3. 总体结构与职责

```text
用户目标 / 当前页与工程 / 明确数据权限
                ↓
统一工程任务 Session：计划、轮数、期限、确认、取消、证据
                ↓ 严格 JSON：reply + plan + 单个 call
Core 契约：工具白名单、参数类型、单位、范围、未知字段拒绝
                ↓
GUI Host：再次核对来源、工程、测试锁与操作确认
                ↓
现有页面模型 / 本地处理器 / 仪表线程 / 测试插件进程
                ↓ 实际结果，非队列受理
E1…证据、覆盖率、单位、质量、错误 → 下一轮分析 → 可读答复
```

模型不能修改产品合格判定、校准要求、硬件保护或物理联锁。遵循 00-system-contract.md：先配置与预检，现有设备占用流程执行刺激和采集，安全停止后分析证据。AI 输出是工程建议，不替代正式报告与验收。

## 4. 本次能力矩阵

| 工具 | 已实现的数据与分析能力 | 已实现的可执行操作 |
|---|---|---|
| 串口 | 当前来源与接收状态；当前文件全范围检索；实时保留快照统计；字面量/正则/排除、上下文、分组、数值提取及阈值统计；有游标的分块续查 | 当前已选实时来源启动/停止，逐次确认；启动等待实际连接 |
| 波形 | 已加载通道摘要；原始采样区间测量与单位；分页、错误过滤、关键词检索协议帧；SCP PING 不计数据帧 | 明确协议/通道后调用已有解码器并等待结果；调整视图和光标 |
| 数据分析 | 已有曲线来源与配置；分帧遍历当前全部点；数量、无效值、最小/最大、均值、RMS、已配置上限超限次数 | 不修改数据或正式结论；统计期间来源变化立即报错 |
| 测试报告 | 当前工程测试索引分页；当前已打开报告的文本、段落、代码行及表格行检索 | 不改写报告；不允许模型指定磁盘路径 |
| 集成测试 | 当前项目、已配置项目分页、选中数量、脏配置、运行日志与状态 | 当前配置预检/运行，复用已有流程；只能停止本助手发起并匹配运行身份的任务 |
| 计算器 | 读取当前输入与结果；LC、带通、Q、RC、CRC、进制/字符/科学计算 | 无副作用本地计算；获准后应用到当前计算器 |
| 仪表控制 | 发现已有会话 ID、状态与缓存测量；已有类型化命令 | 示波器运行/停止/单次、通道/时基/触发/测量，电源与负载受限控制、截图；逐次确认并等待作业完成 |

仪表截图可显示在原有仪表页面；本版本文本模型不能识别图片像素，不声称已支持视觉判读。全源文件采集继续使用现有人工/串口助手流程，本次统一助手没有新增任意文件打开、传输、SCPI、烧录或擦除工具。

## 5. 数据与证据设计

1. 默认仅使用本页数据。跨工具权限需在发起任务前明确开启；本地纯计算可以在任何页面使用，不需上传私有数据。
2. 日志扫描在本地执行：原始文件不整体上传；发送匹配计数、分组、数值统计与有限上下文。实时缓存被淘汰的行不能被重新构造，明确报告保留范围；需要历史全部数据时打开已保存日志或使用串口本地日志库。
3. 单块日志扫描最多 1 GiB / 15 秒，可通过宿主游标续查；这不是全文件总量限制。全范围扫描与模型 token 预算分开。
4. 波形通过 Arc 共享原始采样，后台测量不复制完整数组；频率是交点估计，需要结合信号质量。没有有效采样时返回缺失，不返回虚假的零测量。
5. 数据统计每帧最多 20,000 个点且限制约 4 ms；来源变化时拒绝全量结论，建议先保存快照。数据曲线横轴是帧号，不能当成已同步时间。
6. 报告检索受当前预览 400,000 字节读取上限约束，返回 entire_file_covered 与块定位；块号不是原始文件行号。超限报告不能据此宣布全文件无问题。
7. 每个工具最终结果生成 E 编号、来源范围、算法版本、耗时和成功/未确认状态。大结果显式截断并要求缩小查询，不静默充当全量证据。

## 6. 权限、稳定性与运行约束

- 工具参数严格白名单，拒绝未知字段、任意路径、非有限数值、缺失 SI 输入、无效通道映射；计算器不得用 GUI 默认参数填补用户遗漏。
- 界面调整权限只覆盖解码配置、光标、计算器输入。设备和测试动作必须展示具体参数并逐次确认；模型文本和日志内容不能授予权限。
- 派发前再次检查页面、工程、来源绑定和测试锁。来源变化取消旧任务；已确认动作造成的自身来源转换由主机更新绑定。
- 串口接收、仪表作业、协议解析、数据统计和测试进程各有等待状态。受理、完成、正式合格三个概念分别报告。
- 不自动重试结果未知的设备动作；取消只是停止任务等待，不承诺撤回设备已执行命令。外部启动的测试不允许助手停止。
- 默认 8 轮，可选 4/8/12；4 分钟工作期限，单工具 90 秒；本地分析工作线程最多两个；重复相同调用终止；对话与证据有独立内存上限。
- 沿用现有共享服务并发及凭据保护；不将 API key 写入提示或交付包。关闭/重启不自动重放硬件动作。

## 7. 交互与界面

AI 窗口增加“智能任务”，保留“摘要对话”和连接设置。界面包含数据范围权限、轮数预算、可折叠计划、Markdown 对话、具体操作确认卡、执行证据、取消与导出。支持问题示例、复制答复、Ctrl+Enter 发送。参数与原始 JSON 收入折叠记录，日常阅读以结论和证据为主。

同步统一基础字体（正文/按钮13、辅助12、标题16、等宽13），修正插件标题左对齐、数据筛选标签与输入框分行，并为计算器内部长内容显示滚动条。沿用此前紧凑间距及设备平铺布局。

## 8. 影响范围与兼容性

新增 Core 契约、GUI Session 与主机适配层；页面增加面向助手的受限适配函数。复用算法和设备作业，不更换 GUI 框架、通信驱动或插件协议；不改变串口最大行数、不填充虚构测试项。现有串口专用实时监控与规则告警仍负责及时本地预警，云端模型延迟不能承担硬实时保护。

## 9. 验证与交付原则

契约拒绝测试、来源/权限与取消测试、异步受理不当作完成测试、运行身份测试、证据预算测试、模拟 HTTP 两轮工具闭环、数值基准、页面矩阵与助手窄宽度渲染。真实模型质量和真实硬件动作不由本地模拟测试代替。最终记录实际通过项、限制与发布校验，生成独立 EXE 预览目录，包含 CLI/Service/MCP/插件和相邻资源，不复制本机密钥、不覆盖旧版本、不自动创建 ZIP。

## 10. 后续增强优先级

P1：报告超大文件流式索引与跨报告对比；仪表源文件到波形的统一证据流水线；串口日志库工具与统一助手共享游标契约；增加固定工程分析模板和离线任务回放验证。

P2：有能力声明的视觉模型接口、截图坐标证据；设备能力自动生成工具目录；在明确人工恢复确认后持久化长任务。

P3：多来源时钟校准与事件关联、受控测试方案生成及人工批准后执行。以上均需先明确插件/Dongle契约和验收数据，当前版本不宣称已完成。
