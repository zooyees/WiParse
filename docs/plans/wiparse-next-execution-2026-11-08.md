## 执行方式更新：集中开发后统一验证

用户于本轮明确要求调整步骤。即日起采用：

1. 先集中完成剩余功能、界面、接口、配置和文档，不再为每一个控件或接口重复运行测试、构建或预览。
2. 开发完成后冻结候选版本：记录源码清单和哈希、依赖锁文件、构建环境及明确未覆盖项。不能把开发中旧预览当作候选版本。
3. 对同一候选版本统一执行构建检查、自动化回归、模拟闭环、真实窗口检查、性能与必要实机检查。按照模块逐项记录结果。
4. 将发现的问题汇总成一批，按影响范围集中修复；修复后对受影响项和关联回归统一复验，不再按每次编辑反复打包。
5. 验证通过后提供 EXE 预览；用户确认后再制作完整 ZIP。

只允许在编译问题确实阻塞后续开发时做必要的开发检查。桌面授权和实物缺失留待统一验收处理，不以模拟成功替代。正式五轮检查的标准不降低。
