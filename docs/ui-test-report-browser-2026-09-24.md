# 测试报告页左侧目录方案

日期：2026-09-24

读者：软件工程

对象：测试报告页左侧目录（`crates/wiparse-gui/src/test_report.rs` 的 `browser_panel`、`paint_output_groups`、`format_result_stamp`、`short_artifact_label`、`tree_branch_row`、`tree_leaf_row`）

这是显示方案，也是实施边界。索引结构、文件路径、右侧预览不在本次范围内。

实施时先守第 2 节。第 3 节是可以做的改动。做不到第 2 节的，不要为了目录更短去改。

---

## 1. 目标

左侧目录只回答两件事：有哪些用例，每次跑得怎么样。

扫一眼看到的是用例名，和它下面的时间行。时间行带一盏灯：通过、失败、进行中。报告就是这一次运行，不再另占一层叫 `summary_{stamp}.md` 的文件。日志、捕获、波形是这次运行的附件，需要时才出现。

---

## 2. 不要改坏的日常操作

下面这些是现在每天在用的路径。目录变短之后，这些动作的步数不能增加。

**项目切换保持现在的下拉。** 选中另一项后仍然持久化、重建索引，并给出 `ProjectChanged`。项目名为空或与 id 相同时，下拉里仍显示现在的名称。

**刷新仍然重建索引。** 可以改成图标，点击后的效果与现在的「刷新」相同。

**添加测试仍然是一份未加入的插件列表。** 点「添加测试」展开列表，点某一项写入项目并重建索引。插件都已加入时，仍显示现在的空提示。不要改成必须先去测试工具页才能添加。

**新建项目仍然先填 id 再确认。** 非法 id 仍走 `report.project_id_invalid`。入口可以收进项目下拉的一项，确认框和校验留下。

**打开报告的原有手势留下。**

- 双击用例行：打开该用例最新一份报告；没有报告时打开最新任意产物。逻辑保持 `latest_report().or_else(latest_any())`。
- 双击某一次运行：打开这一次的报告，同样先报告、再任意产物。
- 单击某个附件：打开该文件。Ctrl / Cmd 单击仍是叠加预览。
- 附件行悬停仍显示完整路径、大小、修改时间。
- 附件行右键仍有「外部打开」和「在文件夹中显示」。

报告不再单独占一行之后，上面针对报告文件的能力改挂在这一次运行上：双击打开，Ctrl / Cmd 双击叠加预览，右键外部打开和在文件夹中显示。没有报告、只有其他产物时，双击行为与现在的 `latest_any()` 一致。

**移除用例仍在用例行的右键。** 不要改成滑过才出现的图标，也不要放到别的页面。

**失败的运行全部留在列表里。** 可以默认折叠附件，不能按通过与否过滤，也不能只留最近一次。

**进行中、插件缺失、尚无结果的提示留下。** 用例正在跑时，行尾仍是「进行中」。插件未安装时，名称变淡，展开后仍有缺失说明。没有任何结果时，展开后仍有「尚无运行」这类现有提示，并保留空项目时的「前往测试工具」。

**右侧正在打开的文件保持选中。** 若选中的就是这次运行的报告，选中态画在这次运行上。选中附件时，选中态仍在该附件行。

## 3. 目录怎么排

### 顶栏

项目下拉留在第一行，占满剩余宽度。

第二行不再放三颗等宽的「刷新 / 添加测试 / 新建」。

- 刷新：一颗图标按钮，靠右或靠项目行右侧，点击行为不变。
- 添加测试：一颗文字按钮，点击仍展开插件列表。
- 新建项目：作为项目下拉底部的一项。点开后仍是现在的 id 输入和确认，不在顶栏占一颗等宽按钮。

`2 测试用例 · 7 结果` 留一行淡色说明，放在列表上方。树上不再重复个数。

### 两层

**用例行。** 只显示用例名。有结果或正在运行时默认展开，与现在一致。行尾只保留「进行中」或插件缺失，不显示结果个数。用例行不放通过/失败灯：一次用例里既有失败又有通过时，一颗灯会把失败盖住。灯只放在每一次运行上。

**运行行。** 标题用时间。同一用例里，若两条运行的「月-日 时:分」相同，这两条补上秒；秒也相同再补序号。底层 stamp 不变，只改 `format_result_stamp` 的显示。默认只展开最近一次（现在的第一条）的附件，更早的运行收成一行。单击仍是展开或折叠，双击仍是打开报告。

行尾一盏灯：`result.ok == Some(true)` 用成功色，`Some(false)` 用失败色，`None` 不画灯。进行中的那一次若能对应到正在跑的用例，灯用强调色，文案仍可只放在用例行，避免同一状态写两遍。

### 报告不单列

一次运行里，报告分组（id 为 `reports` 或 `report`）不再画成文件夹，也不再把文件名画出来。

现在 `short_artifact_label` 去不掉字面量 `summary_{stamp}.md`，所以叶子行会显示模板名。这次不修这个文件名的缩写规则来「看起来像标题」，而是不把报告文件当作目录叶子。打开动作按第 2 节挂到运行行。

一次运行有多份报告时，仍在该次运行下各占一行，标题用分组的中文标签加序号（「报告」「报告 2」），不用原始文件名，不用 `MD` 徽章。单击打开对应文件。

### 附件

报告以外的分组不再做成可折叠文件夹，不再显示个数。

- 某一角色只有一个文件：一行，标题用该分组的中文标签（如「配置日志」）。原始文件名放在悬停里。
- 同一角色有多个文件：每个文件一行，标题是角色名加能区分的短后缀。现在 `uart_…` 三行都会变成 `uart 23:27:58`，再加 `FILE` / `JSON`。改为：标签相同时才在行尾用扩展名区分（`json`、`log`），不要每行都放 `FILE`、`MD`、`JSON` 徽章。扩展名相同则再加序号。
- 只有一种非报告附件时，直接排在运行下面，不加分组标题。
- 有两种及以上时，每种前面一行不可点的淡色小字作为分隔，不使用折叠三角。

单击、悬停、右键与现在的叶子行相同。

只有一个非空分组且文件不超过 4 个时，现在会跳过分组行直接铺文件。新规则覆盖这条分支：按上面的角色行显示，不再依赖「≤ 4 就摊平」。

### 选中与层级

选中行用左侧 2px 强调色条加很淡的底，不要整行铺满现在的强调色块。悬停仍可用淡底。

用例、运行、附件的字号可以有差别：用例用标题字重，运行用正文字号，附件用说明字号和次要色。三角只出现在还能展开的用例行和运行行上。附件行不再空出一截三角的宽度。

文案走现有 i18n。中文界面不出现 `summary_{stamp}`、`FILE`、`MD`、`JSON` 这类类型徽章。

## 4. 验收

- 切换项目、刷新、从插件添加测试、新建合法与非法 id，结果与改前一致。
- 双击用例打开最新报告。双击某一次运行打开该次报告。没有报告时仍打开该次最新产物。
- 单击「配置日志」或某条捕获打开对应文件；Ctrl / Cmd 仍是叠加预览；右键仍能外部打开和定位到文件夹。
- 报告文件不再出现 `summary_{stamp}.md` 和 `MD`。右键这次运行仍能外部打开和定位该报告。
- 同一分钟的两次运行能看出先后。三份同名捕获不会是三行相同文字加 `FILE`。
- 失败运行都在，默认不展开附件。用例行没有一颗代表「整体成败」的灯。
- 正在运行、插件缺失、无结果、空项目前往测试工具，这些提示都还在。
- 右侧打开某份附件时，左侧对应行有选中态；打开的是报告时，选中态在该次运行上。
