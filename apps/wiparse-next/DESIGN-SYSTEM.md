# WiParse Next 页面布局与视觉规则

## 适用范围与目标

此规范适用于 Tauri 版的串口工具、仪器控制、波形分析、数据分析、集成测试、测试报告、计算器及设置。各页面保留其业务需要，使用同一套尺寸、颜色、文字和交互规则。极简指减少重复说明和无关控件，保留完成任务所需的信息。

新界面已经能读写一部分工程、串口、仪器和测试命令，离线波形、报告和数据分析不经过旧界面。未迁移的操作必须显示做不到的原因。此规范不是功能迁移或硬件验收完成的证明。

## 全局框架

1. 顶部只有一行：产品名、七个工具、连接状态、刷新和设置。当前页用底边标明。连接状态只在这一行出现一次，底栏写当前页能做什么，不重复同一句连接说明。
2. 内容区外边距为 4 px；相邻面板间隔为 4 px；面板内部按内容需要使用 4、8、12 px，不叠加多层容器间距。
3. 工具页左栏默认宽度 200 px，最小宽度 200 px。工具栏、主内容和详情保持对齐；长文本在对应区域省略或换行，禁止挤压相邻控件。
4. 页脚为单行状态栏。窗口主体使用 CSS Grid 管理主分区，面板内部使用 Grid 或 Flexbox 对齐。数据区按可用空间伸缩，列表、日志和详情分别在各自区域滚动。
5. 最小窗口按 1100 × 720 CSS 像素检查；窗口变化时保证导航可访问、主要操作不重叠、内容不被窗口边缘裁切。系统缩放下还需另行验证。

## 组件和视觉

- 标准操作控件高度 30 px；按钮、输入框、下拉框同一行中心对齐，禁用态与焦点态可识别。
- 正文字号通常 13–14 px，辅助信息 12 px；不靠极小字号容纳信息。标题只比正文提升一个层级，字号和字重在全软件一致。
- 使用克制的浅色背景、轻微层次差和细边框。蓝色表示选择或交互，状态使用有文字的颜色标识；不能只靠颜色表达通过、失败或异常。
- 面板圆角、边框、输入框和按钮统一；避免装饰性大卡片、无意义图标和重复分隔线。搜索和筛选在对应数据区上方，汇总数字靠近结果。
- 不在日常界面直接暴露内部字段名、JSON 或技术错误堆栈；配置无效和连接失败须提供能理解的原因，复杂细节可展开。

## 页面结构

| 页面 | 左侧 | 主区域 | 右侧或辅助区 |
| --- | --- | --- | --- |
| 串口工具 | 连接与采集、日志目录 | 日志标签、搜索和日志正文 | 仅在确有任务时显示详情；避免无意义空栏 |
| 仪器控制 | 设备列表与连接入口 | 当前仪器操作和测量，按仪器类型分区 | 可选设备信息、采集或辅助设置 |
| 波形分析 | 数据源和通道 | 波形及时间轴 | 测量、游标或所选通道参数 |
| 数据分析 | 数据集与分析任务 | 表格或图表 | 当前分析参数与结果 |
| 集成测试 | 测试插件或项目 | 搜索、筛选、测试项列表和状态 | 选中项结果、校验问题和证据 |
| 测试报告 | 项目或报告目录 | 报告列表与内容 | 报告筛选或所选报告信息 |
| 计算器 | 功能分类 | 当前计算表单与结果 | 仅在需要时显示说明 |
| 设置 | 设置分类 | 当前分类的设置项 | 不设置无内容的空栏 |

测试矩阵行高为 36 px，并与虚拟列表计算保持一致；500 项时渲染可见行及少量缓冲行。串口日志按页读取，不能把当前页筛选表述成搜索全部历史。具体表格字段根据业务展示，历史结果和模拟结果必须可辨别。

## 验收

1. 以有数据、无数据、连接失败和长文本四种状态检查布局；不得用模拟通过代替真实结果。
2. 至少检查 1440 × 900 和 1100 × 720，并检查滚动到底部、切换项目、搜索筛选及键盘焦点。
3. 检查 20 项配置和 500 项列表的可读性、滚动和选择；验证与运行结果绑定的正确性。
4. 与原版比较启动耗时、内存、日志吞吐、波形刷新和交互延迟。新旧功能、仪器行为和硬件安全未通过回归前不得替换正式版。
