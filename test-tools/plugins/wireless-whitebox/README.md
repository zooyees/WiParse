# 无线充电白盒测试

本插件提供 20 项 TX 研发测试模板，支持 Testing Hub 配置工作区和工程共享信息。本轮实际序列号与固件版本通过运行参数输入；工程信息中的设备标识仅作记录，未完成设备连接与能力核对。模板仅描述目标、刺激和证据要求；具体产品遥测、仪器控制、自动刺激、波形采集与数值限值尚未实现。

默认目录为 `recipes/wireless-whitebox/cases`。如果该目录不在当前数据根的允许范围内，需将模板复制到数据根内并在插件参数中选择该目录，或使用宿主的授权目录设置。不要修改原始模板以替代工程版本管理。

“配置检查”仅展示本轮选择项和检查报告，所有选中项结果为无法判定，不连接设备。“实物测试”在预检和运行时均拒绝，不能用于实际产品验证。使用前需实现统一设备所有权、原始日志、采集武装及时间质量、产品白盒适配和真实判定，并完成工位实机验收。

首次使用请进入工程设置并保存工程信息，之后选择测试项并预检。模板可以在配置工作区编辑；改变工程信息、测试项或运行参数后需要重新预检。

工程中的 `mt5788.mjs` 根据 MaxicCTP 实现了芯片/客户版本识别、RX 原始寄存器读取以及受用户限值约束的 VOUT 写入顺序；HW 和 HH 使用不同寄存器和命令位。读取与 VOUT 设置模式通过 WiParse 的 FT4222 仪器命令与设备租约执行。该链路已完成模拟任务联调，尚未进行实机验收，返回的寄存器原始值不能替代电气测量。默认客户地址为 0x2B，仍需针对实际硬件确认。

在工程设置中从 WiParse 的已连接设备选择 FT4222 和 TX 日志串口，并填写工位编号、串口波特率、I2C 频率、日志标记及超时；运行模式选择“读取 MT5788 状态（只读）”，仅选择“低功率稳态”后预检运行。插件只接受本轮新接收到的日志：依次看到 `Start CHG` 和 `ASK 71`，或者看到运行中的 `ASK 31` 后才访问 MT5788；标记默认值来自当前样例，可按固件日志修改。若没有新的匹配报文，需要重新建立充电；日志丢失、超时或停止不会启动 I2C。

报告保存协议观察、芯片身份和内部原始寄存器值，不设置电源、负载或 RX 输出，也不作产品合格判定。若命令超时且不能确认结束，设备锁保留为人工恢复状态；先检查 FT4222 任务和工位状态，再由维护人员处理锁，不能直接自动重试。

如需控制 RX，先在“低功率稳态”测试项中添加 `RX 输出电压控制`（目标值及允许上下限，单位 mV）和`负载端输出电压限值`（V），并在工程设置中选择连接 RX VOUT 的电子负载，再选择“设置 MT5788 输出电压”。插件在本轮建链日志、芯片 ID、客户版本与 RX 模式确认后执行写入，读取内部寄存器及负载端电压。写入后发生异常或未取得电压读数时保留设备恢复锁，不自动重试。此模式会改变 RX 的输出目标，不改变电源或电子负载状态。

开发中的“RX 恒流负载测试”需要在同一测试项配置负载电流及允许上限、负载端电压范围和等待时间；工程中选择已连接的电子负载。RX 就绪并完成身份确认后，按关闭输入、设置恒流模式和电流、开启输入、等待与测量、关闭输入的顺序执行。停止时仍尝试关闭输入；命令状态不确定或关断失败会保留恢复锁。命令完成不等于物理输入状态已验证；本模式仅经模拟测试，尚未实机验收。

“低功率稳态”配置可添加测量限值，项目填写 `fop`、`iout`、`vout`、`vrect` 或 `temp`，单位填写 `raw`，并输入上下限。报告会给该内部寄存器检查独立的 PASS/FAIL，并展示实际值和限值；产品总结果仍为无法判定，因为该单点内部值不能替代独立电气测量。不同固件的寄存器单位和比例须由产品定义，当前不会自动换算。

工程种子按当前研发工位填写 MT5820、MT5788、MDO3014 和 RIGOL 832；VISA 地址、实际型号识别、I2C 接口及电子负载仍需填写。`mt5820-log.mjs` 是针对已提供的串口终端导出样例的离线观察器，只提取完整接收块中的已见字段，不推断单位、原因码或产品结论，尚未接入实时执行。

## 已有日志定位

将 UTF-8 串口终端导出文件放在 Testing Hub 数据目录下，运行模式选择“分析已有串口日志”，填写该文件路径，并在测试项中选择“历史故障复现”。保存工程配置并预检后运行。报告列出 `FO Alert!` 及前次 `FodCnt`、后续 `EPT_REASON`、后续 `Start CHG` 的候选序列，归档输入日志、SHA-256 和 JSON 观察结果。预检后文件内容变化时运行会拒绝。序列只是日志观察，不证明因果、精确时间或电气保护结果。
